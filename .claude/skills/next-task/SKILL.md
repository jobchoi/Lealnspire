# 다음 작업 수행

인자: `$ARGUMENTS` (비어 있으면 TASKS.md에서 자동 선택, 작업 ID가 있으면 그 작업)

CLAUDE.md의 규칙이 이 문서보다 우선합니다.

## 절차

1. **상태 확인**: `git status`, 현재 브랜치, 최근 커밋을 확인합니다. 커밋되지 않은 변경이 있으면 무엇인지 사용자에게 알리고 진행 여부를 판단합니다.
2. **읽기**: `docs/NEXT_SESSION.md`, `docs/TASKS.md`를 읽고, 고른 작업과 관련된 설계 문서(GAME_DESIGN, CURRICULUM, ARCHITECTURE)의 해당 부분을 읽습니다.
3. **작업 선택**: 인자가 없으면 상태 `대기`, 선행 작업 완료, 걸린 [미결정] 항목 없음 조건을 만족하는 가장 높은 우선순위 작업 하나를 고릅니다. 조건을 만족하는 작업이 없거나 [미결정] 항목이 걸려 있으면 **구현하지 말고** 무엇이 막혀 있는지와 질문을 보고하고 끝냅니다.
4. **시작 표시**: TASKS.md에서 그 작업의 상태를 `진행 중`으로 바꿉니다.
5. **구현**: 완료 조건 범위만 구현합니다. 범위 밖 아이디어는 TASKS.md에 `제안` 상태로만 추가합니다.
6. **검증**: `npm run verify`와 완료 조건에 적힌 검증을 실행합니다. 변경이 크면 `reviewer` 서브에이전트에게 검토를 맡기고 지적 사항을 반영하거나 반영하지 않은 이유를 기록합니다.
7. **문서 갱신**: CLAUDE.md 4절 표에 따라 갱신합니다. 최소한 TASKS.md(상태, 검증 결과), WORK_HISTORY.md(맨 위에 기록 추가), NEXT_SESSION.md(덮어쓰기)는 항상 갱신합니다.
   - 모든 완료 조건을 실제로 확인했을 때만 상태를 `완료`로 바꿉니다. 일부만 확인했으면 `진행 중`으로 두고 남은 항목을 적습니다.
8. **커밋과 push**: 작업 브랜치에 커밋하고 push합니다. 기본 브랜치 병합, pull request 생성, 배포는 하지 않습니다.
9. **보고**: CLAUDE.md 5절 형식으로 사용자에게 보고합니다.
