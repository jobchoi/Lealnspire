# 게임 기획 (GAME_DESIGN)

> 표시: **[확정]** 사용자가 승인한 내용 · **[제안]** 검토 대기 중인 안 · **[미결정]** 결정이 필요한 항목

## 1. 대상 사용자 [확정]

- 프로그래밍 경험이 없는 **청소년과 성인**
- 회원가입 없이 브라우저에서 바로 시작
- [제안] 한 스테이지는 1~3분 안에 끝나는 짧은 퍼즐로 구성합니다.
- [제안, T23] 화면은 저학년도 글 없이 쓸 수 있게 기호 중심(T9 사용자 요청)으로 만들었습니다.
- [미결정, 사용자 2026-11-25] "일단 연령은 구분하지 않았다. 필요하다면 함께 더 생각해 보자." — 연령별 모드·문구는 만들지 않고, 필요성이 생기면 사용자와 함께 논의합니다.

## 2. MVP 목표 [확정]

- 명령의 **순서**와 **반복문**의 기본을 게임으로 이해한다.
- 플레이어가 직접 블록을 조합하고 실행 결과를 확인한다.
- 5~10개의 짧은 스테이지를 완주할 수 있다.
- 회원가입 없이 브라우저에 진행 상황을 저장한다.

## 3. 핵심 게임 루프 [제안]

```
스테이지 선택 → 목표 확인(맵, 블록 제한) → 블록 조합 → 실행
→ 로봇 애니메이션(실행 중인 블록 강조) → 결과
   ├ 성공: 별 평가(블록 수 기준) → 진행 상황 저장 → 다음 스테이지
   └ 실패: 실패 이유 표시(벽 충돌 / 목적지 미도달) → 처음으로 → 수정 → 다시 실행
```

[제안, T15~T22 반영] 현재 구현된 루프:

```
(선택) 예측 도전: 고정 코드의 도착 모습 고르기 → 실행으로 확인
블록 조합(되돌리기 1회) → 실행(반복 회차 표시) → 결과
   ├ 성공: 별 → 저장 → 다음 스테이지 (8개 완주 후 선택 보너스 2개)
   └ 실패: 원인 블록·칸 표시 → 고치기(코드 유지, 원인 블록 선택) 또는 닫고 바로 편집
막히면(요청할 때만) 힌트 1단계: 볼 곳 강조 → 2단계: 질문. 정답은 알려 주지 않음
```

- 실패해도 벌점 없이 바로 다시 시도합니다.
- **잠정 별 평가**: 성공 시 전체 블록 수(반복 몸체 포함)가 `starBlocks` 이하이면 별 3개, `starBlocks + 2` 이하이면 2개, 그 외 1개입니다. 실패는 0개입니다. 반복문을 쓰면 블록 수가 줄어 반복을 쓸 동기가 생깁니다.

## 4. 실행 규칙 [제안]

- 명령 블록: 앞으로, 왼쪽으로 돌기, 오른쪽으로 돌기
- 반복 블록: N번 반복(N은 2~10), 안에 다른 블록(반복 포함)을 넣을 수 있음
- 앞으로: 앞 칸이 벽이거나 맵 밖이면 **부딪힘으로 실패**하고 멈춤
- 돌기: 제자리에서 90도 회전, 한 단계로 셈
- 도착 칸에 들어가면 **즉시 성공**하고 멈춤
- 프로그램이 끝났는데 도착하지 못했으면 실패
- 안전장치: 기본 명령은 최대 1000단계, 반복 몸체 진입은 별도로 최대 1000회까지만 실행. 다음 실행이 상한을 넘으면 단계 초과(`stepLimit`)로 멈춤. 반복 진입은 화면 프레임을 만들지 않으며, 빈 반복만 있어도 진입 상한을 넘으면 단계 초과(상한 이내에서 끝나면 미도달)
- 블록 수: 반복 블록과 몸체 블록을 각각 1개로 세며 전체 최대 10개(`MAX_PROGRAM_BLOCKS`). 편집기 제한은 `min(stage.maxBlocks ?? 10, 10)`. 상한에서는 추가를 비활성화하고 안내하며, 10칸 점 막대로 사용량을 표시합니다.

## 5. MVP 범위

### 포함 [제안]

- 블록 4종(위 실행 규칙)
- 블록 추가, 삭제, 순서 바꾸기, 반복 횟수 바꾸기(1차는 클릭 방식)
- 실행 / 한 단계씩 실행 / 처음으로 / 속도 조절
- 실행 중인 블록 강조, 실패 이유 메시지
- 스테이지 8개(+보너스 1개 선택), 순서대로 잠금 해제, 별 평가, 스테이지별 힌트 1개
- localStorage에 진행 상황과 스테이지별 마지막 코드 저장

### 제외 [제안]

- ~~조건문, 변수, 함수(다음 단원 후보)~~ → **[확정, 사용자 2026-11-25] 2단원부터 포함**: "프로그래밍의 기본 개념은 다 담는다. 글자를 외우는 것이 아니라 개념을 익히는 방향." (1단원 MVP 범위에서는 계속 제외, 2단원 계획은 ROADMAP 라운드 3)
- 아이템 줍기, 적, 움직이는 장애물
- 회원가입, 서버, 순위표, 공유
- 스테이지 편집기, 다국어, 사운드, 캐릭터 꾸미기
- 드래그 앤 드롭(MVP 이후 선택 기능)
- 블로그 자동 발행

## 6. 화면 구성 [제안]

- 구현된 화면 흐름(T6): 첫 화면 → 시작하기(스테이지 1) / 이어하기 / 스테이지 목록 → 게임 화면 → 결과 모달
- 이어하기: 진행 기록이 있으면 완료하지 않은 첫 열린 스테이지로 이동합니다. 기록이 없거나 모두 완료했으면 숨깁니다. 시작하기는 기존 진행을 지우지 않습니다.
- 목록: 스테이지 1~8의 번호·제목·최고 별·잠김 상태를 표시합니다. 첫 스테이지와 직전 스테이지를 완료한 카드만 선택할 수 있습니다. 목록에서 첫 화면으로 돌아갈 수 있습니다.
- 게임에서 목록으로 돌아가거나 힌트를 열고 닫을 수 있습니다. 성공하면 다음 스테이지로 이동하며, 마지막 성공에서는 완주 축하와 목록으로 버튼을 표시합니다.
- 스테이지 진입 시 저장 코드 → 초기 코드 → 빈 코드 순으로 복원하고, 재생·모달·선택·힌트 상태를 초기화합니다. 화면 전환 시 제목에 키보드 포커스를 옮깁니다.
- 게임 화면: 왼쪽 맵(CSS Grid)은 sticky, 맵 바로 아래 실행 컨트롤, 오른쪽 블록 팔레트와 남은 화면 높이를 사용하는 자체 스크롤 작업 공간. 새 블록과 현재 실행 블록은 작업 공간 내부만 스크롤하여 표시합니다.
- 모바일: 화면 높이에 맞춘 배치 안에서 맵을 위쪽 약 22% 이내로 유지하고 편집기를 아래에 쌓습니다. 실행 컨트롤은 하단의 별도 행에 항상 보이며 안전 영역 여백을 둡니다. 작업 공간만 스크롤하므로 하단 컨트롤이 마지막 블록을 가리지 않습니다.
- 로봇의 방향은 큰 화살표로 표시
- 완료 기록이 있는 스테이지는 결과 창을 닫거나 재방문해도 상단에 다음 스테이지 버튼을 표시합니다(마지막 제외).

## 8. 저학년 UX 원칙 (T9)

- 이중 부호화: 큰 기호와 짧은 한국어 보조 글을 함께 표시해 읽기 부담을 줄이고 명령의 뜻을 연결합니다. 앞으로 ⬆, 회전 ↺/↻, 반복 🔁를 팔레트와 작업 공간에서 동일하게 사용합니다. 로봇 방향 화살표는 앞으로가 로봇 기준임을 보여 줍니다.
- 일관된 색과 위치: 이동은 파랑, 회전은 초록, 반복은 주황으로 구분하되 기호도 항상 함께 표시합니다. 본문·보조 글은 밝은 배경 위 어두운 색으로 WCAG AA 4.5:1 이상 대비를 사용합니다.
- 운동 부담 완화: 터치 영역은 최소 48×48px, 명령 기호는 1.85rem, 반복 횟수는 ×N과 큰 −/+ 버튼으로 조절합니다(2~10).
- 주의와 즉각 피드백: 맵을 고정하고 작업 공간만 스크롤하여 명령과 결과를 함께 비교하게 합니다. 현재 실행 블록 강조와 반복 선택 테두리를 유지합니다.
- 부담 없는 재시도: 벌점 없이 다시 하기, 목표 옆 로봇 → 별, 결과의 큰 별·충돌·생각 기호 뒤 작은 설명을 제공합니다. 모든 아이콘 버튼에 한국어 접근성 이름과 툴팁을 유지하고 reduced-motion 환경에서는 효과와 부드러운 스크롤을 억제합니다.

## 9. 테마 월드 (T13, 배치 확정)

- 1~3: 크레용 스케치북. 줄 공책, 스티커 명령, 크레용 괄호와 “N번”, 거친 선 로봇, “해 보기!”.
- 4~6: 기차 마을. 하늘·잔디, SVG 이소메트릭 섬과 역 깃발, 명령 기차 칸, 순환 선로와 “N바퀴”, “출발!”.
- 7~8: 게임기. 베젤·녹색 도트 화면, 방향 명령과 B 반복, 빈 카트리지 칸, 점선 반복 칩과 ×N, A 실행.
- 완료한 스테이지에서 공책·기차·게임기 SVG 버튼으로 다른 월드로 다시 풀 수 있습니다. 이 선택은 해당 화면에서만 유지되며 진행 저장은 바꾸지 않습니다. 실행 의미와 접근성 이름은 모든 월드에서 같습니다.
- 첫 화면은 세 세계를 소개하고 목록은 월드별 이름·그림으로 묶습니다. 작은 화면에서는 스프링·테이프·게임기 장식을 축소해 맵과 실행 버튼 공간을 확보합니다.

## 10. 완주 계약 [제안, T23]

- **1단원 완료** = 정규 스테이지 1~8 성공. 별 개수와 무관합니다.
- 보너스(b1, b2)와 예측 도전은 **선택 활동**입니다. 정규 완주나 다음 단원의 조건이 아닙니다.
- **별의 의미**: 학습 능력 평가가 아니라 "더 짧은 코드로도 풀 수 있다"는 코드 길이 피드백입니다(잠정 기준 3·2·1, 사용자 확정 대기).
- 진행 기록은 이 기기의 브라우저에만 저장되며, 홈의 "내 기록 안내"에서 지울 수 있습니다(T20).
- 공식 지원 언어는 한국어입니다. en.json은 일부 키만 있는 개발 예제입니다.
- [확정 방향, 사용자 2026-11-25] 영어는 기계 번역이 아니라 AI 번역으로 세밀하게 만든다. 또 "너무 한글화하면 오히려 가독성이 떨어지고 개념을 더 못 알아듣는다(해외 서비스를 보니 그렇다)" — 프로그래밍 개념어(repeat, if 등)를 억지로 우리말로 바꾸지 않는 방향. 구체안은 ROADMAP 라운드 3.
