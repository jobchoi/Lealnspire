# 작업 지시서 T12 — 구조 개편: MVC·OOP, 언어 리소스 파일, 에이전트용 프로젝트 지도

- 지시: Claude Code · 구현: Codex(GPT) · 검증: Claude Code(verify + 사용자 시나리오 E2E)
- 작업 브랜치: `feature/T12-mvc-i18n` (브랜치 변경·커밋·push 금지)
- 먼저 읽을 것: `AGENTS.md`, `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/TASKS.md`의 T12·T13, `src/` 전체, `e2e/helpers.ts`(화면 계약)

## 목적(사용자 요청)

1. 코드 재사용과 작업 효율을 위해 **OOP + MVC**로 정리합니다.
2. 화면 문구를 **언어별 JSON 파일**로 분리해, 언어 추가는 파일 하나 추가로 끝나게 합니다.
3. 다른 AI 에이전트가 폴더 전체를 분석하지 않고 **문서 하나만 읽고 착수**할 수 있게 `docs/PROJECT_MAP.md`를 만듭니다.
4. 다음 작업 T13(테마 월드 3종: 스케치북·기차 마을·게임기)이 **View만 갈아 끼우면** 되도록 경계를 만듭니다.

**동작 변화는 없어야 합니다.** 화면 모양, 문구, 접근성 이름(aria-label), CSS 클래스(`.palette`, `.workspace`, `.board`, `.run-button`, `.playback-controls`, `.editor`, `.block-active`, `[role=dialog]`, `[role=status]`)는 E2E가 쓰는 계약이므로 유지합니다.

## 목표 구조(권장, 이름은 조정 가능)

```
src/
  model/        # 순수 TS 클래스, React·DOM 의존 없음
    Program.ts        # 불변 블록 트리: add/remove/move/setCount/count/find, MAX_PROGRAM_BLOCKS
    Robot.ts / Grid.ts# 위치·방향, 맵 파싱
    Interpreter.ts    # run(stage, program) → RunResult (기존 규칙·안전장치 그대로)
    Stage.ts, stages/ # 스테이지 데이터(world 필드 추가: 'sketchbook' | 'train' | 'handheld')
    Score.ts
    ProgressRepository.ts  # localStorage 접근은 여기서만(기존 검증·버전·메모리 대체 유지)
  controller/   # 화면 흐름과 상태 변경, React 의존 없음
    GameController.ts # 현재 스테이지, 편집(선택·추가·삭제·이동·횟수), 실행·재생(프레임 인덱스, 속도, 타이머), 결과, 저장
    AppController.ts  # 화면 이동(첫 화면/목록/게임), 이어하기·다음 스테이지·잠금
    Observable.ts     # subscribe/getSnapshot 기반 간단한 상태 알림(useSyncExternalStore용)
  view/         # React 컴포넌트: 표시와 이벤트 전달만, 규칙·저장 로직 금지
    hooks/useController.ts  # useSyncExternalStore로 컨트롤러 상태 구독
    pages/, components/     # 기존 화면 이동
    theme/                  # T13 대비: 테마 인터페이스(블록 기호·이름·반복 표현·버튼 라벨 키)와 기본 테마 1개
  i18n/
    locales/ko.json   # 모든 화면 문구(기존 ko.ts 내용)
    I18n.ts           # t(key, params) — 플레이스홀더 {name} 치환, 빠진 키는 ko로 대체, 그래도 없으면 key 표시
```

- 기존 `engine/`, `hooks/`, `storage/`, `pages/`, `stages/`는 위 구조로 옮기고 중복을 없앱니다(이동 후 옛 파일 삭제). 공개 함수가 필요하면 클래스의 정적 메서드나 얇은 함수로 유지해도 됩니다.
- 컨트롤러는 React 없이 단위 테스트합니다(가짜 타이머/가짜 storage 주입).
- 의존 방향: view → controller → model. model은 위로 의존하지 않습니다.

## 요구사항(완료 조건)

1. 위 MVC 경계를 지킴: `src/model/`, `src/controller/`에 `react`·`react-dom`·`document`·`window` 사용 없음(단, `ProgressRepository`는 주입받은 storage만 사용).
2. View 컴포넌트에 게임 규칙·저장·재생 타이머 로직이 없음(컨트롤러 메서드 호출과 상태 표시만).
3. 문구: `src/i18n/locales/ko.json` + `I18n` 클래스. 화면의 모든 문구가 `t()`를 거침(하드코딩 한글 금지, 테스트로 확인: `src/view` 안 .tsx에 한글 문자열 리터럴 없음). 함수형 문구는 `{count}` 같은 플레이스홀더로.
4. 언어 추가 방법: `locales/en.json`을 **예시로 일부 키만** 넣고, 빠진 키는 한국어로 나오는 것을 테스트. 언어 선택 UI는 만들지 않음(기본 ko, 개발용으로 `?lang=en` 쿼리 정도는 허용).
5. 키 일치 테스트: 모든 locale 파일의 키가 ko.json의 부분집합(오타 키 방지).
6. 스테이지 데이터에 `world` 필드: 1~3 `sketchbook`, 4~6 `train`, 7~8 `handheld`(사용자 확정). 화면은 아직 기본 테마 하나.
7. `view/theme/`에 테마 인터페이스와 기본 테마. 블록 기호·색 클래스·반복 표현 등 테마마다 달라질 것을 한곳에 모음(T13에서 3개로 늘림).
8. 기존 단위 테스트는 새 구조로 옮기되 검증 내용을 줄이지 않음. 컨트롤러 단위 테스트 추가(편집, 상한, 실행·재생·결과·저장, 화면 이동·이어하기·다음).
9. `docs/PROJECT_MAP.md` 작성(에이전트가 이 문서만 읽고 착수할 수 있게, 300줄 이내):
   - 프로젝트 한 줄 소개, 실행·검증 명령(verify, e2e)
   - 폴더·파일별 역할 표(모든 소스 파일 한 줄씩)
   - MVC 경계와 의존 방향, 핵심 타입(Block, Program, Stage, Frame, RunResult, Progress)
   - 화면 흐름과 컨트롤러 메서드 요약
   - "이걸 바꾸려면 여기를" 표(스테이지 추가, 블록 종류 추가, 문구·언어 추가, 테마 추가, 저장 구조 변경, 배치 변경)
   - 테스트 지도(단위 테스트 위치, E2E 시나리오, `e2e/helpers.ts`가 화면 계약)
10. `CLAUDE.md` 0절 문서 지도 맨 위와 `AGENTS.md` 맨 앞에 "먼저 docs/PROJECT_MAP.md를 읽는다" 추가. CLAUDE.md 2절의 `src/engine/`, `src/i18n/ko.ts`, `src/storage/` 언급을 새 경로로 갱신. 4절 문서 갱신 표에 "폴더·파일 추가·이동 → PROJECT_MAP.md" 추가.
11. `docs/ARCHITECTURE.md` 2·3절을 새 구조로 갱신하고 결정 기록(MVC, I18n JSON).
12. `npm run verify` 통과. 가능하면 `npx playwright test`도(안 되면 미검증으로 보고, Claude가 실행).
