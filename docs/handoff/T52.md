# T52 지시서 — 논리 화면·6단원 퍼즐 (구현 Codex, 설계·QC Claude) [제안·잠정]

T51 완료 후 `docs/design/unit6-logic.md`, `docs/handoff/T51.md`, `docs/ROADMAP.md` 라운드 3 논리 행, `docs/PROJECT_MAP.md`, `CLAUDE.md`, glossary를 읽는다. T51의 실제 API와 다른 부분은 명시하여 조정한다.

## 화면

- if와 while 조건 슬롯을 원자·not·and·or로 편집한다. 식의 깊이 제한을 조작과 검증 양쪽에서 지킨다. 기존 단원의 조건 편집·표시와 초기 코드는 유지한다. 실행 중 편집 잠금, 되돌리기, 키보드, 접근성 이름을 유지한다.
- 타일은 영어 키워드 `not`/`and`/`or`를 glossary 단일 출처에서 표시하고 조건 설명·접근성 이름은 ko/en 리소스로 현지화한다. glossary에 설계 문서의 세 항목을 추가하고 ko/en 문구·치환 인자 일치를 검사한다. 맵마다 A 시작값을 보인다.
- 검사 프레임의 양쪽 원자 결과와 최종 결과를 나란히 표시한다. not이 있으면 원래 결과와 반전 결과를 구분하고 참·거짓은 색과 글·기호로 나타낸다. 한 단계 실행, 되감기, 변형 전환, while 재검사에서 현재 프레임과 일치한다. 세 월드·작은 화면·키보드·스크린리더에서 확인한다.
- 선택형 예측 활동은 P/Q 네 조합에 대해 and와 or 결과를 각각 고르고 답을 확인·재도전한다. 진행이나 정규 저장을 막지 않는다. 설계 문서의 ko/en 초안을 사용한다.

## 스테이지

`docs/design/unit6-logic.md`의 u6-1~u6-3 맵 문자열, 시작 A·방향, 팔레트, 상한, 정답과 초기 코드를 그대로 사용한다. 5단원 마지막 이후 순차 개방하고 모든 변형 성공 시 별 3개, 6단원 마지막은 완주 안내와 목록 복귀를 제공한다. 같은 프로그램을 각 변형에서 새 상태로 실행한다. ko/en 제목·목표·답을 직접 말하지 않는 2단계 힌트를 작성한다. u6-3은 or를 and로 고치는 조작을 실제로 확인한다.

## 필수 검증

- 세 정답의 모든 변형 성공·경로·상한, u6-3 초기 코드의 두 실패와 수정 후 성공, 팔레트·잠금·저장·별·순차 개방·이어하기를 검사한다.
- `src/model/unit5.test.ts` 방식의 상태 변환 전수 탐색으로 **각 퍼즐**에서 논리 연산 없이 상한 4 이하 동시 해가 없음을 증명한다. 문법은 팔레트의 F/L/R, 단일 원자 조건 `clearAhead`, `blockedAhead`, `aIsZero`를 쓰는 if(else 유무), 빈 몸체·양 가지·순차 연결·중첩 if 모두 포함한다. not/and/or만 제외한다. 모든 변형의 벽이 아닌 위치·네 방향·가능한 A 상태에 대한 변환을 합성하고 목표·충돌을 흡수 상태로 두어 동치 제거한다. 초기 상태는 각 맵의 A로 설정한다. 블록 수는 if와 양 가지의 모든 블록을 센다. 탐색이 반례를 찾으면 증명 성공이라고 보고하지 말고 맵·상한·팔레트를 재설계하고 경로 및 테스트를 다시 확인한다. 팔레트 밖 문법은 증명 범위가 아니다.
- 1~5단원 전체 프레임 fixture와 기존 테스트를 유지한다. ko/en × 세 월드의 조건 편집·결과, 네 조합 예측·재도전, 기존 단원 렌더링을 검사한다.
- `npm run verify`, `npm run e2e`와 새 실제 사용자 시나리오를 실행한다. 세 월드 × 1280×720·375×667·360×560의 배치, 44px 터치, 키보드, 영어, 동작 줄이기를 확인하고 스크린샷을 직접 본다. 실행 불가 시 이유와 함께 미검증으로 보고한다.

## Claude QC 결정 (2026-11-26, 잠정)

- 네 조합 예측은 기존 예측 기능(`src/model/predictions.ts`, T39 조건 예측)의 방식과 화면을 재사용해 u6-1의 선택 활동으로 둔다. 새 화면 흐름을 만들지 않는다.
- `A = 0` 원자와 상한 4는 설계대로 진행하고, 사용자 확인 항목으로 남긴다.
- **T51 QC 지적(필수)**: `validDocument`는 논리 조건 트리를 스테이지와 무관하게 받아들인다. 6단원이 아닌 스테이지(1~5단원)에 저장된 논리 조건 코드가 그대로 복원되면 안 된다(T50의 '팔레트 없는 단원에 변수 블록 복원'과 같은 문제). 스테이지(단원)별로 논리 조건 허용 여부를 정하고, 허용되지 않는 스테이지는 기존 정책대로 코드만 비운다. 저장 왕복 테스트로 확인한다.
- 정답 경로는 Claude가 세 퍼즐 모두 직접 다시 추적해 일치를 확인했다. 동시 해 부재는 전수 탐색 결과로만 판단한다.
