# T15 지시서 — 실패 지점에서 고쳐 보기 (구현 Codex, QC Claude)

브랜치: `feature/T14-t13-polish` 위에서 그대로 작업(Claude가 커밋 시 정리). 먼저 docs/PROJECT_MAP.md, CLAUDE.md, docs/ROADMAP.md, docs/TASKS.md의 T15를 읽는다. [제안·잠정] 작업이다.

## 목적
실패했을 때 "어느 블록에서, 어디서" 틀렸는지 보여 주고, 코드를 그대로 둔 채 바로 고치게 한다. 원인을 알려 주되 정답(어떻게 고칠지)은 알려 주지 않는다.

## 현재
- Model `RunResult = { frames, result: 'success'|'collision'|'unfinished'|'stepLimit' }`, `Frame`에 `activeBlockId`, `event: 'bump'` 등.
- 실패 시 ResultModal(src/view/components/ResultModal.tsx)이 문구와 "다시 하기"(재생 초기화), "닫기"를 보여 준다.

## 할 일
1. Model(순수 TS, 테스트 포함): 실행 결과에서 실패 지점을 계산하는 함수. collision → 부딪힌 순간 실행한 블록 ID와 부딪히기 전 위치·방향, unfinished → 마지막으로 실행한 블록 ID와 멈춘 위치, stepLimit → 원인 블록 없음(반복 안내 유지), 빈 프로그램 → 안전하게 null. 반복 안 블록이면 그 안쪽 블록 ID.
2. 실패 모달에 "고치기" 버튼(세 월드 공통 기호 + 라벨, 44px 이상, aria-label "고치기"). 누르면 모달이 닫히고 로봇은 출발점으로, 코드는 그대로, 원인 블록이 선택(편집 대상)된 상태가 되고 작업 공간에서 그 블록이 화면 안에 보이도록 스크롤.
3. 원인 표시: 원인 블록 타일에 실패 표시(테마별 색 테두리 + 작은 기호, 색만으로 구분하지 않음), 맵에 멈춘·부딪힌 칸 표시. 사용자가 편집하거나 다시 실행하면 표시가 사라진다.
4. 기존 "다시 하기"·"닫기" 동작과 E2E 계약(aria-label, .block-active, [role=dialog] 등) 유지. 문구는 ko.json(en.json에도 키 추가 가능하면 추가).
5. 테스트: Model 단위 테스트(충돌·미도달·단계 상한·반복 안·빈 프로그램), 컨트롤러 테스트(고치기 후 코드 보존·선택 상태).
