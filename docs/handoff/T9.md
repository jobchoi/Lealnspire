## 배경(사용자 피드백)

1. 블록을 추가하면 페이지가 길어지고 스크롤이 내려가 로봇 맵(실행 화면)이 안 보인다.
2. 블록과 버튼이 한글 텍스트뿐이라 한글을 못 읽는 저학년은 풀 수 없다.
3. 저학년 교육 측면을 고려한 디자인이 필요하다.
4. 속도 "느리게/보통/빠르게"를 기호로.
5. 이미 푼 스테이지를 다시 할 때 다음 레벨로 가는 버튼이 안 보인다. (Claude 재현: 결과 창에는 "다음 스테이지"가 있으나, 창을 닫으면 게임 화면에 다음으로 가는 수단이 없음)

## 요구사항(완료 조건)

1. **맵 고정**: 넓은 화면은 2열(왼쪽 맵, 오른쪽 편집기)에서 맵 열을 `position: sticky`로 고정하고, 작업 공간(블록 목록)은 자체 스크롤 영역(예: `max-height` + `overflow-y: auto`)으로 만들어 페이지가 계속 길어지지 않게 합니다. 375px에서는 맵을 화면 위쪽에 고정(sticky, 높이는 화면의 약 40% 이하로 축소 가능)하고 그 아래 편집기. 블록을 추가하면 새 블록이 작업 공간 안에서 보이도록 그 영역만 스크롤(페이지 전체를 스크롤하지 않음).
2. **기호 중심 블록**(아이콘이 주, 글은 작은 보조 라벨):
   - 앞으로 `⬆`, 왼쪽으로 돌기 `↺`, 오른쪽으로 돌기 `↻`, 반복 `🔁`(또는 같은 의미의 기호)
   - 반복 횟수는 `×3` 형태로 표시, 횟수 변경은 `−` / `+` 버튼(2~10, 범위 끝에서 비활성화). select 대신 큰 버튼.
   - 블록 종류별 색: 이동(앞으로) 파랑 계열, 회전 초록 계열, 반복 주황 계열. 팔레트와 작업 공간에서 같은 색·기호(일관성). 색만으로 구분하지 않도록 기호를 항상 함께.
   - 편집 버튼: 위로 `▲`, 아래로 `▼`, 삭제 `✕`(또는 🗑), 반복 선택 = "이 반복 안에 넣기"를 뜻하는 기호(예: 반복 블록 자체를 누르면 선택, 선택 시 굵은 테두리와 `⤵` 표시).
   - 모든 아이콘 버튼은 기존 한국어 이름을 `aria-label`/`title`로 유지(스크린리더·마우스 오버). 이모지/기호는 `aria-hidden`.
3. **실행 컨트롤 기호**: 실행 `▶`(가장 크고 눈에 띄는 녹색), 한 단계 `⏭`(또는 `▶|`), 처음으로 `↺`(또는 `⏮`), 힌트 `💡`, 스테이지 목록 `☰`, 다음 스테이지 `➡`. 속도는 `▶` / `▶▶` / `▶▶▶` 세그먼트 토글(선택된 것 강조, `aria-pressed`, aria-label은 느리게/보통/빠르게).
4. **다음 스테이지 버튼**: 현재 스테이지가 저장된 진행 상황에서 완료(`completed`)이고 마지막 스테이지가 아니면 게임 화면 상단에 `➡` 다음 스테이지 버튼을 항상 표시. 결과 창의 다음 버튼도 유지. 테스트 추가.
5. **저학년 고려 디자인**(교육학 근거를 GAME_DESIGN.md에 새 절로 짧게 기록):
   - 터치 영역 최소 48×48px, 블록 기호는 크게(약 1.75rem 이상), 간격 넉넉히
   - 글 최소화: 스테이지 목표 문장 옆에 목표 그림(예: 로봇 → ★) 기호, 결과 창은 큰 기호(성공 ★★★ / 충돌 💥 / 미도달 🤔)를 먼저, 글은 아래 작게
   - 이중 부호화(기호+짧은 글), 일관된 색·위치, 즉각 피드백(현재 실행 블록 강조 유지), 실수해도 부담 없는 다시 하기
   - 로봇 방향과 `⬆` 블록의 관계가 보이도록 로봇 화살표 유지
   - 색 대비 WCAG AA(본문 4.5:1), `prefers-reduced-motion` 존중
6. 문구는 `src/i18n/ko.ts`(기호도 상수로 모아도 좋음). 기존 테스트 기대값이 문구 변경으로 바뀌면 의미가 같은지 확인하고 갱신(삭제 금지).
7. 테스트: 다음 스테이지 표시 조건 순수 함수, 반복 횟수 −/+ 범위, 아이콘 버튼의 aria-label 렌더링. 의존성 추가 금지.
8. `docs/GAME_DESIGN.md`(6절 화면, 새 절 저학년 UX 원칙), `docs/ARCHITECTURE.md`(구조가 바뀌면) 갱신. `npm run verify` 통과.
