## 요구사항(완료 조건 = TASKS.md T6)

1. 화면 3개와 이동(라우터 의존성 없이 App state로): **첫 화면**(제목, 한 줄 소개, "시작하기" = 스테이지 1, "이어하기" = 완료하지 않은 첫 열린 스테이지, 진행 기록이 없으면 이어하기 숨김), **스테이지 목록**(1~8 카드: 번호·제목·최고 별·잠김 표시, 잠긴 스테이지는 비활성화 — T5의 잠금 해제 함수 사용), **게임 화면**(지금 화면 + "스테이지 목록" 버튼).
2. 결과 모달: 성공 시 "다음 스테이지" 버튼 추가(마지막 스테이지면 "목록으로"와 완주 축하 문구). 실패 모달은 지금처럼.
3. 힌트: 게임 화면에 "힌트" 버튼, 누르면 스테이지의 `hint` 표시(다시 누르면 숨김). 스테이지를 바꾸면 힌트는 닫힘.
4. 스테이지를 바꿀 때 재생 상태·모달·선택 상태가 초기화되고, 저장된 마지막 코드(T5 규칙)로 시작.
5. 반응형: 폭 375px에서 맵 위·편집기 아래, 가로 스크롤 없음. 넓은 화면은 맵 왼쪽·편집기 오른쪽.
6. 문구는 `src/i18n/ko.ts`, 버튼은 `<button>`, 화면이 바뀌면 새 화면의 제목(`h1`/`h2`)으로 포커스 이동(키보드 사용자).
7. 컴포넌트는 `src/pages/`(HomePage, StageSelectPage, PlayPage)로 나누는 것을 권장(ARCHITECTURE 3절).
8. 테스트: 이어하기 대상 계산 같은 순수 함수 단위 테스트, 페이지 렌더링 테스트(`renderToString`: 잠김 표시, 별, 이어하기 숨김). 의존성 추가 금지.
9. `docs/ARCHITECTURE.md` 2절, `docs/GAME_DESIGN.md` 6절(구현된 화면 흐름) 갱신. `npm run verify` 통과.
