## 화면
1. **상자 A 표시**(5단원): 맵 옆(좁으면 맵 위 한 줄)에 상자 그림 + `A` + 큰 숫자. 맵 카드(변형)마다 그 맵의 시작 값도 표시("A = 2"). 재생 중 set·change 프레임에서 "2 → 3"처럼 바뀌는 순간을 보여 줌(동작 줄이기 설정이면 애니메이션 없이 값만). aria: 상자 role=status "상자 A: 3" / "Box A: 3", 바뀔 때 "상자 A가 2에서 3이 됐어요" / "Box A changed from 2 to 3".
2. **팔레트**(5단원): 앞·왼·오·repeat + `set`(상자 그림 + `set`, 보이는 라벨 `set`, aria "상자 A에 값 넣기"/"Set box A") + `change`(aria "상자 A 1 바꾸기"/"Change box A by 1"). glossary 키워드, 하드코딩 금지. while·if 없음(T47 증명 전제).
3. **타일·작업 막대**: set 타일 `set A ← 3`(숫자 +/− 작업 막대, 기존 늘리기/줄이기 aria 계약과 비슷하게 "값 늘리기/값 줄이기"), change 타일 `A + 1`/`A − 1`(작업 막대 "+1/−1 바꾸기"), repeat 타일에 횟수 원천 바꾸기 "A로 반복"(aria "횟수를 A로"/"Use A as the count") ↔ 숫자. repeat A 타일은 `repeat ×A`, 재생 중 회차는 "2/A(=3)"처럼 고정된 횟수 함께.
4. **결과**: variableRange 실패 문구 ko "상자 A의 값이 0보다 작거나 20보다 커졌어요", en "Box A went below 0 or above 20", 원인 블록 표시·고치기.
5. 세 월드·세 화면 크기 배치 기준(상자 표시 포함, 맵 높이 120px 이상 — functions @layout과 같은 기준), 44px, 영어 키 일치, 5단원 묶음 "5단원: 변수 (variable)"/"Unit 5: Variables", 제목 "5단원 N: …"/"Unit 5-N: …", u5-3 성공 시 "5단원 완주!"/"Unit 5 complete!". 4단원 u4-3 완료 후 열림.

## 스테이지 (통과 중심 별 3개, 모두 startDir E, 팔레트 [forward, turnLeft, turnRight, repeat, set, change])
### u5-1 (sketchbook) — maxBlocks 4, 변형 2개
- 맵1 A=2: `##G####`, `S......` / 맵2 A=4: `####G##`, `S......` (Claude 추적: repeat A [F] → 왼쪽 → 앞 = 도착)
- solution `repeat A [F], L, F`
- ko "상자에 든 수만큼", 목표 "맵마다 상자 A에 든 수가 달라요. 같은 코드로 두 맵을 지나가요.", 힌트1(goal) "두 맵에서 상자 A의 수와 꺾는 곳까지의 칸 수를 비교해 보세요.", 힌트2 "반복 횟수에 숫자 대신 A를 쓰면 어떻게 될까요?"
- en "As Many as the Box Says", "Box A holds a different number on each map. Use the same code for both maps.", "Compare the number in box A with the cells before the turn on each map.", "What happens if you use A instead of a number for the repeat count?"
### u5-2 (train) — maxBlocks 6, 변형 2개
- 맵1 A=1: `#G...`, `####.`, `###S.` / 맵2 A=2: `##G....`, `######.`, `######.`, `####S..`
- solution `repeat 3 [ repeat A [F], L, A+1 ]` (Claude 추적: 맵1 앞1·왼·앞2·왼·앞3=도착, 맵2 앞2·왼·앞3·왼·앞4=도착)
- 증명 2개: (a) 변수 블록 없이 ≤6 불가(센서 없음), (b) **change 없이**(set·repeat A는 허용) ≤6 불가 — 전수 탐색으로.
- ko "점점 길어지는 길", 목표 "길이 한 칸씩 길어져요. 상자 A를 바꿔 가며 두 맵을 지나가요.", 힌트1(path) "꺾일 때마다 길이 몇 칸씩 길어지나요?", 힌트2 "한 번 꺾고 나서 A에 1을 더하면, 다음 길은 몇 칸이 될까요?"
- en "The Path Gets Longer", "Each part of the path is one cell longer. Change box A as you go to get through both maps.", "How much longer does the path get after each turn?", "If you add 1 to A after each turn, how long will the next part be?"
### u5-3 (handheld) — maxBlocks 5, 맵 1개(A 시작 0)
- 맵 `###G##`, `S.....`, initialProgram `repeat A [F], set A ← 3, L, F`(처음 반복 때 A=0이라 0칸 → 왼쪽 → 벽에 부딪힘), solution `set A ← 3, repeat A [F], L, F`(set을 앞으로 옮기면 성공 — 편집기의 '앞으로 옮기기' 두 번)
- 오해 퍼즐(값은 자동으로 갱신되지 않음·순서)이라 우회 증명은 하지 않음(맵 하나) — 설계 문서에 그렇게 명시.
- ko "값을 넣는 순서", "미리 놓인 코드를 고쳐 도착해요.", 힌트1(start) "처음 코드를 실행하면 로봇은 몇 칸 가나요?", 힌트2 "repeat A가 시작될 때 상자 A에는 몇이 들어 있나요?"
- en "When the Value Goes In", "Fix the code that's already there and reach the star.", "When you run the starting code, how many cells does the robot move?", "When repeat A starts, what number is in box A?"
