브랜치 `feature/T47-variables`(v1.4.1 위). 먼저 docs/ROADMAP.md 라운드 3(변수 행: "대입은 수학의 등식", "값은 자동으로 갱신된다" 오해, 변수 칸의 값 전후 표시, 초기값은 저장·실행 중 값은 미저장), docs/PROJECT_MAP.md, CLAUDE.md, src/i18n/glossary.json(set/variable)을 읽는다. [제안·잠정]. **Model·저장만**(화면·스테이지는 T48).

## 설계 (Claude 확정)
- 변수는 상자 **A 하나**(이름 입력 없음, 나중 단원을 위해 타입은 'A' | 'B' 유니언으로 두되 지금은 A만 허용). 값은 정수 0~20.
- 블록:
  - 값 넣기 `{ id, type: 'set', variable: 'A', value: number }` (0~20, 편집은 +/−)
  - 1씩 바꾸기 `{ id, type: 'change', variable: 'A', by: 1 | -1 }`
  - 변수 횟수 반복: 기존 repeat에 선택적 `countVariable?: 'A'`(있으면 count 대신 **반복을 시작할 때의 A 값**만큼 반복 — 반복 중에 A가 바뀌어도 횟수는 그대로. 이 규칙을 문서·테스트로 명시). A가 0이면 0회.
- 실행: 프로그램 시작 시 A = 0. set·change는 이동 없는 프레임 1개(단계 1, 상한 1000 포함), 프레임에 `variables: { A: number }`(그 프레임 직후 값)와 `variableChange?: { variable, from, to }`. 모든 프레임에 현재 변수 값을 실어 화면이 언제든 보여 줄 수 있게. A가 0 미만·20 초과가 되면 실행 오류 결과 `'variableRange'`(새 결과 종류, 원인 블록 = 그 change/set)로 멈춤.
- runAll: 변형마다 A=0에서 새로 시작.
- 블록 수: set·change 각 1, 변수 횟수 repeat은 기존 repeat과 같음.
- 편집 도우미: set 값 +/−(0~20), change 방향 바꾸기(+1↔−1), repeat의 횟수 원천 바꾸기(숫자↔A).
- 저장: v2 그대로. 검증 확장(set value 정수 0~20, change by ±1, variable 'A'만, repeat countVariable 'A'일 때 count 없음 허용). 옛 버전 롤백 시 이런 블록이 든 스테이지 코드는 비워지고, 5단원 기록은 옛 버전이 모르는 ID라 무시됨 — CHANGELOG에 적을 것은 Claude가 함.
- interpreter exhaustive switch 유지(새 블록 명시 처리).

## 테스트 (단위)
초기값 0, set·change 프레임과 값 전후, 반복 시작 시 A 값으로 횟수 고정(반복 중 change가 횟수를 안 바꿈), A=0이면 0회, 범위 초과 variableRange와 원인 블록, while 안 change로 세고 나중에 repeat A로 쓰기(아래 예시), 변형마다 초기화, 함수 안 set/change(함수와 main이 같은 A를 공유 — 전역 하나), 저장 왕복·검증 거부, 1~4단원 결과 회귀(fixture).
- 예시(설계 검증용, 테스트에 포함): 맵 A `S..#` / `.....` 꼴처럼 "벽까지 L칸 → 오른쪽 → 같은 L칸 → 왼쪽 → 한 칸 = 도착"인 두 맵(L=2, L=4)에서 `set A 0, while 열림 [F, A+1], R, repeat A [F], L, F`가 둘 다 성공. 맵은 Codex가 만들어 테스트에 넣고(T48에서 스테이지로 다듬음), **변수 없이**(앞·왼·오·repeat 숫자·while, ≤ 9블록) 두 맵을 동시에 못 푸는지 전수 탐색으로 미리 확인해 보고.
