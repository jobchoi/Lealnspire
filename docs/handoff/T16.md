# T16 지시서 — 요청할 때 한 단계씩 주는 힌트 (구현 Codex, 내용·QC Claude)

브랜치: `feature/T14-t13-polish` 작업 트리 그대로. 먼저 docs/PROJECT_MAP.md, CLAUDE.md, docs/ROADMAP.md, docs/TASKS.md의 T16을 읽는다. [제안·잠정] 작업이다.

## 목적
지금 힌트는 정답을 그대로 말한다(예: stage6 "앞, 왼쪽, 앞, 오른쪽을 반복해요"). 생각을 대신하지 않도록 "어디를 볼까 → 생각해 볼 질문" 2단계로 바꾼다. 정답 블록 순서는 어떤 단계에서도 말하지 않는다.

## 힌트 내용 (Claude 작성, 이 문구 그대로 ko.json에)
| 스테이지 | 1단계: 볼 곳(맵 강조) | 2단계: 질문 |
|---|---|---|
| 1 | path — "로봇과 별 사이의 칸을 세어 보세요." | "별까지 몇 칸을 가야 할까요?" |
| 2 | walls — "벽이 어디에 있는지 보세요." | "어느 칸에서 방향을 바꿔야 별 쪽으로 갈 수 있을까요?" |
| 3 | path — "로봇이 지나갈 수 있는 길을 따라가 보세요." | "길이 꺾이는 곳은 몇 군데이고, 각각 어느 쪽으로 꺾일까요?" |
| 4 | start — "로봇이 지금 바라보는 방향을 보세요." | "첫 칸에서 돌 때, 로봇 입장에서 별은 오른쪽일까요 왼쪽일까요?" |
| 5 | path — "곧게 뻗은 길의 칸 수를 세어 보세요." | "같은 블록을 여러 번 놓아야 하는데, 블록은 2개만 쓸 수 있어요. 어떻게 할까요?" |
| 6 | path — "계단 모양이 어떻게 되풀이되는지 보세요." | "계단 한 칸을 오르는 동작은 블록 몇 개일까요? 그 동작이 몇 번 되풀이될까요?" |
| 7 | path — "길이 이루는 모양을 보세요." | "한 변을 가는 동작을 찾았나요? 그 동작을 몇 번 하면 될까요?" |
| 8 | goal — "계단이 끝난 뒤 별까지 남은 칸을 보세요." | "반복이 끝난 다음에도 해야 할 일이 있을까요?" |

강조 종류: path=벽이 아닌 칸 전체(출발 제외), walls=벽 칸, start=출발 칸과 로봇 방향, goal=도착 칸. 세 월드 맵(SVG 격자, 기차 이소메트릭, 게임기 도트) 모두에서 보이게, 색만이 아니라 테두리·무늬로.

## 할 일
1. Model: Stage에 힌트 2단계 데이터(문구 키 2개 + 강조 종류). 순수 TS, 단위 테스트(모든 스테이지에 2단계가 있고, 강조 칸 계산이 맞음).
2. Controller: 힌트 단계 상태(0=닫힘, 1, 2). 힌트 버튼: 닫힘→1단계, 1단계에서 "다음 힌트" 버튼으로 2단계, 닫기. 스테이지를 바꾸면 0. 힌트를 열고 닫아도 코드·별 기준·저장 불변.
3. View: 힌트 영역에 단계 표시(1/2, 2/2), "다음 힌트" 버튼(44px+, aria-label "다음 힌트"), 기존 aria-expanded/aria-controls 유지. 맵 강조. 문구는 ko.json, en.json은 키만 맞춰 영어 번역.
4. T15 후속: 기차 이소메트릭 맵의 실패 칸 표시가 가는 점선이라 잘 안 보인다. 다른 월드처럼 굵은 테두리 + "!" 기호로 또렷하게.
5. 기존 힌트 문구 stage1Hint~stage8Hint는 새 데이터로 대체(다른 곳에서 안 쓰면 제거).

## 하지 말 것
정답 순서·블록 이름 나열, 자동으로 힌트 띄우기, 게임 규칙·저장 형식 변경, e2e 폴더·package 파일 수정, 새 의존성, 커밋·push, TASKS/NEXT_SESSION/WORK_HISTORY 수정.

## 검증·보고
`npm run verify`. 포트를 못 열면 E2E·브라우저는 미검증. 바꾼 파일, 강조 칸 계산 규칙을 보고. Claude가 e2e(실패 → 힌트 1단계·맵 강조 → 2단계 → 직접 고쳐 성공, 스테이지 이동 시 닫힘)를 추가한다.
