# T37 지시서 — 센서와 `if` (Model만) (구현 Codex, 명세·QC Claude)

브랜치 `feature/T33-unit2-plan`. **먼저 docs/design/unit2-conditions.md(T33 명세) 전체**, docs/PROJECT_MAP.md, CLAUDE.md, docs/ROADMAP.md 라운드 3 "저장·엔진 원칙"을 읽는다. [제안·잠정]. 화면은 T38에서 한다 — 이번에는 `src/model/`(순수 TS)과 저장 검증만.

## 할 일
1. 타입: `Block`에 `{ id, type: 'if'; condition: 'blockedAhead'; body: Block[] }`. `Frame`에 `event: 'check'`와 `check?: { blockId: string; condition: 'blockedAhead'; result: boolean }`. `Stage`에 `variants?: string[][]`(없으면 `[grid]`).
2. interpreter: `if` 도달 시 센서를 **한 번** 검사(앞 칸이 벽 또는 맵 밖이면 참 — 1단원 충돌 규칙과 같은 함수 재사용), 검사 프레임 1개(위치·방향 그대로, activeBlockId = if 블록, loops 정보 유지), 단계 수 1 증가(상한 1000 포함). 참이면 body 실행, 거짓이면 건너뜀. 빈 body 허용. **"그 외 = 회전" 분기를 없애고 모든 블록 종류를 명시적으로 처리, 알 수 없는 종류는 예외**(타입 검사로 누락이 드러나게 exhaustive switch).
3. 여러 맵 실행: `runAll(stage, program)` → `{ results: RunResult[]; result: 'success' | 첫 실패의 result; failedVariant: number | null }`. 모든 변형이 success여야 success. 기존 `run`은 변형 하나용으로 유지(1단원 동작 불변).
4. 실패 지점(T15 failurePoint): 변형 번호를 함께 돌려줌(첫 실패 변형 기준). 반복 회차 정보(T18)는 if 안에서도 정확해야 함.
5. program.ts/editor 헬퍼: "자식 목록을 가진 블록"(repeat, if)을 공통으로 다루는 작은 도우미로 countBlocks·찾기·삽입·삭제·이동·복제·ID 재발급이 if body에도 동작하게. 범용 플러그인 구조는 만들지 말 것.
6. 저장 검증(ProgressRepository v2): 허용 블록에 `if` 추가(condition 허용 목록 `['blockedAhead']`, body 검증, 깊이·노드 상한 동일). v2 형식은 그대로(새 버전 불필요 — v2가 이미 블록 목록을 담음). v1 이행에는 if가 없으므로 영향 없음.
7. 단위 테스트(필수):
   - if 참/거짓, 맵 밖·벽 모두 참, 빈 body, if 안의 repeat·repeat 안의 if·if 안의 if, 검사가 단계 상한에 포함, 검사 프레임의 위치·방향 불변
   - "한 번만 검사": `if 막힘 [R], F, F`가 처음엔 열려 있다가 두 칸 뒤 막히는 맵에서 충돌(명세 5절 예측 시나리오)
   - runAll: 명세 4절 U2-1 두 맵(문자열 그대로 사용)에서 `repeat 4 [ if 막힘 [R], F ]` 성공, `F F R F F`는 A만 성공·failedVariant=1
   - **지름길 검사**: U2-1 두 맵을 블록 4개 이하의 `if` 없는 프로그램(앞·왼·오·repeat 2~10, 깊이 2까지) 전수 탐색에서 두 맵 동시 성공이 없음(1초 이내)
   - 1단원 스테이지 1~8·보너스의 기존 정답·실패·프레임 결과가 바뀌지 않음(회귀)
   - 알 수 없는 블록 종류는 예외, 저장 검증은 거부
