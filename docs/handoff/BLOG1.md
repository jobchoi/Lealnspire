# 지시서 BLOG1: 블로그 연재 6편 발행 전 첨삭

브랜치: `feature/BLOG1-series` (이미 생성됨). PM·QC: Claude, 첨삭: Codex.

## 대상
`docs/blog/01-start.md` ~ `06-curriculum.md`. 발행처는 Blogger(lealnspire.blogspot.com), 형식은 개발 일지.

## 할 일
1. **사실 대조**: 날짜, 수치, 작업 ID, 검증 범위, 잠정 상태를 `docs/WORK_HISTORY.md`, `docs/TASKS.md`, `docs/NEXT_SESSION.md`, `CHANGELOG.md`, `docs/ROADMAP.md`, `docs/CURRICULUM.md`와 대조해 틀린 곳을 고친다. 근거를 찾지 못한 문장은 지우거나 표현을 낮춘다(새 사실·수치·감정·깨달음을 지어내지 않는다).
2. **개인정보 제거**: 이메일, 개인 경로(/home/...), PC·계정 이름, 접속 정보, 비밀 정보, 다른 프로젝트 운영 정보를 없앤다.
3. **문체**: 가볍게 읽히되 "핵심 질문 → 기존 가정 → 확인·선택 → 근거 → 검증과 남은 질문" 흐름이 보이게 다듬는다. 기능 나열을 줄인다. 모든 편을 같은 길이·절 수로 맞추지 않는다. 테스트 통과를 학습 효과 입증으로 쓰지 않는다.
4. **머리말**: `title`은 그대로 둔다(사용자가 따로 만든 제목으로 나중에 교체). `labels`는 `[P-Lealnspire, 개발일지, <본문 핵심 주제 1~3개>]`로 바꾼다(잠정). `status: draft` 유지.
5. 본문의 `# 제목` 줄과 `> [스크린샷: ...]` 자리표시는 유지한다(이미지는 사용자가 Blogger에서 넣음).
6. `docs/blog/README.md`의 발행 전 확인 목록 중 1~3번을 확인했으면 체크하고, 편별 "첨삭 요약" 표(편 / 고친 사실 / 지운 문장 / 남은 질문)를 추가한다.

## 하지 말 것
- docs/blog/ 밖의 파일 수정 금지(이 지시서 제외). 코드 수정 금지.
- 외부 서비스 업로드·네트워크 사용 금지. 커밋 금지(Claude가 QC 후 커밋).
