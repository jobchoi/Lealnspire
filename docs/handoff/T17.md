# T17 지시서 — 실행 전에 도착 모습 예측 (구현 Codex, 내용·QC Claude)

같은 작업 트리(`feature/T14-t13-polish`). 먼저 docs/PROJECT_MAP.md, CLAUDE.md, docs/ROADMAP.md, docs/TASKS.md의 T17을 읽는다. [제안·잠정] 작업.

## 목적
"실행해 보고 맞으면 끝"이 아니라, 실행 전에 결과를 머릿속으로 따라가 보게 한다(코드 추적). 선택형 도전이며 정규 진행에 강제하지 않는다.

## 설계
- 예측 도전은 별도 데이터(Model, 순수 TS): `{ id, stageId, program, choices: {pos, dir}[3] }`. 정답은 저장하지 않고 엔진 실행 결과(마지막 프레임 위치·방향)로 판정한다. 데이터 검사 테스트: 후보 3개가 서로 다르고(위치 또는 방향), 정확히 하나가 실제 결과와 같다.
- 도전 내용(Claude 작성): 우선 3개.
  1. stageId 2(맵 S.. / ##G), program `F R F` → 실제 결과를 엔진으로 계산, 오답 후보는 "오른쪽 대신 왼쪽으로 돈 경우"와 "회전을 무시한 경우"의 위치·방향.
  2. stageId 5(S.....G), program `3[F]` → 오답: 6칸(반복을 몸체 수로 착각하지 않은 경우의 혼동), 1칸(반복을 한 번으로 본 경우).
  3. stageId 7(S.. / ##. / G..), program `2[F F R]` → 오답: 3번 반복한 경우, 회전을 왼쪽으로 본 경우.
  (오답 후보도 엔진으로 "변형 프로그램"을 실행해 계산하고, 실제 결과와 같아지면 테스트가 실패하게.)
- 해당 스테이지를 완료한 뒤에만 열린다(스테이지 목록 카드 또는 그 스테이지 화면에 "예측 도전" 버튼, 기호: 생각 풍선/눈, aria-label "예측 도전").

## 화면
1. 도전 화면: 맵(현재 월드 테마) + 고정 코드(편집 불가, 기존 타일 표시 재사용) + 후보 3개 버튼(맵 위에 A/B/C 위치 표시와 방향 화살표, 버튼에도 같은 기호, 44px+, aria-label "후보 A: 3번째 줄 2번째 칸, 오른쪽을 봐요" 형식).
2. 하나를 고르면 바로 실행 재생(기존 재생 재사용) → 끝나면 "예상과 같아요!" 또는 "예상과 달라요. 로봇이 간 길을 다시 보세요" + 실제 위치 표시. 벌점·별 없음. "다시 고르기"로 재도전, "돌아가기".
3. 결과는 저장하지 않는다(저장 형식 불변).
4. 세 월드 × 1280×720·375×667·360×560에서 스크롤 없이 맵·코드·후보가 보임, 44px, 글자 잘림 없음.

## 하지 말 것
예측을 정규 실행에 강제, 점수·별·저장 형식 변경, e2e·package 수정, 새 의존성, 커밋·push, TASKS/NEXT_SESSION/WORK_HISTORY 수정.

## 검증
`npm run verify`. 포트 불가 시 E2E·브라우저 미검증. Claude가 e2e(2번 완료 상태 → 예측 도전 → 오답 → 실행 확인 → 다시 골라 정답)를 추가한다.
