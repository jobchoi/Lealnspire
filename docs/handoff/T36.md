## 설계 (Claude 확정)
- 새 키 `lealnspire.progress.v2` = `{ version: 2, stages: { [stageId]: { completed, bestStars, lastProgram: { main: Block[], functions: [] } } } }`. `functions`는 지금은 항상 빈 배열(4단원 함수용 자리).
- 읽기 순서: v2 키가 유효하면 사용 → 없거나 무효면 v1 키(`lealnspire.progress`)를 **스테이지별로** 변환(`lastProgram` 배열을 `{ main, functions: [] }`로) → v2 키에 저장. **v1 키는 읽기만 하고 절대 덮어쓰거나 지우지 않는다**(v1.0.0으로 롤백해도 옛 기록이 남게). 이후 쓰기는 v2 키에만.
- 손상 격리: 한 스테이지의 데이터가 무효면 그 스테이지만 버리고 나머지는 살린다(현재는 블록 하나만 이상해도 그 스테이지가 무효 처리되는지 확인하고 스테이지 단위로 유지). 알 수 없는 버전(3 이상 등)은 v1 이행을 시도하지 않고 비어 있는 상태로 시작하되 그 키를 지우지 않는다.
- 검증 상한: 블록 종류 허용 목록(forward, turnLeft, turnRight, repeat), 반복 횟수 2~10, 중첩 깊이 ≤ 8, 한 프로그램 전체 노드 ≤ 60, ID 중복 금지.
- 기록 삭제(T20): v1·v2 진행 키를 **둘 다** 지우고, 언어 설정(`lealnspire.settings`)은 유지. 안내 문구는 그대로 맞는지 확인.
- 외부 API는 그대로: 컨트롤러·화면은 지금처럼 `Block[]`(main)을 다룬다. ProgressRepository가 문서 ↔ main 변환을 숨긴다(함수 단원에서 확장).
- 변환은 순수 함수 `migrateV1toV2(raw)`로 분리하고, 앞으로 `v2→v3`처럼 단계별로 추가할 수 있는 구조(`migrations` 배열 등)로. 과하게 일반화하지 말 것.

## 테스트 (단위, Codex)
