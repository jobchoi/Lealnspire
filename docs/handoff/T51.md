# T51 지시서 — 논리 조건 Model·저장 (구현 Codex, 설계·QC Claude) [제안·잠정]

먼저 `docs/design/unit6-logic.md`, `docs/ROADMAP.md` 라운드 3 논리 행, `docs/PROJECT_MAP.md`, `CLAUDE.md`, `src/i18n/glossary.json`을 읽는다. T51은 Model·저장만 담당한다. 화면과 6단원 스테이지는 T52다. 사용자 승인 전 설계는 잠정이다.

## 설계

- 설계 문서의 Condition 트리와 원자 `aIsZero`를 if와 while 양쪽에 도입한다. 기존 if의 `blockedAhead`, while의 `clearAhead` 문자열은 그대로 수용·왕복한다. 새 트리는 원자, not 원자, 또는 and/or 하나와 각 원자 앞 선택적 not만 허용한다. 잘못된 형태·연산자·원자·과도한 깊이와 노드는 거부한다. A는 기존 실행 상태를 읽고 변경하지 않는다.
- 모든 원자는 부작용 없이 왼쪽부터 빠짐없이 평가한다. 단락 평가하지 않는다. 검사당 기존처럼 한 단계·한 check 프레임이다. 기존 문자열 검사 프레임은 모양과 동작을 유지한다. 새 트리의 check에는 전체 식, 최종 result, 순서가 있는 각 원자의 종류·원래 값·식에서의 경로와 not 적용 결과를 담아 두 원자와 최종 결과를 화면에서 나란히 표현할 수 있게 한다. 단항도 일관되게 표현한다. while은 진입 및 매 반복 뒤 다시 평가하고 기존 단계·반복 제한을 지킨다.
- Model의 생성·불변 편집·복제 및 문서 검증에 조건 선택과 연산자 변경에 필요한 API를 제공한다. 블록 수는 식 노드를 포함하지 않는다. 기존 호출·변수·가지·ID 소유권 및 exhaustive 분기를 유지한다.
- 저장 v2를 유지하고 식 검사만 확장한다. 유효한 모든 식 및 기존 문자열 왕복, 잘못된 식의 스테이지별 격리, 완료·별·다른 스테이지 보존, 깊이·노드·필드·순환 객체 방어를 확인한다. 실행 상태는 저장하지 않는다. 이전 v2 구현에서 새 조건이 알려진 스테이지의 코드를 비우고 새 ID를 무시하며 재저장 시 손실될 수 있는 롤백 영향을 이전 구현 fixture 또는 독립된 이전 검증기로 검증한다. v1은 백업으로 간주하지 않는다.

## 테스트

네 입력 조합의 and/or, not, 양쪽 모두 실제 평가됨, 동일 원자 중복·순서, if 양 가지, while 0회·재검사·무한 반복 예산, 함수 안과 변형별 A 초기화를 검사한다. 원자 결과와 not 적용 결과·최종 결과의 프레임을 검증한다. 기존 문자열 조건과 저장 fixture를 보존하고, **1~5단원 전체 정답의 결과 및 전체 프레임 fixture**를 변경 전 기준으로 확보하여 회귀를 검증한다. fixture 변경이 필요하면 이유와 차이를 보고하고 기존 기대값을 무근거로 갱신하지 않는다.

## 하지 말 것

화면·스테이지·E2E·package 수정, 물건 요소, 새로운 저장 버전, 임의의 중첩 논리식, 커밋·push·브랜치 변경, TASKS/NEXT_SESSION/WORK_HISTORY 수정 금지. Model 및 관련 테스트·fixture에 한정한다.

## 검증 및 보고 형식

`npm run verify`를 실행한다. 보고: 변경 파일, 조건·저장·롤백·1~5단원 fixture 결과, 실행한 검증과 미검증 사유, 열린 문제. 구현 결과가 설계와 다르면 차이와 근거를 적는다.
