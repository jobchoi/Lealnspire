# T84-1·2 지시서 — 학습 기록 명세·저장 v3·집계 (Model만, 구현 Codex, 기획 GPT, 확정·QC Claude)

브랜치 `feature/T84-learning-history`. 먼저 docs/design/learning-history.md(**1-1절 사용자 결정 = 기준**, 2절 GPT 원문 1·2·7절), CLAUDE.md(2절 저장 규칙), src/model/ProgressRepository.ts를 읽는다. [제안·잠정]. **이번에는 화면·컨트롤러를 바꾸지 않는다**(이벤트 연결은 T84-3).

## 구현 (src/model/ — React·DOM 없는 순수 TS)
1. `src/model/history.ts`: 학습 이벤트 타입(설계 1절 표: 방문 시작·종료, 시도 시작, 실행 결과(변형별·실패 종류·원인 블록 종류), 결과 도달/중단, 코드 변경 요약, 고치기, 되돌리기, 힌트 단계, 시범 시작·끝, 완료 확정, 다시 보기 선택·해제)과 공통 봉투(이벤트 id, 기기 내 순번, 학습자 익명 id, 방문·시도 id, 활동 종류·id, 단원, 기록일, 방문 경과 시간, 앱·평가 기준 버전). 실패 종류는 실행기 결과 그대로.
2. 저장: 진행 문서 **v3**(v2 + 익명 학습자 id + 히스토리 시작일, v1·v2 이행 — 완료·별·마지막 코드 보존, 과거 상세 없음 표시) + 별도 키의 **학습 이력 v1** 문서. 모두 `ProgressRepository`(또는 그 안에서 주입받은 storage만 쓰는 하위 모듈)에서만 읽고 쓴다. 손상 격리(이력 손상이 진행을 지우지 않음, 잘못된 이벤트만 제외), 미래 버전은 덮어쓰지 않음, 기존 v2 원본 보존 정책은 지금의 v1 원본 보존과 같은 방식.
3. 보존 정리: 상세 90일·시도 2,000·이벤트 10,000·앱 전체 2MB(문자열 길이×2) 중 먼저 닿는 것 → 오래된 종료 방문을 퍼즐별 누적 요약으로 접고 상세 제거. 저장 용량 오류 시 한 번 더 정리 후 재시도, 실패하면 메모리 유지(기존 `persistent` 계약과 T78 안내 유지).
4. 집계 순수 함수(`src/model/historySummary.ts`): 단원별 완료/전체(진행 문서 기준), 퍼즐별 시도 수·완료·실패 종류 빈도·힌트 단계 사용 시도 수/전체·시범 이용·활동 추정 시간(60초 비활동 제외, 재생·시범 분리), "살펴볼 퍼즐"(최근 종료 실행 3회 연속 실패, 중단은 제외), 상세 범위·누적 요약 구간을 섞어 이중 집계하지 않음.
5. 전체 삭제: 진행·이력·옛 원본 키 모두 삭제, 언어 설정 유지(기존 T72 삭제 실패 처리 계약 유지).
6. 단위 테스트: 이행(v1·v2 → v3), 손상 격리, 미래 버전, 보존 상한별 정리와 요약 합계 불변, 용량 오류 재시도, 삭제, 집계 대표 흐름(실패 3회→힌트→성공, 중단 실행 제외, 비활동 제외), 개인정보 필드 없음.
