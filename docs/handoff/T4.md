## 요구사항(완료 조건 = TASKS.md T4)

1. 실행 컨트롤: **실행**(처음부터 끝까지 자동 재생), **한 단계**(다음 프레임 하나), **처음으로**(첫 프레임으로, 재생 중지), **속도** 3단계(느리게·보통·빠르게, 예: 800/400/150ms). 실행 버튼을 누를 때 `run(stage, program)`을 한 번 호출해 `Frame[]`을 만들고, 화면은 프레임 인덱스만 들고 재생(D5). 재생 로직은 `src/hooks/usePlayback.ts`, 프레임 인덱스 계산 같은 순수 부분은 테스트 가능하게 분리.
2. 맵(`Board`)은 현재 프레임의 위치·방향을 표시. 충돌 프레임(`bump`)은 눈에 띄게(예: 흔들림 또는 빨간 테두리, `prefers-reduced-motion`이면 애니메이션 없이).
3. 편집기에서 현재 프레임의 `activeBlockId` 블록을 강조(편집기 props로 전달).
4. 결과 모달(마지막 프레임 도달 후): 성공이면 별 개수와 "다음 스테이지"는 아직 없으니 "다시 하기"/"닫기", 실패면 이유(충돌: "벽에 부딪혔어요", 미도달: "목적지에 도달하지 못했어요", 단계 초과: 안내 문구). 모달은 `role="dialog"`, `aria-modal`, 열리면 포커스 이동, Esc로 닫힘.
5. 별 평가(잠정, 순수 함수 `src/engine/score.ts` + 테스트): 성공 시 블록 수 ≤ `starBlocks` → 3개, ≤ `starBlocks + 2` → 2개, 그 외 1개. 실패는 0개. `docs/GAME_DESIGN.md` 3절에 "잠정"으로 기록.
6. 재생 중(그리고 "한 단계" 진행 중 처음으로 누르기 전)에는 편집 잠금(팔레트·편집 버튼 비활성화). 처음으로를 누르면 편집 가능. 프로그램이 비어 있으면 실행 버튼 비활성화.
7. 문구는 `src/i18n/ko.ts`. 버튼은 `<button>`, 키보드 조작 가능.
8. 테스트: 순수 함수(점수, 프레임 진행) 단위 테스트, 결과 모달·강조 렌더링 테스트(`renderToString`). DOM 테스트 라이브러리 추가 금지.
9. 375px에서 가로 스크롤 없음. `docs/ARCHITECTURE.md` 2절 갱신. `npm run verify` 통과.
