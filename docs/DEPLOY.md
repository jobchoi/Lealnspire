# 정적 배포 준비

T27은 배포 산출물과 절차를 준비합니다. 실제 게시, 호스트·도메인·원격 설정은 사용자 승인 후 담당자가 진행합니다.

## 빌드와 업로드

1. 의존성을 설치한 작업 트리에서 `npm run verify`를 실행합니다.
2. 루트 배포는 `npm run build`, 하위 경로는 `npm run build -- --base=/경로/`로 빌드합니다. 예: `npm run build -- --base=/lealnspire/`. 시작·끝 슬래시를 포함하고 실제 게시 경로와 일치시킵니다. 기본 base는 `/`입니다.
3. 현재 배포본의 `dist` 전체와 빌드에 사용한 base·버전·게시 날짜를 별도로 보관합니다. 다음 빌드는 dist를 덮어씁니다.
4. 새 `dist`의 **내용 전체**를 해당 호스트의 게시 루트 또는 지정 하위 디렉터리에 업로드합니다. `assets/`, `index.html`, `guide.html`, favicon을 함께 게시합니다. 앱에는 서버 API가 필요하지 않습니다.
5. `/lealnspire/`처럼 끝 슬래시가 있는 앱 주소, `/lealnspire/guide.html`, 안내 페이지의 `./` 복귀 링크를 확인합니다. `/lealnspire` 요청은 끝 슬래시 주소로 리다이렉트하도록 호스트에서 설정합니다.

Vite는 HTML 자산 참조·import한 자산·CSS URL을 base에 맞게 바꿉니다. 동적으로 만든 안내 링크는 `import.meta.env.BASE_URL`을 사용합니다. 정적 안내 페이지는 외부 자원을 요청하지 않습니다.

## 게시 전 체크리스트

아래는 실행해야 할 항목이며, 이 문서 자체가 통과 기록은 아닙니다.

- [ ] `npm run verify` 통과
- [ ] `npm run e2e` 사용자 시나리오 통과 및 스크린샷 육안 확인
- [ ] Claude가 구성하는 `e2e:prod`로 루트(`/`) production build 검증
- [ ] `e2e:prod`로 하위 경로(`/lealnspire/`) production build 검증
- [ ] 각 경로에서 홈 → 내 기록 안내 → 교사·보호자 안내 → 앱으로 돌아가기 확인
- [ ] 안내 링크 키보드 접근·포커스 순환, 44px 이상 터치 영역, 375px 화면 및 안내 인쇄 미리보기 확인
- [ ] 게임·안내 페이지 모두 외부 요청 0건, 콘솔 오류 0건, 자산 404 없음
- [ ] 기존 기록 유지·새로고침·삭제 확인
- [ ] 이전 dist 보관 및 실제 게시 경로와 base 일치 확인

지시서에 따라 `e2e:prod` 스크립트와 E2E 설정의 구성·검증은 Claude 담당입니다. 실제로 실행하지 못한 항목은 미검증으로 남깁니다. 수동 확인은 각 base로 빌드한 후 `npm run preview -- --base=/lealnspire/`(루트는 `npm run preview`)로 시작해 표시된 주소를 엽니다. preview는 로컬 검증용입니다.

## 캐시와 업데이트

HTML(`index.html`, `guide.html`)은 `Cache-Control: no-cache`로 재검증하도록 설정합니다. 해시가 붙은 `assets/`는 장기 캐시할 수 있습니다. 새 HTML이 이전 자산을 참조하거나 이전 HTML이 삭제된 자산을 참조하지 않도록 전체 산출물을 함께 교체하고, 가능하면 이전 해시 자산도 전환 기간 보존합니다. CDN을 쓰는 호스트라면 HTML 캐시도 무효화합니다. 호스트별 실제 설정은 게시 승인 후 확인합니다.

## 기록의 저장 범위

현재 저장 키는 `lealnspire.progress`이며 경로 접두사는 없습니다. localStorage는 **출처(프로토콜·도메인·포트)마다 따로 저장**됩니다. 도메인·프로토콜·포트가 바뀌면 이전 사용자 기록이 보이지 않습니다. 브라우저·프로필·기기가 달라도 기록은 공유되지 않습니다.

**지시서의 “기록은 도메인·경로마다 따로 저장됨”은 현재 구현과 다릅니다.** 같은 출처에서 `/`를 `/lealnspire/`로 옮기기만 하면 기록은 공유됩니다. 같은 출처에 여러 사본을 두어도 같은 저장 키를 사용하므로 기록이 섞일 수 있습니다. 경로별 격리가 필요하면 별도의 저장 정책 작업으로 결정해야 합니다.

## 되돌리기

1. 문제가 생긴 배포본도 별도로 보관합니다.
2. 이전에 보관한 dist 전체를 원래와 같은 도메인·경로에 재업로드하거나 호스트의 이전 배포본으로 전환합니다. 다른 base로 빌드한 파일을 그대로 쓰지 않습니다.
3. HTML 캐시를 무효화하고 새 탭에서 앱·자산·guide.html·복귀 링크·기록을 확인합니다.
4. 정적 파일 복원은 브라우저 기록을 복원하지 않습니다. 장애 대응 중 사용자 기록을 삭제하지 않습니다. 향후 저장 형식이 바뀌면 이전 버전과의 호환성을 별도로 검증합니다.

근거: [Vite production build·Public Base Path·캐시 안내](https://vite.dev/guide/build.html). 로컬 설치 버전은 package-lock.json을 기준으로 합니다(T27 검증 시 Vite 8.3.8).

## 라즈베리파이 메모 (준비만, 실제 배포는 사용자 결정 후)

사용자 계획(2026-11-25): 배포 서버는 사용자의 라즈베리파이. 아직 배포하지 않습니다.

- 앱은 정적 파일뿐이라 nginx·Caddy 같은 웹 서버가 `dist` 폴더를 내주기만 하면 됩니다(Node 실행 불필요).
- 버전별 보관과 즉시 롤백 예시: `/srv/lealnspire/releases/v1.0.0/`(각 버전의 dist), `/srv/lealnspire/current` → 사용할 버전 폴더를 가리키는 심볼릭 링크, 웹 서버는 `current`를 루트로. 되돌릴 때는 링크만 이전 버전으로 바꿉니다.
- 하위 경로(예: `http://<파이>/lealnspire/`)로 내면 빌드 때 `--base=/lealnspire/`를 꼭 맞춥니다.
- 기록은 출처(주소·포트)마다 따로 저장되므로, 파이의 주소나 포트를 바꾸면 아이들 기록이 안 보입니다. 처음 정한 주소를 유지하세요.
- 같은 집·교실 네트워크 안에서만 쓰면 오프라인(PWA)은 필요 없습니다(T32 보류).
