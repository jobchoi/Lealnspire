# AI로 시작하는 첫 블록부터 아이언맨까지 #1 — AI와 작은 교육 게임 시작하기

AI 코딩 도구에 “게임을 만들어 줘”라고 말하면 화면과 코드가 빠르게 나올 수 있습니다. 하지만 무엇을 배우는 게임인지, 어디까지 만들지, 결과가 제대로 동작하는지는 여전히 정해야 합니다. Lealnspire는 아이가 명령 블록과 반복을 이용해 로봇을 목적지까지 보내는 웹 게임입니다. 이 프로젝트는 목표를 정하고 작업을 잘게 나누는 데서 출발했습니다.

## 먼저 정한 것

첫 제품은 순서와 반복을 배우는 닫힌 경험을 목표로 삼았습니다. 세부 기획은 아직 확정 전인 잠정안입니다. 정규 스테이지 8개를 완주하고, 선택형 보너스와 예측을 포함해 실행한 뒤 실패 원인을 찾아 고치는 흐름입니다. 정적 사이트와 브라우저 저장소를 사용하며 회원가입이나 외부 전송을 전제로 하지 않습니다.

기능이 많을수록 좋은 것은 아니었습니다. 로드맵에서는 정답을 자동으로 주는 AI 챗봇, 순위표, 보호자 감시 화면을 만들지 않기로 했습니다. 힌트도 정답 순서를 알려 주기보다 관찰과 질문으로 아이가 직접 생각하도록 두 단계로 설계했습니다. 이 선택은 학습 경험을 우선한 기획 판단입니다. 테스트 통과만으로 실제 학습 효과가 입증되는 것은 아닙니다.

## 사람과 AI의 역할

사람은 목표와 중요한 결정을 정합니다. 기록된 작업 방식에서는 Claude가 기획과 지시서, 검증과 기록을 맡고, Codex가 지시받은 범위를 구현했습니다. GPT는 독립 기획이나 읽기 전용 교차 검토에도 참여했습니다. 역할을 나누더라도 결과는 확인해야 합니다. AI가 만들었다는 사실은 정확성의 증거가 아니기 때문입니다.

지시서에는 목적과 수정할 파일, 완료 조건, 하지 않을 일, 검증 방법을 적었습니다. 예를 들어 환경 구성 작업은 스크립트와 점검 모드를 만들고 운영체제별로 무엇을 확인했는지 보고하도록 나눴습니다. 작업 범위가 작으면 실패했을 때 원인을 좁히고 다른 작업에 미치는 영향도 살펴보기 쉽습니다.

## 끝의 기준도 작게

로드맵은 첫 제품의 완성을 장기 교육과정 전체와 구분했습니다. 사용자가 시작부터 끝까지 갈 수 있는지, 키보드와 작은 화면에서 조작할 수 있는지, 저장 기록이 유지되는지, 배포 산출물을 점검할 수 있는지가 기준이었습니다. 실제 배포는 별도의 사용자 결정으로 남겼습니다.

AI와 함께 시작할 때 먼저 필요한 것은 거대한 프롬프트보다 확인 가능한 목표일 수 있습니다. 다음 편에서는 다른 컴퓨터에서도 같은 작업을 이어 가기 위해 환경을 준비하고 점검한 기록을 살펴봅니다.
