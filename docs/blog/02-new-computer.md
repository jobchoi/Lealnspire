# AI로 시작하는 첫 블록부터 아이언맨까지 #2 — 새 컴퓨터에서 AI 개발 환경 준비하기

작업 중인 프로젝트를 다른 컴퓨터에서 이어 가려면 코드만 가져오는 것으로 끝나지 않습니다. Git과 Node.js, 의존성, 테스트용 브라우저가 준비되어야 하고, 도구가 사용하는 권한도 확인해야 합니다. Lealnspire는 이 준비를 스크립트와 점검 모드로 정리했습니다.

## 설치와 점검은 다릅니다

Git은 변경 이력을 다루고, Node.js와 npm은 웹 프로젝트의 도구를 실행합니다. SSH는 GitHub 저장소에 인증해 접속하는 방법입니다. 인증 정보 자체를 문서나 화면에 공개하지 않는 것이 중요합니다.

프로젝트에는 환경 구성 스크립트와 현재 상태를 살펴보는 점검 모드가 있습니다. 다음은 저장소에서 쓰는 명령입니다.

```sh
bash scripts/setup.sh --check
bash scripts/setup.sh
npm run verify
npm run e2e
```

첫 명령은 점검 모드이고, 두 번째는 환경을 구성합니다. `verify`는 린트, 단위 테스트, 빌드를 차례로 실행합니다. E2E는 브라우저에서 사용자 시나리오를 확인하는 테스트입니다. 실제로 설치나 설정을 바꾸기 전에 출력과 필요한 권한, 비용을 확인합니다.

> [스크린샷: 개인정보를 가린 점검 모드 결과]

## 도구마다 준비할 것이 있습니다

프로젝트의 MCP는 외부 도구를 연결하는 방식으로, 라이브러리 문서를 살펴보는 Context7과 브라우저를 확인하는 Playwright를 사용합니다. 연결이나 승인이 필요할 수 있으므로 상태를 확인하고, 문서 조회가 불가능하면 공식 문서를 확인하도록 규칙을 정했습니다. 질의에 코드나 비밀 정보를 넣지 않는다는 규칙도 있습니다.

브라우저 이름이 같아 보여도 용도가 다를 수 있습니다. 2026년 11월 26일 새 환경에서는 MCP용 브라우저가 준비되어 있었지만 E2E용 Chromium은 없었습니다. 그 결과 처음 실행한 E2E 220개가 모두 실패했고, 이후 환경 구성 스크립트에 해당 브라우저의 설치와 존재 점검을 추가했습니다.

## 확인한 범위를 함께 적기

T0b 환경 구성 작업에서 Linux 전체 실행과 Windows PowerShell 5.1 점검 모드는 확인됐습니다. macOS 전체 실행과 Windows 전체 설치는 확인하지 못했습니다. 나중에 보강한 Windows 스크립트 역시 해당 검증 환경에 Node가 없어 확인하지 못했습니다.

한 환경의 성공을 모든 환경의 성공으로 옮겨 적지 않는 것이 핵심입니다. 실패한 항목뿐 아니라 실행하지 못한 항목도 남겨야 다음 사람이 무엇부터 확인할지 알 수 있습니다.
