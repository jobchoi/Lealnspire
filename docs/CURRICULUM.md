## 2. 1단원 학습 목표 [확정]

- 컴퓨터는 명령을 **순서대로** 하나씩 실행한다는 것을 이해한다.
- 명령의 순서가 바뀌면 결과가 바뀐다는 것을 경험한다.
- 같은 동작이 되풀이되는 **패턴**을 찾고 **반복문**으로 줄여 쓸 수 있다.
- [제안] 틀린 프로그램을 실행해 보고 원인을 찾아 고칠 수 있다(디버깅). — 4번 스테이지와 실패 지점 고치기(T15)로 지원
- [제안] 실행하기 전에 결과를 예측할 수 있다(코드 추적). — 예측 도전(T17)

### 설계 원칙 [제안]

- 1~4번은 블록 제한 없이 별 평가만 합니다. 5번부터 제한을 걸어 반복을 쓰게 만듭니다.
- 스테이지마다 새로운 개념을 하나만 넣습니다.
- 스테이지마다 정답 코드를 함께 저장하고, 자동 테스트로 정답이 실제 통과하는지 확인합니다(2단계에서 구현 예정).
- 맵 크기는 최대 8×8 정도로 작게 유지합니다.

### T38 U2-1 — 막히면 돌아요 [제안·잠정]

2단원 첫 퍼즐 u2-1은 sketchbook 월드, 동쪽 출발, 상한 6블록입니다. 두 맵은 unit2-conditions 명세 4절 그대로이며 정답은 repeat 4 [ if blockedAhead [오른쪽], 앞으로 ]입니다. 센서 검사와 조건 선택으로 모퉁이 위치가 다른 두 맵을 같은 코드로 통과합니다. 성공은 두 맵 모두 도착, 별은 3개 고정입니다. 정규 1~8 완료 후 열리며 보너스는 필수가 아닙니다.


### T39 2단원 확장 [제안·잠정]

모두 동쪽 출발, 상한 6블록, 두 맵 모두 성공하면 별 3개입니다. 정규 1~8 완주 뒤 U2-1 → U2-2 → U2-3 → U2-4 순서로 열리며 보너스 완료는 필요하지 않습니다.

| 스테이지 | 월드 | 학습 목표 | 정답 |
|---|---|---|---|
| U2-2 왼쪽일 수도 있어요 | sketchbook | 같은 센서로 다른 행동 선택 | repeat 4 [ if blockedAhead [왼쪽], 앞으로 ] |
| U2-3 두 번 꺾는 길 | train | 같은 조건을 여러 모퉁이에 적용 | repeat 5 [ if blockedAhead [오른쪽], 앞으로 ] |
| U2-4 if는 계속 지켜보지 않아요 | handheld | 한 번 검사와 반복 검사 구분·디버깅 | repeat 4 [ if blockedAhead [오른쪽], 앞으로 ] |

U2-4 초기 코드는 if [오른쪽], repeat 4 [앞으로]이며 A에서 충돌하고 B에서 성공합니다. U2-1 완료 후 조건 예측 도전 p-u2-1이 열립니다. 별도 단일 맵에서 고정 코드를 추적해 위치·방향을 고르고, 실행 후 처음 검사 결과와 안쪽 실행 여부를 확인합니다. 후보는 실제 엔진의 원래 코드·오해 변형 코드 결과이며, 정규 진행 기록은 바뀌지 않습니다.

### T41 조건 확장 [제안·잠정]

| 스테이지 | 월드 | 배울 것 | 맵·상한 |
|---|---|---|---|
| U2-5 | train | if/else 중 하나만 실행 | 막다른 출발·열린 출발, 4블록 |
| U2-6 | handheld | 세 맵에 같은 선택 원리 적용 | 모퉁이·막다른 출발·세로 길 세 변형, 4블록 |

제목: U2-5 막혔을 때와 열렸을 때, U2-6 세 맵 연습. 힌트는 출발 방향·연속 막힘과 세 맵의 회전 위치·횟수 및 한 반복의 선택을 묻는다. else 예측 도전은 보류한다. 2단원 완주는 U2-6 성공 시 표시한다.

## T42 3단원 조건 반복 [제안·잠정]

u2-6 이후 u3-1(벽까지 가요), u3-2(벽까지 가고 돌기), u3-3(끝나지 않는 반복)을 순차 개방한다. 길이가 다른 맵을 같은 코드로 통과하며 검사→몸체→재검사를 익히고, 조건을 바꾸지 않는 몸체를 고친다. while은 처음 거짓이면 0회 실행한다. u3-1·2는 F/L/R/repeat/while, u3-3은 F/L/R/while만 제공한다. 세 스테이지 모두 전체 변형 통과 시 별 3개다. 맵과 힌트 상세는 design/unit3-while.md 및 handoff/T42.md 참고.

## T60 7단원 매개변수 [제안·잠정]

6단원 u6-4 다음에 u7-1~3을 순차 개방한다. 모두 E 출발·A=2/4의 두 맵·6블록 상한이며 별 함수 `repeat ◆ [F], L`을 호출한다. 정의 몸체는 세고 입력 홈·인자는 세지 않는다. 모든 변형 통과 시 별 3개, u7-3 성공 시 7단원 완주를 표시한다.

| 스테이지 | 월드 | 배울 것 | main 정답 |
|---|---|---|---|
| u7-1 값 건네기 | sketchbook | 호출 시 상자 값 복사 | ★(A), ★(2), ★(A) |
| u7-2 호출마다 다른 값 | train | 같은 함수에 다른 값 전달 | ★(2), ★(A), ★(3) |
| u7-3 함수 안의 A | handheld | 바깥 A와 건네받은 ◆ 구별 | ★(A), ★(3), ★(A) |

u7-3은 입력 있는 별 함수의 `repeat A [F], L`과 완성된 main으로 시작하며 두 맵 모두 충돌한다. 함수 안 repeat 원천을 ◆로 바꾸면 두 맵을 통과한다. 매개변수만 없는 문법(숫자/A 반복·함수 두 개 포함)의 상한 이하 우회 부재는 unit7.test.ts에서 검사한다. 여러 입력·지역 대입·반환값·중첩 호출은 범위 밖이다. 상세 맵은 design/unit7-parameters.md.

## 9단원 이벤트 (T67) [제안·잠정, 브라우저 QC 대기]

학습 목표는 신호가 와야 처리기가 실행됨, 연결 순서와 실행 순서의 구별, 신호 순서에 따른 한 번에 하나의 처리기 실행이다. 8단원 다음에 순차 개방한다. 팔레트는 F/L/R/repeat/on이며 두 시나리오를 같은 코드로 해결한다. 맵·신호·정답의 기준은 [design/unit9-events.md](design/unit9-events.md)다.

| 퍼즐 | 월드 | 목표 | 몸체 포함 상한 |
|---|---|---|---:|
| u9-1 신호가 와야 출발 | sketchbook | 닫힌 문 앞 main과 신호 뒤 처리기의 실행 시점 구별 | 3 |
| u9-2 연결과 순서 | train | ◇→○와 ◇→△→○, 카드 순서와 신호 순서 구별 | 6 |
| u9-3 잘못 연결한 처리기 | handheld | 몸체를 유지하고 서로 바뀐 연결 수정 | 7 |

on 없는 문법 전체(F/L/R·순차·repeat 2~10·임의 중첩·빈 몸체)의 변환은 각 퍼즐 5개, 성공 0개다. 압축 효과의 증명이 아니라 제한 팔레트와 공급 경계에서 실행 시점이 필요함을 보인다. u9-3 성공 시 9단원 완주 문구를 표시한다.

## 11단원: 탐색 (T70, 제안·잠정)

같은 목표 칸을 찾아도 입력과 순회 방향·조기 종료에 따라 비교 횟수가 달라짐을 관찰한다. 목표 값은 7이며 각 문제는 같은 코드로 두 리스트를 검사한다. 블록은 전진(main 최상위만), 순회(앞/뒤), 현재 값 일치 조건, 가장 안쪽 순회 멈추기로 제한한다. 일치 비교가 찾은 번호를 자동 기록하며 찾은 뒤 별에 도착하고 비교 상한 이하여야 성공한다.

| 문제 | 리스트 ① / ② | 블록 / 비교 상한 | 관찰 |
|---|---|---|---|
| u11-1 찾은 칸을 표시해요 | [7,2,4] / [4,2,7] | 3 / 3 | 빈 조건 몸체도 일치 칸을 표시한다(3/3회 비교) |
| u11-2 찾았으면 멈춰요 | [7,2,4,1,3] / [2,7,4,1,3] | 4 / 2 | 발견 즉시 멈추면 1/2회 비교한다 |
| u11-3 뒤에서 찾으면? | [2,4,1,7,3] / [2,4,1,3,7] | 4 / 2 | 초기 앞 방향 4/5회를 뒤 방향 2/1회로 고친다 |

특정 방향이 항상 빠르다고 일반화하지 않는다. 중복 목표·못 찾는 경우·빈 리스트·정렬·이진 탐색·Big-O는 범위 밖이다. 구현·전수 열거 수치·브라우저 미검증 범위는 `design/unit11-search.md` 6절에 기록한다.
