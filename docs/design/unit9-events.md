# 9단원 이벤트 — 신호가 오면 실행 [제안·잠정]

> 기획: GPT 독립 기획안(2026-11-26, 읽기 전용, 원문 `~/project/_progress/logs/unit9-gpt-plan.md`) → Claude 검토·확정(세 퍼즐 경로 직접 추적). 근거: ROADMAP 라운드 3 이벤트 행(결정적 이벤트, 한 처리기씩, 동시 실행 제외, "이벤트 블록은 위에서부터 자동 실행된다" 오해).

## 1. 배울 것

- `on ◇ [처리기]`는 **신호가 와야** 실행된다. 놓인 순서대로 자동 실행되지 않는다.
- 처리기는 **한 번에 하나**, 신호가 온 순서대로(대기열). 연결된 처리기가 없는 신호는 아무 일도 일으키지 않는다.
- 신호가 없으면 아무것도 실행되지 않는다.

## 2. 의미 (Model)

- 블록 `on {signal: '◇'|'○'|'△', body}` — **main 최상위 전용**, 신호당 하나. on은 실행 명령이 아니라 연결 선언(main 순회에서 건너뜀).
- 실행: main을 한 번 실행 → 외부 신호열에서 신호를 하나씩 공급(main 종료 후, 그리고 각 처리기 종료 후) → 대기열 FIFO → 연결된 처리기 실행(하나씩). 신호열이 끝나면 미도착은 `unfinished`. 시간·재생 속도와 무관(결정적).
- 장치: ◇는 문 a, ○는 문 b를 연 뒤 전달(열린 문은 계속 열림). △는 장치 변화 없음. 닫힌 문은 벽과 같다(앞으로 가면 충돌).
- 제한: 기존 1000단계·반복 진입 1000회 유지, 신호 공급·처리기 시작·종료도 단계에 셈. 대기열 64·총 발행 128 상한. 학습자용 신호 보내기 블록 없음.
- 프레임: 신호열 커서, 대기열, 현재 처리기 `{onId, signal, serial}`, 문 상태. 표시용 `Frame.event`와 별도 필드.
- 저장: v2 유지, `events: true` 스테이지에서만 on, 중첩 on·중복 연결·알 수 없는 신호 거부(그 코드만 비움). 실행 상태 미저장.

## 3. 퍼즐 (공통: 시작 E, 팔레트 F/L/R/repeat/on만, 상한 = main·on·몸체 합산, 별 통과 중심)

| 퍼즐 | 월드 | 맵 | 신호열(시나리오 2개 — 같은 코드로 둘 다) | 정답(main은 빔) | 상한 |
|---|---|---|---|---|---|
| u9-1 신호가 와야 출발 | sketchbook | `#####`/`#SaG#`/`#####` | ◇ · △→◇ | `on ◇ [repeat 2 [F]]` | 3 |
| u9-2 연결과 순서 | train | `#######`/`#Sa.bG#`/`#######` | ◇→○ · ◇→△→○ | `on ◇ [repeat 2 [F]]`, `on ○ [repeat 2 [F]]` | 6 |
| u9-3 잘못 연결한 처리기(고치기) | handheld | `###G#`/`###.#`/`#Sa.#`/`#####` | ◇→○ · △→◇→○ | `on ◇ [repeat 2 [F]]`, `on ○ [L, repeat 2 [F]]` | 7 |

- 시나리오 2개는 기존 `variants` 장치로 표시(맵은 같고 신호열만 다름 — 맵 카드에 신호열 표시).
- Claude 추적: u9-1 ◇ → 문 a 열림 → F F 도착. u9-2 ◇ → (3,1)까지, ○ → 문 b 열림 → F F 도착. u9-3 ◇ → (3,2), ○ → 북쪽으로 돌아 F F 도착. △는 아무 처리기도 없어 그대로.
- u9-2는 **○ 카드를 위에 놓아도** ◇ 처리기가 먼저 실행됨을 보여 준다(놓인 순서 ≠ 실행 순서).
- u9-3 미리 놓인 코드는 두 처리기의 신호가 서로 바뀜(◇에 `L, repeat 2 [F]`) → 첫 신호에서 북쪽 벽 충돌. 몸체는 그대로 두고 머리 기호 두 개를 바꿔 고친다.
- **증명(GPT 독립 Python)**: on만 뺀 문법(F/L/R·순차·repeat 2~10 임의 중첩·빈 몸체) 전체의 상태 변환 — 신호 전 출발점이 닫힌 문과 벽으로 고립돼 main이 도달하는 상태는 출발점 네 방향과 충돌뿐, 고유 변환 5개, 성공 0 → **상한과 무관하게** on 없이 불가. 끝난 main은 신호 뒤 다시 실행되지 않음.
- **정직한 한계**: 제한 팔레트에서 "실행 시점" 때문에 이벤트가 필요함을 보인 것이지 블록 압축 효과의 증명은 아님. while 검사 도중 신호를 공급하는 규칙으로 바꾸면 폴링 우회가 생김 → 신호 공급 경계(main·처리기 종료 후)를 바꾸지 말 것.
- 범위 밖: 동시 실행·선점·실시간 입력·무작위 신호·신호 보내기 블록·여러 구독자·연쇄 이벤트.

## 4. 화면

- on 카드: 머리에 신호 기호(◇ ○ △ 선택 버튼, 글자 입력 없음), 몸체는 함수 카드처럼. 카드 배치 순서는 실행 순서가 아님을 안내.
- 실행 중: **다음 신호열 → 대기열 → 실행 중 처리기**를 구분해 표시, 실행 중 카드 강조, 문은 자물쇠 열림/닫힘 모양, 연결 없는 신호는 "연결된 처리기 없음"으로 지나감. 한 단계는 신호 전달·처리기 시작·종료에서 멈춤. 색만으로 구분하지 않음.
