# 2단원 명세 — 조건 `if` (T33, 구현 없음)

> [제안·잠정] Claude 작성(2026-11-25). 근거: 사용자 결정(GAME_DESIGN 11절: 기본 개념 전부, 글자 암기가 아닌 개념), ROADMAP 라운드 2·3(GPT: "앞이 막혔으면", 도달 시 한 번 검사, 같은 코드로 여러 맵). 구현은 T36(저장 v2) → T37(Model) → T38(화면·퍼즐).

## 1. 배울 것

- 프로그램은 **실행 중에 주변을 보고** 다음 행동을 고를 수 있다(센서 → 참/거짓 → 선택).
- 조건은 **그 블록에 도달했을 때 한 번만** 검사한다. 계속 지켜보지 않는다.
- 조건을 쓰면 **하나의 프로그램이 서로 다른 맵**에서 모두 통한다(일반화).

## 2. 블록과 의미

| 블록 | 타일 표기(개념어 방침) | 의미 |
|---|---|---|
| 조건 `if` | 기호(갈림길) + `if` + 센서 그림 `[앞 막힘]` | 도달하면 센서를 한 번 검사. 참이면 안쪽 블록들을 실행, 거짓이면 건너뛰고 다음 블록 |

- 센서는 처음엔 하나: **앞이 막힘**(`blockedAhead`) — 로봇이 바라보는 바로 앞 한 칸이 벽이거나 맵 밖이면 참. 1단원 엔진에서 "앞으로"가 부딪히는 조건과 정확히 같다.
- `if` 안에는 다른 블록(앞으로·돌기·반복·`if`)을 넣을 수 있다. 빈 `if`도 허용(검사만 하고 지나감).
- 검사는 **한 단계로 센다**(단계 상한 1000에 포함). 화면 프레임을 하나 만든다: `event: 'check'`, 결과 참/거짓. 이동은 없다.
- 블록 수: `if` 블록 1개 + 안쪽 블록. 단원 상한은 1단원처럼 10개(퍼즐마다 `maxBlocks`).
- 별 평가: 2단원은 **통과 중심**(성공하면 별 3개, 코드 길이 별 없음 — 라운드 3 원칙). 1단원 별은 그대로.

## 3. 같은 코드, 여러 맵 (변형 판정)

- 2단원 스테이지는 `variants`(맵 2~3개, 같은 출발 방향)를 가진다.
- "실행"을 누르면 **모든 변형을 차례로** 재생한다. 화면 위에 맵 카드 `1/2`, `2/2`와 각 결과(✓/!)를 보여 준다.
- **모든 변형에서 도착해야 성공**. 하나라도 실패하면 결과 창에 어느 맵에서 왜 실패했는지 표시하고, "고치기"는 그 맵으로 바꾼 뒤 원인 블록을 선택한다(T15 재사용).
- 실행 전에 모든 변형 맵을 작은 그림으로 보여 준다(무엇을 일반화해야 하는지 보이게).

## 4. 스테이지 초안 (월드는 T38에서 정함)

모두 출발 방향 동쪽(E). `S` 출발, `G` 도착, `#` 벽.

### U2-1 "막히면 돌아요" (오른쪽 모퉁이 위치가 다른 두 맵)

```
변형 A        변형 B
S..#          S.##
##.#          #.##
##G#          #.##
              #G##
```

- 기대 정답: `repeat 4 [ if 앞 막힘 [ 오른쪽으로 돌기 ], 앞으로 ]` (4블록)
- A: 앞→앞→(막힘: 돌기)→앞→앞 = 도착. B: 앞→(막힘: 돌기)→앞→앞→앞 = 도착.
- 반복 없는 고정 코드는 A(F F R F F)와 B(F R F F F)를 동시에 풀 수 없다 → T37에서 전수 탐색 테스트로 확인(상한 이하의 `if` 없는 프로그램은 두 맵 모두 성공 못 함).

### U2-2 "왼쪽일 수도" (왼쪽 모퉁이)

U2-1을 좌우 반전한 두 맵. 정답 `repeat 4 [ if 앞 막힘 [ 왼쪽으로 돌기 ], 앞으로 ]`. 목적: 센서는 같고 행동만 바뀐다.

### U2-3 "소용돌이" (모퉁이가 두 번, 위치가 다른 두 맵)

같은 `repeat N [ if 앞 막힘 [ 오른쪽으로 돌기 ], 앞으로 ]`이 두 번 꺾는 길에서도 통함. 맵은 T38에서 크기 6×6 이하로 설계하고 정답·지름길 테스트로 확정.

### U2-4 "if는 계속 지켜보지 않아요" (고치기)

- 미리 들어 있는 코드: `if 앞 막힘 [ 오른쪽으로 돌기 ], repeat 4 [ 앞으로 ]` — 처음 한 번만 검사하므로 나중의 벽에 부딪힘.
- 한 블록 위치(`if`를 반복 안으로)만 옮기면 성공. 대표 오해를 드러내는 디버깅 퍼즐.

## 5. 예측 도전 (T39)

- 고정 코드 `if 앞 막힘 [ 오른쪽으로 돌기 ], 앞으로, 앞으로`를 처음엔 열려 있다가 두 칸 뒤에 막히는 맵에서 실행.
- 후보: (A) 벽에 부딪혀 멈춤 — 정답, (B) 모퉁이에서 돌아 내려감 — "계속 지켜본다" 오해, (C) 처음에 돌아 버림 — "막힘/열림"을 거꾸로 이해.
- 위치와 함께 "검사 결과: 참/거짓"도 고르는 선택지를 둔다.

## 6. 화면 표시 (글자 암기 없이 상태 보이기)

- 검사 순간: 로봇 앞 칸에 센서 빛(테두리·무늬), 결과는 기호(✓ 참 / ✕ 거짓)와 짧은 문구("앞이 막혔어요" / "앞이 열려 있어요"). 색만으로 구분하지 않음.
- 참이면 `if` 안쪽 블록들이 강조되며 실행, 거짓이면 안쪽 블록이 흐리게 "건너뜀" 표시 후 다음 블록으로.
- 맵 대체 설명(aria)에 센서 결과를 포함.

## 7. E2E 시나리오 명세 (T38에서 작성)

1. U2-1에서 `if` 없이 변형 A만 맞춘 코드(F F R F F) → 실행 → A ✓, B ! → 결과 창에 "2번 맵에서 벽에 부딪혔어요" → 고치기 → 맵 B로 바뀌고 원인 블록 선택.
2. 정답 코드 → 두 맵 모두 ✓ → 성공·저장 → 새로고침 후 코드 복원(v2 저장).
3. 한 단계 실행: 검사 프레임에서 센서 빛과 참/거짓 표시, 거짓일 때 안쪽 블록 건너뜀 표시.
4. U2-4: 미리 들어 있는 코드 실패 → `if`를 반복 안으로 옮겨 성공.
5. 키보드만으로 `if` 추가·안에 넣기·실행. 세 화면 크기 배치(맵 카드와 변형 표시가 있어도 맵·실행 버튼이 스크롤 없이 보임).
6. 1단원 기록(v1)이 있는 상태에서 2단원 진입·저장 후 1단원 기록 그대로.

## 8. 엔진·저장 영향 (T36·T37 지시서에 반영)

- `Block`에 `{ type: 'if', condition: 'blockedAhead', body: Block[] }` 추가. interpreter의 "그 외 = 회전" 분기를 명시적 분기로 바꾸고 알 수 없는 블록은 오류.
- `Frame.event`에 `'check'`, `Frame.check = { blockId, condition, result }`.
- `Stage.variants?: string[][]`(없으면 기존 `grid` 하나). 성공 = 모든 변형 성공. 실패 지점은 실패한 첫 변형 기준.
- 저장 v2(T36): 프로그램을 `{ main, functions: [] }`로 감싸고 v1을 단계 변환, 이행 성공 전 v1 키 보존. `if` 블록 검증(조건 값 허용 목록, 깊이·노드 수 상한).
