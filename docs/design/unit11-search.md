# 11단원 탐색·알고리즘 비교 — 같은 답, 다른 과정 [제안·잠정]

> 기획: GPT 독립 기획안(2026-11-27, 읽기 전용, 원문 `~/project/_progress/logs/unit11-gpt-plan.md` — 후반부가 일본어로 출력돼 Claude가 한국어로 옮김) → Claude 검토. 근거: ROADMAP 라운드 3 탐색 행("답이 같으면 과정도 같다" 오해, 확인한 칸·비교 횟수 표시).

## 1. 배울 것

- 목표 값을 찾는 절차는 여러 가지이고, **같은 칸을 찾아도 비교 횟수는 입력에 따라 다르다**.
- **찾으면 멈추면** 비교가 줄어든다. 어느 방향(앞/뒤)이 늘 빠른 것은 아니다.

## 2. 새 기능(최소)

- `if`의 조건 `▣ = 🎯`(🎯는 문제가 정한 목표 값, 입력 없음). 참이면 실행기가 **찾은 번호**를 기록(아이가 조작하는 변수가 아님).
- `순회 멈추기` 블록: 가장 안쪽 for each만 끝내고 다음 블록으로.
- for each 방향 선택: 앞→뒤(기본) / 뒤→앞.
- 성공 = **비교로 목표 번호를 찾은 뒤 G 도착 + 비교 횟수 상한 이하**. 상한 초과는 안전 상한(stepLimit)과 구분해 "찾았어요! 비교를 {limit}회 이하로 줄여 보세요."
- **팔레트 제약**: 전진은 main 최상위에만(순회·조건 안 금지). GPT 탐색에서 `for each [if 일치 [전진]]`이 목표 도착 즉시 종료로 멈추기 블록을 우회했기 때문 — 편집기·저장 검증·실행 모두에 적용. 팔레트: 전진·for each·if(일치)·순회 멈추기만(A·set·change·repeat·L[A]·센서·while·함수·이벤트·논리 결합 제외), 모든 A=0.

## 3. 퍼즐 (맵은 모두 `SG` 한 줄, 시작 E, 🎯=7, 같은 코드로 두 입력)

| 퍼즐 | 리스트 ① / ② | 찾을 번호 | 정답(E앞/E뒤=순회 방향, I=if 일치, B=멈추기, F=전진) | 블록 상한 | 비교 상한 |
|---|---|---|---|---:|---:|
| u11-1 찾은 칸을 표시해요 | [7,2,4] / [4,2,7] | 0 / 2 | `E앞 [I []], F` | 3 | 3 |
| u11-2 찾았으면 멈춰요 | [7,2,4,1,3] / [2,7,4,1,3] | 0 / 1 | `E앞 [I [B]], F` | 4 | 2 |
| u11-3 뒤에서 찾으면?(고치기) | [2,4,1,7,3] / [2,4,1,3,7] | 3 / 4 | `E뒤 [I [B]], F` | 4 | 2 |

- u11-1의 빈 조건 몸체는 비교 결과를 관찰하는 활동(오류처럼 보이지 않게 안내). u11-3은 앞 방향 코드를 미리 놓고 방향만 고침.
- **증명(GPT 독립 Python, 상한 이하 모든 코드 트리)**: 새 기능 없는 후보 성공 0, 비교 조건 없는 후보 성공 0, 멈추기 없는 후보는 u11-2·3에서 성공 0(u11-1은 멈추기 불필요 — 의도). 범위는 이 팔레트·전진 배치 제약·상한.
- 예측 활동(선택): 같은 입력에서 "앞에서부터 멈추기 / 뒤에서부터 멈추기 / 끝까지 비교"의 비교 횟수 — 입력에 따라 순위가 뒤집힘([7,2,4,1,3]은 1/5/5, [2,4,1,3,7]은 5/1/5).

## 4. 모델·저장·화면 (GPT 원문 5절)

- `Stage.search {target, maxComparisons}`, `forEach.direction?`, 비교 조건 타입, `breakForEach`. 실행 신호에 순회 종료 추가(가장 안쪽에서 잡고 바깥 ▣·반복 문맥 복원). `Frame.search`에 비교한 번호·값·참거짓, 비교 횟수, 확인한 번호들, 찾은 번호. 비교·멈추기도 단계 예산 1.
- 저장 v2 외피 유지, 11단원만 새 조건·방향·멈추기 허용, 전진 배치·▣ 범위·멈추기 위치 검증. 실행 결과는 저장 안 함.
- 화면: 비교 중 칸 굵은 테두리, 불일치 ×, 일치 🎯(SVG), "비교 2 / 상한 2", "번호 1에서 찾았어요.", 멈춘 뒤 남은 칸은 흐린 윤곽 + "여기부터는 보지 않았어요". 색만으로 구분 금지.
- 문구(ko/en): 조건 "▣가 🎯와 같으면" / "if ▣ equals 🎯", 멈추기 "순회 멈추기" / "stop this traversal", 방향 "앞에서부터 / 뒤에서부터" / "from the front / from the back", 횟수 "비교 {count}회 / 상한 {limit}회" / "Comparisons: {count} / limit: {limit}", 발견 "번호 {index}에서 찾았어요." / "Found it at index {index}.", 초과 "찾았어요! 비교를 {limit}회 이하로 줄여 보세요." / "Found it! Try using at most {limit} comparisons.", 되돌아보기 "같은 칸을 찾았어요. 비교 횟수도 같았나요?" / "You found the same element. Was the number of comparisons the same?"
- 위험: 전진 최상위 제약은 이 단원 전용(풀면 재증명), 상한 판정을 알고리즘 전체 우열로 일반화하지 않음. 범위 밖: 중복 목표·못 찾는 경우·빈 리스트·이진 탐색·정렬·Big-O.

## 5. Claude 검토 메모

- 맵이 `SG` 한 줄이라 로봇 이동은 단순해지고 개념은 리스트 칸 표시에 집중된다 — 앞 단원들과 화면 느낌이 달라지므로 리스트 칸 줄을 크게, 맵은 작게 두는 배치를 T(구현)에서 확인.
