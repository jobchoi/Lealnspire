## 1. 배울 것

- 목표 값을 찾는 절차는 여러 가지이고, **같은 칸을 찾아도 비교 횟수는 입력에 따라 다르다**.
- **찾으면 멈추면** 비교가 줄어든다. 어느 방향(앞/뒤)이 늘 빠른 것은 아니다.

## 2. 새 기능(최소)

- `if`의 조건 `▣ = 🎯`(🎯는 문제가 정한 목표 값, 입력 없음). 참이면 실행기가 **찾은 번호**를 기록(아이가 조작하는 변수가 아님).
- `순회 멈추기` 블록: 가장 안쪽 for each만 끝내고 다음 블록으로.
- for each 방향 선택: 앞→뒤(기본) / 뒤→앞.
- 성공 = **비교로 목표 번호를 찾은 뒤 G 도착 + 비교 횟수 상한 이하**. 상한 초과는 안전 상한(stepLimit)과 구분해 "찾았어요! 비교를 {limit}회 이하로 줄여 보세요."
- **팔레트 제약**: 전진은 main 최상위에만(순회·조건 안 금지). GPT 탐색에서 `for each [if 일치 [전진]]`이 목표 도착 즉시 종료로 멈추기 블록을 우회했기 때문 — 편집기·저장 검증·실행 모두에 적용. 팔레트: 전진·for each·if(일치)·순회 멈추기만(A·set·change·repeat·L[A]·센서·while·함수·이벤트·논리 결합 제외), 모든 A=0.

## 3. 퍼즐 (맵은 모두 `SG` 한 줄, 시작 E, 🎯=7, 같은 코드로 두 입력)

| 퍼즐 | 리스트 ① / ② | 찾을 번호 | 정답(E앞/E뒤=순회 방향, I=if 일치, B=멈추기, F=전진) | 블록 상한 | 비교 상한 |
|---|---|---|---|---:|---:|
| u11-1 찾은 칸을 표시해요 | [7,2,4] / [4,2,7] | 0 / 2 | `E앞 [I []], F` | 3 | 3 |
| u11-2 찾았으면 멈춰요 | [7,2,4,1,3] / [2,7,4,1,3] | 0 / 1 | `E앞 [I [B]], F` | 4 | 2 |
| u11-3 뒤에서 찾으면?(고치기) | [2,4,1,7,3] / [2,4,1,3,7] | 3 / 4 | `E뒤 [I [B]], F` | 4 | 2 |

- u11-1의 빈 조건 몸체는 비교 결과를 관찰하는 활동(오류처럼 보이지 않게 안내). u11-3은 앞 방향 코드를 미리 놓고 방향만 고침.
- **증명(GPT 독립 Python, 상한 이하 모든 코드 트리)**: 새 기능 없는 후보 성공 0, 비교 조건 없는 후보 성공 0, 멈추기 없는 후보는 u11-2·3에서 성공 0(u11-1은 멈추기 불필요 — 의도). 범위는 이 팔레트·전진 배치 제약·상한.
- 예측 활동(선택): 같은 입력에서 "앞에서부터 멈추기 / 뒤에서부터 멈추기 / 끝까지 비교"의 비교 횟수 — 입력에 따라 순위가 뒤집힘([7,2,4,1,3]은 1/5/5, [2,4,1,3,7]은 5/1/5).

### 전수 열거 증명

설계 원문 `~/project/_progress/logs/unit11-gpt-plan.md` 3절은 문제별 방향을 고정하고 if/else·임의 중첩·빈 몸체를 포함한다. 초기 구현에서 else를 빠뜨려 후보 수가 달랐으나 원문을 확인하고 else를 복구했다. 최상위 전진·순회 안 비교/멈추기·A=0·시작 E·팔레트를 고정하고, ID와 생략 가능한 빈 else/기본 방향 표기 차이를 중복 집계하지 않는다.

| 상한 | 전체 / 성공 | 새 기능 제외 / 성공 | 비교 조건 제외 / 성공 | 멈추기 제외 / 성공 |
|---|---:|---:|---:|---:|
| 3 (u11-1 앞) | 48 / 1 | 22 / 0 | 31 / 0 | 35 / 1 |
