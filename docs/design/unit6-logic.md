# 6단원 논리 결합 not/and/or [제안·잠정]

앞이 열림 P와 상자 A가 0임 Q를 같은 순간에 검사한다. 기존 blockedAhead와 clearAhead는 서로 부정이므로 이 둘만으로 and/or를 배우면 결과가 항상 같거나 정해진다. 새 원자는 `A = 0` 하나다. A는 5단원의 기존 상태이고 변형마다 시작값을 줄 수 있다. 좌·우 열림 센서도 독립 조건이지만 방향별 센서와 맵 설명을 늘린다. 로드맵의 물건이 남았을 때라는 예시는 별도의 물건·줍기·수량 상태가 필요하므로 이번에는 A를 독립 입력으로 사용한다. A를 물건 수라고 부르지 않는다.

## 표현과 실행

기존 문자열 조건을 계속 읽고 쓴다. 새 조건은 `{kind:'atom', atom:'clearAhead'|'blockedAhead'|'aIsZero'}`, `{kind:'not', operand: Condition}`, `{kind:'and'|'or', left: Condition, right: Condition}` 트리다. if와 while에 같은 타입을 사용한다. 새 트리는 원자 하나, 원자 앞 not 하나, 또는 and/or 하나의 양쪽에 각각 원자나 원자 앞 not을 허용한다. 즉 이항 연산자 중첩과 이중 not은 거부한다. 표현식은 블록 수에 포함하지 않으며 if/while과 그 몸체만 기존 방식으로 센다. 모든 원자는 부작용이 없다.

단락 평가하지 않고 왼쪽부터 두 원자를 모두 같은 상태에서 평가한다. 초보자가 두 결과와 최종 결과를 언제나 나란히 볼 수 있기 때문이다. 검사 전체는 기존처럼 한 단계·check 프레임 하나이며 while은 매회 다시 검사한다. `check`에 원자별 순서·조건·참거짓과 전체 트리·최종 결과를 담는다. 기존 문자열 조건의 check 형태는 그대로 보존하고 새 트리에만 추가 필드를 둔다. 중복 원자도 위치별로 기록하며 not의 결과와 원자 원래 결과를 구분한다. 검사에 이동이나 변수 변경은 없다. 한 단계 예산, 목표 즉시 성공, 반복 안전장치는 그대로다.

| P | Q | P and Q | P or Q | not P |
|---|---|---|---|---|
| 참 | 참 | 참 | 참 | 거짓 |
| 참 | 거짓 | 거짓 | 참 | 거짓 |
| 거짓 | 참 | 거짓 | 참 | 참 |
| 거짓 | 거짓 | 거짓 | 거짓 | 참 |

선택형 예측 활동에서 네 행 각각의 and·or 결과를 실행 전에 고르게 하고, 선택 뒤 위 결과와 원자 값을 보여 준다. 오답은 재도전할 수 있고 진행을 막거나 저장하지 않는다. 맵의 세 변형으로 네 조합을 모두 보여 줄 수 없으므로 예측에는 별도의 네 입력을 사용한다.

## 저장과 호환

`lealnspire.progress.v2`의 문서 외피는 바뀌지 않으므로 v2 유지가 가능하다. 이는 이전 v2 독자가 새 트리 의미를 알지 못하는 전방 호환을 뜻하지 않는다. 검증은 허용 원자·형태·깊이·노드 수·필수 필드와 정확한 피연산자 수를 검사하며 기존 블록 깊이/개수 제한과 별도 조건 제한을 둔다. 잘못된 조건은 해당 스테이지 프로그램을 기존 정책대로 비우고 완료·별과 다른 스테이지는 보존한다. 순환 객체 등 비정상 입력에도 안전해야 한다. 이전 문자열 조건은 정규화하지 않고 그대로 왕복한다. 실행 결과와 예측 선택은 저장하지 않는다.

구버전으로 롤백하면 새 조건 트리가 포함된 **기존에 알려진 스테이지**의 저장 코드는 구버전 검증에서 무효가 되어 빈 코드로 읽힐 수 있다. 6단원 ID는 구버전에서 무시된다. 구버전이 진행을 다시 저장하면 무시한 6단원 기록과 빈 코드가 v2에 덮일 수 있으므로 롤백 전 v2 백업이 필요하다. 보존된 v1은 최신 v2 기록의 백업이 아니다. 테스트로 실제 구버전의 읽기·재저장 영향을 확인한다.

## 퍼즐

공통: 시작 방향 E, 팔레트 `[forward, turnLeft, turnRight, if]`, 블록 상한 4, 별은 전체 통과 시 3개. `if`는 else 가지를 편집할 수 있고 조건 슬롯에서 원자와 not/and/or를 선택한다. repeat·while·변수 변경·함수 호출은 팔레트에 없다. `F` 앞 한 칸, `L` 제자리 왼쪽 회전. 조건의 두 원자와 연산자는 블록 수에 넣지 않는다. 모든 맵은 같은 코드를 독립 실행하며 A는 표의 값으로 초기화된다. 좌표는 왼쪽 위 (0,0), S는 (0,1)이다.

| 퍼즐 | 월드 | 변형 (위 행 / 아래 행; A) | 정답과 직접 추적 |
|---|---|---|---|
| u6-1 | sketchbook | `##` / `SG`; 0 · `G#` / `S.`; 1 · `G#` / `S#`; 0 | `if P and Q [F] else [L,F]` (4). ① 참·참 → F로 (1,1) 도착. ② 참·거짓 → L, F로 (0,0) 도착. ③ 거짓·참 → L, F로 (0,0) 도착. |
| u6-2 | train | `G#` / `S#`; 1 · `G#` / `S.`; 0 · `##` / `SG`; 1 | `if not P or Q [L,F] else [F]` (4). ① 거짓·거짓 → not P 참, L F로 (0,0). ② 참·참 → Q 참, L F로 (0,0). ③ 참·거짓 → 둘 다 거짓, F로 (1,1). |
| u6-3 | handheld | `##` / `SG`; 0 · `G#` / `S.`; 1 · `G#` / `S#`; 0 | 초기 `if P or Q [F] else [L,F]`: ① 성공, ② 잘못 F로 (1,1)에 가고 미도착, ③ F 충돌. or를 and로 바꾸면 u6-1과 같은 세 경로로 성공. |

u6-2는 not을 포함하므로 논리 연산 전체를 제거한 우회가 없는지 검사한다. 각 퍼즐에서 단일 원자만 허용하는 if와 else, 순차 연결과 중첩 if를 포함한 상한 이하 문법을 `unit5.test.ts` 방식으로 전수 탐색한다. 정답 경로는 손으로 추적했으며 동시 해 부재는 **아직 증명되지 않았다**. T52에서 테스트가 실패하면 반례를 보고하고 퍼즐을 재설계해야 한다. 팔레트 밖 블록을 포함한 일반적 불가능성은 주장하지 않는다.

## 화면·문구 초안

타일 키워드는 glossary의 영어 `not`, `and`, `or`; 조건과 설명·접근성 이름은 UI 언어다. 조작은 슬롯 선택으로 하며 철자 입력을 요구하지 않는다. 검사 시 원자 원래 값, not 적용 후 값, 최종 값을 기호와 글로 나란히 보여 준다. 값은 색만으로 구분하지 않는다. 원자 카드와 검사 프레임은 되감기·한 단계·변형 전환에도 일치해야 한다.

| 항목 | ko | en |
|---|---|---|
| P / Q | 앞이 열림 / A가 0임 | Path ahead is clear / A is 0 |
| not | 결과를 반대로 바꿔요. | Reverses the result. |
| and | 두 조건이 모두 참일 때 참이에요. | True when both conditions are true. |
| or | 적어도 한 조건이 참이면 참이에요. | True when at least one condition is true. |
| 예측 | 두 조건의 결과를 보고 최종 결과를 골라요. | Look at both conditions and predict the result. |
| 결과 | 첫 조건: {left}, 둘째 조건: {right}, 결과: {result} | First: {left}, second: {right}, result: {result} |
| 참 / 거짓 | 참 / 거짓 | True / False |

## 검증과 열린 질문

T51은 저장·표현식과 1~5단원 실행 프레임 fixture 회귀, T52는 UI·세 퍼즐·탐색·예측을 검증한다. 구현·실제 탐색·브라우저 검증은 아직 하지 않았다. 열린 질문: 네 조합 예측을 별도 선택 도전으로 둘지 6단원 내 선택 활동으로 둘지, A=0의 추상성이 대상 학습자에게 적절한지, 상한 4가 조작 부담 없이 충분히 명확한지 QC에서 확인한다.
