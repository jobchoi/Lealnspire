# 8단원 반환값 — 함수가 값을 돌려줌 [제안·잠정]

> 기획: GPT 독립 기획안(2026-11-26, 읽기 전용, 원문 `~/project/_progress/logs/unit8-gpt-plan.md`) → Claude 검토·확정(세 퍼즐 경로 직접 추적). 근거: ROADMAP 라운드 3 반환값 행("화면에 보여 주면 반환한 것", "return 뒤에도 실행한다" 오해).

## 1. 배울 것

- 함수가 계산한 값을 `return`으로 **돌려주고**, 부른 쪽(repeat 횟수)이 그 값을 쓴다.
- `return`은 함수를 **바로 끝낸다**(뒤의 블록은 이번 호출에서 실행 안 됨).
- 센서가 보여 주는 숫자(관찰)와 돌려받은 값(전달)은 다르다 — 돌려받으려면 return이 실행돼야 한다.

## 2. 의미 (Model)

- **숫자 센서** `앞 칸 수`: 바라보는 방향으로 벽(또는 맵 끝) 전까지 열린 칸 수(목표 칸 포함, 0~20). 로봇은 움직이지 않음. 이번 단원은 앞 방향만, return의 값 슬롯에서만 사용.
- `return` 블록: 값 = 숫자 0~20 · A · ◆ · 앞 칸 수. 함수 몸체에서만(main 거부). 실행하면 현재 함수 전체 종료(반복 안에서도), 값을 호출자에게.
- repeat 횟수 원천에 **값 호출** `repeat [★(인자?)]` 추가: 진입 시 함수를 한 번 호출, 돌려받은 값으로 횟수 고정. return 없이 끝나면 새 결과 `missingReturn`(0으로 보정하지 않음, 원인 블록 = 그 repeat). 문장 호출(기존 `★()`)은 반환값을 버림.
- 실행기 중단 신호를 계속/반환(값)/중단(결과)로 분리. 호출·return·센서도 단계 예산에 포함, 기존 1000단계·반복 진입 제한 유지. 함수 몸체 호출 금지 유지.
- 프레임: 호출 순번·입력값·return 블록·반환값·그 값을 쓴 repeat ID. 블록 수: return·값 호출 repeat 각 1, 값 슬롯·정의 0.
- 저장: v2 유지(6·7단원과 같은 방침), 새 필드 검증, 8단원 스테이지는 `returns: true`, 허용 안 된 스테이지는 그 코드만 비움.

- **증명(GPT 독립 Python + 논리)**: 이 팔레트에서 return을 빼면 맵마다 달라지는 입력이 없다(A 시작 값 같음, if·while·센서 대입 없음) → 어떤 프로그램도 두 맵에 같은 이동열을 보냄. 모든 공통 F/L/R 이동열의 상태 전수 탐색(u8-1 결합 상태 35, u8-2 35, u8-3 59)에서 동시 성공 없음 → **상한과 무관하게** return 없이 불가. T63에서 TypeScript 테스트로 옮김.
- **정직한 한계**: if·while을 허용하면 u8-1은 `while 앞 열림 [F], L, F`(4블록)로 풀림. 센서 값을 A에 직접 넣는 기능을 추가하면 증명이 깨짐 → 8단원 팔레트 제한은 설계 조건.

## 4. 화면

- 함수 카드에 입력 홈 ◆(왼쪽)과 출력 홈 ↩(오른쪽)을 다른 모양으로. return 타일 `↩ 앞 칸 수`.
- 실행 중: `◆1 → ★ → ↩4 → repeat ×4`처럼 전달을 표시, return 뒤 블록은 "이번 호출에서 실행 안 함"으로 흐리게(색만으로 구분 금지). 센서 관찰 숫자(맵 위)와 돌려받은 값(repeat 옆)은 모양·위치·라벨로 구분.
- missingReturn 실패 문구: ko "함수가 값을 돌려주지 않았어요. return이 실행됐나요?", en "The function didn't return a value. Did return run?"

## 5. T63 구현 기록 (Codex, 2026-11-26) [제안·잠정]

Model·v2 검증·편집·화면·세 퍼즐을 연결했다. `return.value.kind`는 number/A/param/ahead이고 `repeat.countCall`은 fn과 선택 인자를 가진다. 숫자/A/◆/함수별 값 호출을 허용 문맥에 맞게 순환하며 return은 함수 안에서만 추가한다. 값 호출 인자도 숫자 ±/A로 편집한다. 함수 입력 끄기는 해당 함수의 return ◆를 숫자 0으로 바꾸고 main 중첩 값 호출의 인자를 제거한다. 다시 켜면 기본 숫자 2를 넣는다. 삭제는 해당 함수를 값으로 부르는 repeat까지 제거한다. 문서 단위 되돌리기에 포함된다.

계속·반환·실행 중단 신호를 분리했다. 반환은 중첩 반복을 빠져나와 함수를 끝내고, 문장 호출은 값을 버린다. 값 호출에서 return 없이 끝나면 소비 repeat가 missingReturn의 원인이다. 호출·return·센서는 8단원 단계 예산에 각각 포함되며 기존 단원의 프레임은 보존한다. 센서 관찰 숫자는 맵 위 점선 표식, 반환값은 출력 홈과 repeat 옆의 사각 테두리 ↩로 구분한다. 함수 입력 홈은 왼쪽 ◆, 출력 홈은 오른쪽 ↩이며 미실행 타일은 점선·⊘·흐리기와 안내를 함께 사용한다.

전수 탐색은 두 맵의 위치·방향을 결합하고 목표·충돌은 흡수 상태로 둔다(실제 실행기도 그 순간 멈춤). 각 상태에서 모든 F/L/R 간선을 탐색하므로 길이 제한 없는 모든 공통 이동열을 포함한다. 상태 수를 35/35/59로 단언하고 동시 목표 상태가 없음을 검사한다. return이 없으면 A 시작 값 1이 같고 if/while·센서 직접 대입이 없어 모든 입력·변수·반복·문장 호출이 맵과 무관한 동일 이동열을 만든다. 반환 없는 값 호출은 missingReturn으로 중단하므로 맵 입력을 만들 수 없다. 열린 두 보드에서 64개 return 없는 프로그램의 전체 실행열 표본도 비교한다. 목표·충돌이 한쪽을 일찍 멈추는 차이는 흡수 상태 전수 탐색에서 처리한다.
