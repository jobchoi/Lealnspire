## 2. GPT 기획 원문

T84는 **학습 기록 기반 → 학습자 화면 → 관리자 화면 → 프로젝트 기록 → 서버 시험** 순서를 권합니다. 먼저 기록의 의미를 고정해야 두 대시보드가 같은 사실을 보여 줄 수 있습니다.

사용자가 정한 진행 방향과 순위표·공유 제외는 확정으로 취급하고, 아래 구체 수치·화면·정책은 모두 **제안**입니다. 이번 기획은 요청한 6~10세를 기준으로 작성했습니다. 다만 기존 게임 기획의 대상 연령 문구와는 차이가 있어, 추후 문서 정합성 정리가 필요합니다.

**1. 기록할 학습 이벤트와 질문**

‘방문’은 퍼즐에 들어왔다 나갈 때까지, ‘시도’는 실행 또는 첫 한 단계 실행으로 새 실행을 시작할 때로 정의합니다. 한 단계 버튼을 여러 번 눌러도 한 시도입니다. 같은 코드를 다시 실행하면 별도 시도지만, 코드 수정 여부를 함께 남깁니다.

| 기록 이벤트 | 주요 기록 내용 | 대시보드가 답하는 질문 |
|---|---|---|
| 퍼즐 방문·종료 | 단원·퍼즐·활동 종류, 방문 식별자, 종료 사유 | 어디까지 했고, 무엇을 하다 멈췄나? |
| 시도 시작 | 시도 식별자, 코드 개정 번호, 자동/한 단계 시작, 직전 시도 연결 | 몇 번 실행했나? 코드를 바꿔 다시 해 보았나? |
| 실행 결과 계산 | 전체 결과, 변형별 결과, 첫 실패 변형 | 같은 코드가 모든 맵을 통과했나? |
| 결과 도달·실행 중단 | 결과까지 재생했는지, 초기화·재실행·이탈 여부 | 결과를 확인했나, 도중에 떠났나? |
| 실패 정보 | 실패 종류, 원인 블록 종류·경로, 호출 문맥 | 어떤 실행 규칙에서 반복해서 막히나? |
| 코드 변경 요약 | 변경 횟수, 개정 번호, 블록 종류별 수, 직전 실행 코드와의 차이 여부 | 실패 뒤 실제로 수정했나? |
| 고치기·실패 뒤 재시도 | 고치기 버튼 사용, 일반 편집 경로, 이전 실패 시도 연결 | 실패를 보고 고쳐 성공하는 흐름이 있었나? |
| 되돌리기 | 사용 횟수, 코드 개정 번호 | 편집 실수를 복구했나? |
| 힌트 단계 공개 | 1·2단계, 방문 내 최초 공개, 연결할 다음 시도 | 어느 퍼즐에서 어느 단계 도움을 요청했나? |
| 시범 이용 | 시범 종류, 시작·끝 컷 도달·중도 종료 | 개념 시범을 열었고 마지막까지 진행했나? |
| 시간 구간 | 활동 추정 시간, 재생 시간, 시범 시간, 제외된 비활동 시간 | 풀이와 도움 확인에 각각 얼마나 머물렀나? |
| 완료 확정 | 최초/재완료, 별, 평가 기준 버전 | 무엇을 완료했고, 당시 어떤 기준으로 평가했나? |
| 다시 보기 선택·해제 | 퍼즐, 아이의 직접 선택 | 아이가 무엇을 다시 해 보고 싶어 하나? |

실패 종류는 현재 실행기가 제공하는 **충돌, 미도달, 단계 상한, 변수 범위 초과, 반환 누락, 리스트 번호 범위 초과, 비교 횟수 초과**를 그대로 구분합니다. 이를 ‘조건문을 이해하지 못함’ 같은 능력 판단으로 바꾸지 않습니다.

현재 실행기는 결과를 먼저 계산하고 화면에서 재생합니다. 따라서 계산상 성공이어도 재생 도중 나갔다면 ‘완료 확정’으로 기록하지 않습니다. 기존의 **성공 마지막 프레임에서 완료 저장**하는 계약을 유지합니다.

추가 원칙은 다음과 같습니다.

- 블록 수는 현재 계산처럼 본문과 모든 함수 몸체를 포함합니다. 실행된 명령 수와 별도 항목입니다.
- 힌트를 다시 열었다는 이유만으로 도움받은 시도 수를 늘리지 않습니다.
- 시범의 마지막 컷 도달은 ‘이해 완료’를 뜻하지 않습니다.
- 예측·보너스·시범은 정규 퍼즐 진행과 구분합니다. 시범 내부 실행이 정규 시도로 집계되지 않게 합니다.
- 매 클릭·매 프레임·마우스 이동은 저장하지 않습니다. 코드 편집도 클릭 로그 대신 변경 요약으로 모읍니다.

**2. 로컬 1단계 데이터 구조**

저장 문서는 **진행 3판**으로 올리고, 증가하는 상세 이력은 별도 문서로 분리하는 안을 권합니다. 저장소 접근은 계속 `ProgressRepository` 한곳에서만 담당합니다.

| 문서 | 제안 구조와 역할 |
|---|---|
| 진행 3판 | 저장 버전, 기기 내 익명 학습자 식별자, 기존 퍼즐별 완료·최고 별·마지막 코드, 히스토리 기록 시작일 |
| 학습 이력 1판 | 기록 규격 버전, 방문 목록, 시도 목록, 도움·수정 이벤트, 누적 요약, 정리 기준일 |
| 설정 | 기존 언어·시범 확인 설정 유지. 관리자 잠금 설정을 추가하면 설정 버전도 올림 |

이벤트의 공통 봉투에는 다음을 둡니다.

- 고유 이벤트 식별자와 기기 내 증가 순번
- 익명 학습자·기기·방문·시도 식별자
- 활동 종류와 활동 식별자, 단원 번호
- 기록일과 방문 시작부터의 경과 시간
- 앱·학습 콘텐츠·평가 기준의 버전
- 이벤트 종류와 종류별 제한된 자료

현재는 **브라우저 하나에 학습자 한 명**을 권합니다. 임의 식별자는 사람의 신원을 확인하는 계정이 아닙니다. 공용 기기에서 여러 아이가 함께 쓰면 기록이 섞인다는 안내가 필요합니다.

저장·이행 정책:

- 기존 1·2판에서 완료·별·마지막 코드를 이행합니다. 과거 시도·시간·힌트 사용은 만들지 않고 **“기록 시작 전: 상세 이력 없음”**으로 표시합니다.
- 상세 이력 손상이 기존 진행을 초기화하지 않도록 문서별로 검증합니다. 잘못된 이벤트만 제외하고 누락 여부를 표시합니다.
- 두 문서 저장은 원자적이지 않으므로, 완료 진행과 이력 중 하나만 저장되는 경우도 처리합니다. 대시보드 완료 수는 진행 문서를 기준으로 하고 이력 불일치는 미상으로 표시합니다.
- 지원하지 않는 미래 버전은 덮어쓰지 않고 해당 문서의 영구 저장을 멈춥니다.
- 기본적으로 과거 코드 전체와 실행 프레임은 저장하지 않습니다. 마지막 코드만 기존대로 보존합니다. 따라서 1단계에서는 과거 풀이를 그대로 재생할 수 없습니다.

용량·보존의 잠정값:

| 항목 | 제안 상한·정책 |
|---|---|
| 상세 기록 | 최근 90일, 시도 2,000개, 이벤트 10,000개 중 먼저 도달한 한계 |
| 전체 앱 저장 예산 | 보존 중인 이전 진행 키까지 포함해 문자열 길이×2 기준 2메비바이트 |
| 정리 순서 | 오래된 종료 방문을 누적 요약으로 접기 → 해당 상세 이벤트 제거 |
| 유지할 내용 | 퍼즐별 누적 시도·완료·실패 종류·도움 사용·활동 시간, 기존 마지막 코드 |
| 저장 용량 오류 | 상세 기록을 추가 정리하고 한 번 재시도. 계속 실패하면 메모리 유지와 저장 상태 안내 |

이는 앱 자체 예산이며 브라우저의 저장 공간 보장은 아닙니다. 상세 기록과 누적 요약은 구간을 나눠 이중 집계를 방지하고, 화면에 **상세 기록 보존 기간**을 표시합니다.

개인정보는 이름·사진·생년월일·연락처·위치·자유 서술·기기 지문을 수집하지 않습니다. 시간은 초 단위 활동량과 날짜 중심으로 보관합니다. ‘전체 학습 기록 삭제’는 이전 진행 키와 새 진행·이력을 모두 지워 복원되지 않게 하고, 언어 설정은 유지합니다.

시간은 화면이 보이고 최근 60초 안에 조작이 있었던 구간을 활동으로 추정하되, 자동 재생 구간은 별도로 셉니다. 숨김·긴 비활동·시범 시간을 풀이 시간에 섞지 않습니다. 조용히 생각하는 시간은 빠질 수 있으므로 명칭도 **‘활동 추정 시간’**으로 합니다.

**3. 학습자 대시보드 화면안**

홈과 퍼즐 목록에 큰 그림 버튼 **‘내 배움’**을 둡니다. 긴 표 대신 큰 기호와 한 줄 문구로 구성합니다.

| 영역 | 화면 내용 | 행동 |
|---|---|---|
| 무엇을 해 봤나 | 12단원 개념 카드, 완료 퍼즐 수, 진행 중 표시 | 단원을 눌러 해당 퍼즐 보기 |
| 최근 해낸 것 | “반복으로 길을 만들었어요”, “고쳐서 도착했어요” 등 기록에 근거한 카드 | 해당 퍼즐 다시 열기 |
| 다시 볼 것 | 아이가 직접 담은 퍼즐, 최근 미완료 퍼즐 중 최대 3개 제안 | 다시 하기·목록에서 빼기 |
| 다음 한 걸음 | 현재 열린 첫 미완료 퍼즐 한 개 | 이어하기 |

예시 배치는 다음과 같습니다.

> **내 배움**  
> 지금까지 퍼즐 12개를 해냈어요  
>   
> **배워 본 도구**  
> 순서와 반복　조건　조건 반복　함수 …  
>   
> **최근 해낸 것**  
> 길을 고쳐서 도착했어요　[다시 해 보기]  
>   
> **다시 보고 싶어요**  
> 두 번 꺾는 길　[해 보기]  
>   
> [이어하기]　[퍼즐 목록]

‘배웠다’는 개념을 접하고 퍼즐을 완료했다는 의미로 제한합니다. 숙달 판정은 하지 않습니다. 실패 횟수·힌트 사용량·시간 비교는 아이 화면에 노출하지 않으며, 재도전과 도움 요청 때문에 보상이 줄어들지 않게 합니다.

**4. 관리자 대시보드와 접근 방식**

로컬 단계에서는 **이 브라우저의 학습자 한 명**을 보는 화면입니다. 반 전체 통계는 서버 단계까지 보류합니다.

| 화면 영역 | 표시 내용 |
|---|---|
| 요약 | 정규 45개 중 완료 수, 최근 활동일, 기록 범위·저장 상태 |
| 단원별 진행 | 단원별 완료/전체, 진행 중 퍼즐, 활동 추정 시간 |
| 살펴볼 퍼즐 | 최근 연속 실패, 같은 실패 종류 반복, 도움 후 미완료 |
| 도움 사용 | 힌트 1·2단계를 사용한 시도 수/전체 시도 수, 시범 이용 |
| 퍼즐 상세 | 방문 → 실행 → 실패 → 힌트/수정 → 재실행의 시간순 이력 |

‘막힌 곳’의 초기 제안 기준은 **최근 종료된 실행 3회 연속 실패**입니다. 중단한 실행은 실패로 세지 않습니다. 시간만으로 막힘을 판정하지 않으며, 화면에는 ‘살펴볼 퍼즐’이라고 표시합니다.

‘힌트 의존’은 단정적인 점수 대신 다음 사실을 보여 줍니다.

- 도움을 본 시도 수와 분모
- 힌트 단계별 사용
- 도움을 본 뒤 성공했는지
- 이후 다른 방문에서 도움 없이 성공한 기록이 있는지
- 표본이 적거나 과거 기록이 없으면 판단 보류

접근 방식은 **홈 정보 영역 → ‘교사·보호자’ → 성인이 설정한 숫자 암호**를 권합니다.

- 최초 설정은 별도 성인 안내와 확인 과정을 거칩니다.
- 게임 중에는 관리자 진입 버튼을 두지 않습니다.
- 잘못 입력하면 점진적인 재시도 대기 시간을 둡니다.
- 홈 복귀·화면 숨김·일정 시간 비활동 때 다시 잠급니다.
- 길게 누르기만으로 열리는 방식은 키보드 접근과 우발 진입 방지에 부족합니다.
- 분실 시 초기화는 기존 암호를 보여 주지 않고, 로컬 잠금의 한계를 안내한 별도 절차로 제공합니다.

이 잠금은 **아이의 실수 진입을 막는 장치**입니다. 같은 기기의 저장소를 직접 조작할 수 있는 사람에 대한 계정 권한 통제는 서버 단계에서 다룹니다.

로컬의 오래된 상세 이력을 이미 정리했다면 서버에서도 복원할 수 없습니다. 이전 자료는 ‘누적 요약’으로 올리고 실제 이벤트처럼 재생성하지 않습니다.

## T84-1·2 구현 기록 [제안·잠정]

- Model에만 이벤트 명세와 저장·집계 API를 추가했다. 실제 이벤트 수집은 T84-3에서 연결한다. 공통 봉투는 id/sequence/learnerId/deviceId/visitId/attemptId(실행 관련)/activityKind/activityId/unit/recordedAt/elapsedMs/appVersion/contentVersion/evaluationVersion이다. deviceId는 로컬 익명 learnerId와 같으며 기기 지문이 아니다.
- 이벤트: visitStarted/visitEnded, attemptStarted, executionCalculated, resultReached/executionInterrupted, codeChanged, fixRequested, undo, hintShown, demoStarted/demoEnded, completionConfirmed, reviewChanged, timeSegment. 실패 종류는 RunResult에서 직접 가져오고 변형별 결과·첫 실패·원인 블록 종류·경로·호출 ID를 제한된 자료로 남긴다. 과거 코드·실행 프레임·자유 서술은 저장하지 않는다.
- 진행 v3 예: `{"version":3,"learnerId":"local-example","historyStartedAt":"2026-11-28T00:00:00.000Z","pastDetailsUnavailable":true,"stages":{"1":{"completed":true,"bestStars":3,"lastProgram":{"main":[],"functions":[]}}}}`. v1·v2의 완료·별·코드를 이행하고 원본은 보존한다. 기존 사용자의 과거 시도·시간·힌트를 소급 생성하지 않는다.
- 이력 v1 예: `{"version":1,"nextSequence":2,"events":[{"id":"local-example:1","sequence":1,"learnerId":"local-example","deviceId":"local-example","visitId":"visit-1","activityKind":"puzzle","activityId":"1","unit":1,"recordedAt":"2026-11-28T00:00:00.000Z","elapsedMs":0,"appVersion":"1.20.0","contentVersion":"1","evaluationVersion":"1","type":"visitStarted","data":{}}],"rollups":[],"incomplete":false,"compactedAt":null}`.
- 시도 분모는 attemptStarted 기준이다. 계산상 실패라도 resultReached가 없으면 최근 종료 실패·실패 종류 빈도에 넣지 않는다. 중단 시도는 시도 수에만 남는다. 완료 수는 진행 문서가 기준이다. 힌트는 같은 방문에서 공개한 단계별로 이후 시작 시도에 연결한다. 같은 힌트를 반복해서 열어도 한 시도당 한 번이다.
- 활동 추정: 보이는 구간에서 마지막 조작 후 60초까지만 포함한다. 예: 120초 풀이 구간에서 최초 조작만 있으면 활동 60초·비활동 60초. 이어서 재생 10초·시범 10초·숨김 10초면 각각 재생 10초·시범 10초·총 비활동 70초다. timeSegment는 직전 구간 이후의 비중첩 구간이며 호출자가 표시 상태·마지막 조작 시점을 전달해야 한다. 겹친 구간의 중복 시간은 제외한다.
- 90일·2,000시도·10,000이벤트·2,097,152바이트 중 먼저 넘은 한계에서 오래된 종료 방문을 요약한다. 2MiB 예산에는 옛 진행 두 키와 설정도 포함한다. 요약한 방문의 상세는 제거하고 늦게 도착한 같은 방문의 이벤트는 거부한다. 최근 종료 결과 순번을 요약에 남겨 방문 간 순서가 보존된다. 열린 방문·원본·마지막 코드·요약만으로 예산을 넘는 경우 강제 손실 대신 저장 불가 상태로 메모리 유지한다. 저장 예외 때는 추가 정리 후 한 번만 재시도한다.
- 삭제는 네 학습 기록 키를 모두 시도하고 설정은 유지한다. 하나라도 실패하면 메모리 진행·이력을 초기화하지 않는 T72 계약을 유지한다. 미래 버전 키는 쓰지 않으며 이력 손상은 진행과 격리한다. 상세와 요약의 범위를 함께 반환하며 중복 방문은 합산하지 않는다.
- 검증 결과는 작업 종료 보고에 기록한다. 화면·실제 이벤트 연결·E2E 변경·서버·새 라이브러리 API 사용은 이번 범위에 없다.
- 구현 검증(2026-11-28, Codex): 신규 학습 기록 테스트 20개 통과. `npm run lint`, `npm run typecheck`, 별도 `npm run build`, `git diff --check` 통과. `npm run verify`는 4회 실행했으나 모두 기존 Controller 테스트 두 곳에서 실패했다(최종 425개 중 423 통과·2 실패). `src/controller/controllers.test.ts:49`는 v2 키 직접 조회로 `SyntaxError: "undefined" is not valid JSON`, `src/controller/flow.test.ts:47`은 모든 키를 같은 문자열로 처리하는 가짜 저장소 때문에 이전 진행 복원 기대값 불일치다. 지시서 밖 두 테스트의 v3·분리 저장 계약 갱신은 사용자 범위 승인 대기이며 Controller 구현은 수정하지 않았다. 따라서 **verify 3회 연속 통과 조건은 미충족**이다. 화면 변경이 없어 E2E는 실행하지 않았다.
