**가. T84-6 — 완료 도장과 선택 도전**

**현재 구현에서 바뀌는 기준**

[게임 컨트롤러](/home/jobchoi/project/Lealnspire/src/controller/GameController.ts)는 현재 변형 맵이 있으면 성공 시 별 3개를 주고, 그렇지 않으면 전체 블록 수와 `starBlocks`로 1~3개를 계산합니다. 따라서 현재 1단원·보너스와 2~12단원의 별 의미가 다릅니다.

새 기준은 다음과 같습니다.

| 구분 | 의미 | 진행에 미치는 영향 |
|---|---|---|
| 완료 도장 | 해당 퍼즐의 모든 필수 맵을 통과함 | 다음 퍼즐·단원 개방과 완주에 사용 |
| 선택 도전 스티커 | 공개된 추가 목표를 달성함 | 개방·완주 조건에 사용하지 않음 |
| 기존 별 | 이전 평가 기준으로 얻었던 기록 | 과거 기록으로만 보존 |

시간·실패·힌트·시범 이용은 어느 보상에서도 감점 조건으로 사용하지 않습니다.

**완료 도장 모양과 의미**

- **둥근 도장 안에 로봇과 큰 체크 표시**, 옆에 “해냈어요”를 표시합니다.
- 색 외에도 체크와 외곽선으로 완료를 구분합니다. 세 월드에서 모양과 의미는 같습니다.
- 미완료 카드는 기존 번호·잠금 상태만 보여 줍니다. 빈 도장이나 별 세 칸으로 부족함을 표현하지 않습니다.
- 보너스에도 같은 도장을 주되 “보너스” 구분을 유지합니다.
- 도장은 “이 퍼즐을 통과했다”는 뜻이며, 개념 숙달이나 도움 없이 해결했다는 뜻은 아닙니다.
- 기존 `completed: true`는 그대로 완료 도장으로 표시합니다. 완료 날짜가 없으면 만들지 않습니다.

**선택 도전의 종류와 배치 원칙**

도전은 다음 조건을 모두 만족하는 곳에 둡니다.

1. 기본 통과와 다른 탐색 목표가 있다.
2. 현재 팔레트·편집 상한 안에서 달성할 수 있다.
3. 달성 예제와 미달성 성공 예제를 모두 만들 수 있다.
4. 이름 변경·빈 블록·실행되지 않는 코드 추가로 달성되지 않는다.
5. 아이에게 목표를 한 문장과 그림으로 설명할 수 있다.

우선 배치안은 **47개 중 7개**입니다. 아래 목록은 코드 검토에 따른 후보이며, 실제 실행 시험을 통과해야 최종 배치합니다.

**도전 달성 판정**

공통 규칙은 다음과 같습니다.

- 퍼즐은 기존처럼 **모든 변형 성공 후 마지막 재생 프레임에 도달했을 때** 완료·도전을 확정합니다. 계산만 끝내고 이탈한 실행에는 주지 않습니다.
- 첫 성공에서도 조건을 충족하면 도장과 스티커를 함께 줍니다. 도전을 미리 켜야 한다는 조건은 두지 않습니다.
- 실패·중단·재실행으로 이미 얻은 도장과 스티커를 회수하지 않습니다.
- 같은 도전·규칙 버전의 달성 이벤트는 한 번만 기록합니다.
- 시범·예측 실행은 퍼즐 도전의 증거가 아닙니다.

종류별 판정은 다음을 권합니다.

| 종류 | 판정 규칙 |
|---|---|
| 더 짧게 | 현재 `FunctionProgram.count()` 기준 재사용. 본문·중첩 몸체·양쪽 분기·모든 함수 몸체를 포함하고 반복 횟수는 곱하지 않음 |
| 다른 쪽으로 회전 | 성공 경로에서 실제 실행한 회전만 조사. 오른쪽만 사용한 성공과 왼쪽만 사용한 성공을 각각 확보 |
| 앞·뒤 탐색 | 실제 비교를 수행한 순회의 방향을 기록. 방향만 바꿔 놓고 실행되지 않은 순회는 불인정 |
| 두 가지 길 찾기 | 성공 경로에서 실제 실행된 ‘반복＋조건문’과 ‘조건 반복’ 전략을 각각 확인. 두 도구를 코드에 넣었다는 사실만으로 인정하지 않음 |

“다른 코드 두 개”라는 일반 판정은 권하지 않습니다. 블록 식별자 변경이나 불필요한 회전 추가도 다른 코드가 되기 때문입니다. **퍼즐별로 공개한 두 전략의 증거**를 판정하는 편이 명확합니다.

`u12-1`은 두 전략의 인정 예제와 혼합·빈 몸체·미실행 코드의 반례를 먼저 시험해야 합니다. 안정적인 판정이 어렵다면 이 도전은 보류하고 6개로 출시합니다.

**기존 별 보존과 평가 기준 이행**

- 기존 `bestStars`는 값을 유지하고 새 플레이부터 갱신을 멈춥니다.
- 평가 기준은 기존 `1`, 새 완료·도전 기준 `2`로 구분합니다. 도전에는 별도의 규칙 버전도 둡니다.
- 기존 기준 1 안에서도 1단원·보너스는 길이 평가, 2~12단원은 성공 표시였다는 설명을 보존합니다.
- 기존 별 3개를 새 도전 달성으로 바꾸지 않습니다. 마지막 저장 코드가 당시 최고 별을 얻은 코드라는 보장이 없습니다.
- 기존 완료는 도장으로 이어받되, 새 도전은 “기록 없음”에서 시작합니다.
- 과거 이력의 별·평가 버전은 수정하지 않습니다.

아이의 기본 화면에는 이전 별을 반복 노출하지 않고, 내 배움의 접힌 **“이전 별 기록”**에서 확인하게 합니다. “예전 방식으로 받은 별이에요. 지금은 도장과 도전으로 보여 줘요”라고 안내합니다.

- 옛 앱으로 돌아가 저장하면 새 필드가 유실될 수 있습니다.

따라서 두 선택지가 있습니다.

1. **규칙 준수 기본안:** 진행 4판으로 이행하고 3판 원본 보존.
2. **사용자 선호안:** 진행 3판 유지, 확장 형식 버전 추가. 이 경우 저장 규칙의 명시적 예외와 옛 앱 재저장 시 유실 정책을 결정해야 함.

어느 쪽이든 읽기·정규화·복사·편집 저장·완료 저장 전체에서 추가 필드를 보존해야 합니다.

이력도 현재 `completionConfirmed`가 별 1~3개를 필수로 요구합니다. 새 완료에 가짜 별 3개를 넣지 말고, **이력 2판**에서 별 없는 완료와 `challengeAchieved`를 지원하는 안을 권합니다. 과거 별 필드는 이전 이벤트에만 남깁니다.

**검증과 위험**

단위 시험:

- 완료·개방·정규 45개 완주가 도전과 무관함.
- 4블록 경계·중첩·분기·함수 몸체의 개수 계산.
- 7개 후보별 달성 예제·미달성 성공 예제·실패 예제.
- 모든 변형 통과, 실제 실행 전략, 재생 중 이탈, 중복 확정 방지.
- 힌트·실패·시간·속도를 달리해도 같은 코드의 도전 판정이 같음.
- 기존 별 동결, 과거 이벤트 보존, 추가 필드 왕복, 손상 격리·저장 실패·전체 삭제.

종단 간 시험:

- 긴 코드 성공 → 완료 도장 → 짧게 수정 → 도전 달성 → 새로고침 복원.
- 두 전략을 서로 다른 방문에서 실행 → 두 번째 전략에서만 달성.
- 결과 계산 뒤 이탈하면 달성되지 않음.
- 도전 없이 12단원 완주 가능.
- 기존 사용자 이행·내 배움·관리자 표시 일치.
- 세 월드·한국어/영어·키보드·작은 화면·동작 줄이기·스크린샷 육안 확인.

주요 위험은 도전이 사실상 두 번째 필수 과제로 받아들여지는 것, 길이가 짧은 코드를 무조건 좋은 코드로 해석하는 것, 전략 판정의 오탐입니다. 도전은 완료 후 펼쳐 보이고, “짧은 표현도 찾아봤어요”처럼 한정된 의미로 설명해야 합니다.

**나. T84-7 — 퍼즐 밖에서 만드는 프로그램**

프로젝트는 정답이 정해진 문제나 풀이 모음이 아니라, **아이가 실행 결과를 정하고 맵·코드를 바꾸며 저장하는 독립 활동**으로 설계합니다.

**1단계 범위 비교**

구현 규모는 기존 편집기·보드 재사용 정도를 기준으로 한 상대 평가입니다.

| 안 | 아이가 만드는 것 | 학습 가치 | 구현 규모 |
|---|---|---|---|
| **① 내 로봇 작업실 — 권장** | 빈 격자에 벽·시작 위치를 놓고 로봇 프로그램 제작 | 목표 설정, 순서·반복, 예상과 실행 비교, 스스로 고치기 | 중간. 맵 편집·프로젝트 저장·자유 실행 규칙 필요 |
| ② 그림 그리는 로봇 | 펜 올리기·내리기·색과 이동으로 무늬 제작 | 반복 패턴, 도형, 절차를 작품으로 표현 | 중간~큼. 새 명령·그리기 상태·화면·재생 추적 필요 |
| ③ 버튼으로 움직이는 미니 프로그램 | 버튼을 누르면 이동·색·장면 등이 바뀌는 작품 | 사건과 반응, 상태, 상호작용 설계 | 큼. 현재의 고정 신호열과 다른 입력·실행 수명 설계 필요 |

①은 아이가 맵과 동작을 모두 정하므로 충분히 프로그램 개발 활동입니다. 정해진 도착 문제를 추가로 만드는 화면에 머물지 않도록 **목적지 없는 자유 실행**을 기본으로 권합니다.

**권장안의 첫 범위**

- 고정 **6×6 격자**, 바닥·벽·로봇 시작 칸·시작 방향.
- 명령은 앞으로·좌회전·우회전·횟수 반복부터 시작.
- 실행·한 단계·정지·처음으로·속도 조절.
- 글자 입력 없이도 기본 이름으로 만들 수 있음.
- 맵의 모든 칸을 벽으로 만들거나 로봇 시작 칸을 지우는 조작은 차단.
- 스테이지 잠금과 무관하게 홈에서 진입. 짧은 조작 안내는 다시 볼 수 있게 제공.
- 공유·공개·순위·다른 사람 작품 탐색은 첫 출시 범위에서 제외.

현재 편집기는 전역 10블록 상한이 있으므로 **첫 출시에서는 10블록을 유지**합니다. 자유 제작에 충분한지는 후속 관찰 대상으로 두고, 상한을 늘리려면 편집기·검증기·저장 검증을 함께 분리해야 합니다.

현재 실행기는 목적지 도착 즉시 성공하고 목적지를 가진 맵을 전제로 합니다. 임의의 숨은 목적지를 넣어 재사용하면 자유 프로그램이 중간에 끝날 수 있습니다. 따라서 다음처럼 실행 계약을 분리합니다.

- 퍼즐: 현재 도착·성공 규칙 유지.
- 프로젝트: 목적지 없이 프로그램 끝까지 실행.
- 코드 종료는 “실행이 끝났어요”, 충돌은 “여기에서 멈췄어요”.
- 정답·완료 도장·별은 없음.
- 1,000단계·반복 진입 1,000회 안전장치 유지.
- 실행할 때마다 시작 위치·방향으로 복원하며, 결과 위치가 저장된 시작 위치를 바꾸지 않음.

**화면 흐름**

1. **홈 → 내 작품**  
   저장된 작품 카드와 ‘새로 만들기’를 표시합니다. 카드에는 이름·수정일·코드로 그린 맵 미리보기를 사용합니다.

2. **새 작품 → 이름과 맵 만들기**  
   기본 이름은 “내 로봇 1”. “작품 이름을 지어요. 진짜 이름이나 학교 이름은 쓰지 않아도 돼요”라고 짧게 안내합니다.

3. **맵 만들기 ↔ 코드 만들기**  
   두 탭으로 이동하되 맵·코드를 함께 유지합니다. 실행 중에는 편집을 잠급니다.

4. **실행 → 관찰 → 수정**  
   결과 모달로 흐름을 끊기보다 보드 근처에 실행 상태를 표시합니다.

5. **저장하기 → 저장 완료 확인**  
   저장에 성공한 경우에만 “저장했어요”라고 표시합니다.

6. **내 작품으로 이동**  
   저장되지 않은 변경이 있으면 ‘저장하고 나가기 / 저장하지 않고 나가기 / 계속 만들기’를 제시합니다.

퍼즐 화면의 자동 코드 저장을 그대로 가져오지 않고, 프로젝트는 **명시적 저장**을 중심으로 합니다.

**프로젝트와 저장본의 단위**

| 단위 | 제안 |
|---|---|
| 프로젝트 식별자 | 앱이 생성하는 변경 불가능한 임의 식별자 |
| 작품 이름 | 아이가 정하는 표시 이름. 중복 허용, 변경 가능 |
| 현재 작업본 | 편집 중 메모리 상태 |
| 명시적 저장본 | 저장 버튼으로 만든 맵＋시작 상태＋코드의 불변 묶음 |
| 저장본 식별자 | 프로젝트 안에서 고유한 식별자와 개정 순번 |
| 실행 기록 | 어떤 작업 개정 또는 저장본으로 실행했는지 참조 |

**아이는 이름을 짓고, 내부 식별자는 앱이 생성**하는 방식을 권합니다. 식별자를 아이가 입력하게 하면 이름 변경·중복·개인정보 입력이 저장 연결에 영향을 줍니다.

저장본은 최근 **5개**를 보관하는 초안을 권합니다. 저장한 내용과 같으면 새 저장본을 만들지 않습니다. 예전 저장본을 열면 작업본으로 복사하고, 다시 저장할 때 새 저장본을 만듭니다.

이름은 최대 20자, 줄바꿈·제어 문자 제외, 일반 텍스트로만 표시합니다. 이름은 로컬 작품 문서에만 두고 학습 이벤트에는 복제하지 않습니다. 자동 개인정보 검출이 완전하다는 안내는 하지 않습니다.

**학습 이력 연결**

현재 이력의 활동 종류에는 프로젝트가 없고 단원 번호가 필수입니다. 프로젝트를 특정 단원의 퍼즐처럼 넣지 말고, **프로젝트 활동 분기와 단원 미소속 상태**를 명시적으로 추가해야 합니다.

| 이벤트 | 기록할 내용 |
|---|---|
| `projectCreated` | 프로젝트 식별자·작품 종류·형식 버전 |
| `projectOpened` | 프로젝트 식별자·선택한 저장본 식별자 |
| `projectEdited` | 작업 개정·맵/코드 변경 여부·변경 횟수 요약·블록 종류별 수 |
| `projectRunStarted` | 실행 식별자·작업 개정·연결 가능한 저장본 식별자 |
| `projectRunEnded` | 정상 종료·충돌·안전 상한·사용자 중단 |
| `projectSaved` | 저장에 성공한 저장본 식별자·개정 |
| `projectClosed` | 이탈 사유·미저장 변경 여부 |
| `projectDeleted` | 프로젝트 식별자 |

편집마다 이벤트를 쓰지 않고 실행·저장·이탈 시점에 요약합니다. 이벤트에는 이름·맵·코드·실행 프레임을 넣지 않습니다.

- 내 배움: “내 작품을 만들었어요”, “저장한 작품을 다시 고쳤어요”처럼 기록에 근거한 카드.
- 관리자: 프로젝트 활동·명시적 저장·재방문·활동 추정 시간을 퍼즐과 별도 표시.
- 퍼즐 완료율·실패 연속 횟수·도움 사용 비율에 프로젝트 실행을 섞지 않음.
- 실행 횟수나 편집량으로 창의성·실력을 점수화하지 않음.
- 저장은 됐지만 이벤트 저장이 실패하면 작품을 우선 보존하고 이력 누락을 표시.
- 프로젝트 삭제 뒤에는 이름·코드 참조 없이 “삭제된 작품”으로 처리.

**로컬 저장과 용량**

프로젝트 내용은 진행 문서에 통째로 넣지 않고 **별도 프로젝트 저장 문서 1판**으로 분리하는 안을 권합니다. 모든 저장 입출력은 기존 규칙대로 `ProgressRepository`를 통해 수행합니다.

- 프로젝트 문서: 식별자·이름·생성일·마지막 저장일·저장본 목록.
- 저장본: 형식 버전·실행 규칙 버전·맵·시작 상태·`ProgramDocument`.
- 첫 예산: **작품 20개, 작품당 저장본 5개, 프로젝트 전체 512키비바이트**.
- 기존 전체 앱 예산 **2메비바이트 안에 프로젝트도 포함**합니다. 별도 추가 예산으로 계산하지 않습니다.
- 그림 파일·실행 프레임·썸네일 이미지는 저장하지 않습니다.
- 오래된 상세 학습 이벤트를 먼저 요약하되, 명시적 작품 저장본을 조용히 삭제하지 않습니다.
- 한도 도달 시 작품·저장본 정리 화면을 제공하고, 삭제는 확인 후 실행합니다.
- 저장 실패 시 작업본은 메모리에 유지하고 “이 창을 닫으면 바뀐 내용이 사라질 수 있어요”라고 안내합니다.
- 기록 전체 삭제에는 프로젝트와 저장본도 포함하고, 언어 설정은 유지합니다.

6×6 맵과 10블록은 비교적 작은 자료지만, 위 수치는 **직렬화한 실제 문자열 길이×2로 측정하여 확정**해야 합니다. 옛 진행 원본과 이력이 이미 예산을 차지한 경우 새 작품 20개를 보장할 수는 없습니다.

**단계 분할과 완료 조건**

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 7-가 | 프로젝트 문서·자유 실행 모델 | 목적지 없이 종료, 충돌·중단·상한, 저장본 왕복·손상 격리. 기존 퍼즐 실행 결과 불변 |
| 7-나 | 내 작품·맵·코드 제작 화면 | 생성→맵 편집→코딩→실행→명시적 저장→재접속 복원 가능 |
| 7-다 | 저장본·용량·삭제 | 이전 저장본 열기·새 저장본 생성·중복 저장 방지·한도·실패·미저장 이탈 검증 |
| 7-라 | 이력·두 대시보드 연결 | 작품 이벤트와 저장 내용 일치, 퍼즐 집계 분리, 이력 정리 후 작품 보존 |
| 후속 | 조건·함수, 그림·이벤트 작품 | 첫 출시 사용 결과와 별도 범위 결정 후 진행 |

출시 완료에는 단위 시험 외에 **빈 맵에서 아이가 직접 작품을 만들고 저장한 뒤 다시 여는 종단 간 시나리오**가 필요합니다. 키보드 맵 편집, 작은 화면의 맵·실행 버튼 배치, 저장 실패와 전체 삭제도 포함합니다.

주요 위험은 자유 제작인데 표현할 수 있는 프로그램이 너무 작은 것, 맵 편집이 코딩보다 어려운 것, 명시적 저장을 잊는 것, 퍼즐용 실행·검증 규칙이 프로젝트에 남는 것입니다. 첫 범위를 작게 유지하되, 저장 상태를 항상 보이고 퍼즐·프로젝트의 실행 정책을 분리해야 합니다.

**사용자 결정이 필요한 항목**

| 항목 | 권장안 |
|---|---|
| 선택 도전 배치 | 위 7개 후보. 실행·반례 검증 실패 후보는 보류 |
| 도전 표시 | 완료 후 펼쳐 보기, 조건 충족 시 첫 성공에도 자동 인정 |
| 진행 저장 버전 | 기본은 4판. 3판 유지 시 저장 규칙 예외·롤백 정책 결정 |
| 프로젝트 첫 종류 | 내 맵＋코드의 로봇 작업실 |
| 첫 제작 범위 | 6×6·목적지 없음·기본 이동과 횟수 반복·10블록 |
| 이름과 식별자 | 이름은 아이가, 내부 식별자는 앱이 생성 |
| 저장 정책 | 명시적 저장·작품당 최근 5개 저장본 |
| 용량 초안 | 20작품·프로젝트 512키비바이트·전체 앱 2메비바이트 안 |
| 프로젝트 진입 | 퍼즐 완주와 무관하게 홈에서 제공 |

T84-6·7 읽기 전용 기획을 완료했습니다. 지정 문서·코드와 관리자 작업 트리를 확인했으며 **파일 수정·커밋·푸시·브랜치 변경은 없습니다.** 실행 방법은 해당 없고, 제안한 도전 예제의 실제 실행·단위 시험·종단 간 시험은 **미검증**입니다. 다음 작업은 범위 결정을 반영한 구현 지시서 작성입니다.

## T84-7 2차 기획 (GPT 읽기 전용, 사용자 결정 반영 — 권장: 상자 규칙 창고)

**권장안은 ‘상자 규칙 창고’입니다.** 아이가 세 더미의 시작 모습과 코드를 정해, 상자를 뒤집거나 분류하거나 원하는 상자를 찾아 꺼내는 프로그램을 만듭니다. 상자를 다루는 순서와 조건이 작품의 동작을 결정합니다.

[‘사용자 결정’ 표](/home/jobchoi/project/Lealnspire/docs/design/stars-and-projects.md)에 확정된 세 가지—프로그램 개발 활동, 논리·기본 자료구조 관점, 배운 단원까지 블록 개방—를 기준으로 삼았습니다. **아래 세부 내용과 수치는 모두 제안**입니다.

**1. 프로젝트 세계 후보**

| 세계 | 아이가 만들 수 있는 프로그램 예 3개 | 생각해 볼 개념 | 6~10세에게 보이는 모습 | 구현 규모 |
|---|---|---|---|---|
| **상자 규칙 창고 — 권장** | ① 한 더미를 다른 더미로 옮겨 순서 뒤집기 ② 맨 위 모양에 따라 두 더미로 분류하기 ③ 원하는 상자가 나올 때까지 임시 더미로 치우기 | 나중에 넣은 것을 먼저 꺼내는 스택, 맨 위 확인, 임시 저장, 조건·반복·종료 조건 | 입구가 위에만 있는 투명 상자통 세 개와 집게. 맨 위 상자에 손잡이 표시 | **중간~큼.** 스택 상태·새 명령·조건·실행 추적 필요. 격자·경로 편집은 불필요 |
| **차례대로 출발하는 기차** | ① 대기한 순서대로 칸 내보내기 ② 앞 칸의 모양에 따라 서로 다른 출구로 보내기 ③ 지정한 모양이 나올 때까지 차례로 내보내기 | 먼저 들어온 것을 먼저 꺼내는 큐, 앞·뒤의 구분, 처리 대기열 | 뒤에서만 연결하고 앞에서만 출발하는 기차. 앞·뒤 화살표를 고정 표시 | **중간~큼.** 큐 조작·입출구·대기열 추적 필요. 자유로운 칸 재배열은 제외 |
| **규칙 분류 공장** | ① 별 상자와 나머지 상자 나누기 ② 두 조건을 모두 만족하는 상자만 보관하기 ③ 불필요한 상자를 옆으로 보내고 원하는 상자 찾기 | 분기, 논리 결합, 입력 순회, 분류 결과의 순서 | 한 번에 한 상자씩 나오는 벨트와 분류 바구니 | **큼.** 벨트·집게·출력 더미의 실행 순서와 상태를 함께 설명해야 함 |

창고는 **같은 상자도 쌓는 순서에 따라 다음 동작이 달라진다**는 점이 직접 보입니다. 분류 공장은 창고의 선택 시작 장면으로 일부 흡수할 수 있습니다. 기차의 큐는 후속 세계로 두면 스택과 꺼내는 순서를 비교하기 좋습니다.

**2. 권장안: 상자 규칙 창고**

첫 범위는 **더미 세 개, 더미당 여섯 상자, 집게 한 개**를 권합니다. 더미는 잎·달·해 그림으로 구분하고, 변수 상자 이름인 ‘A’와 겹치지 않게 합니다.

아이는 실행 전에 각 더미에 상자를 쌓아 시작 상태를 만듭니다. 상자는 별·원·세모처럼 색 없이도 구분되는 그림을 가집니다. 집게는 한 번에 하나만 들며, 실행 중에는 코드만 상태를 바꿉니다.

| 새 명령·조건·값 | 의미 |
|---|---|
| `잎 더미에서 집기` | 맨 위 상자를 더미에서 빼 집게에 듦 |
| `달 더미에 놓기` | 집게의 상자를 해당 더미 맨 위에 놓음 |
| `잎 더미가 비었으면` | 상자가 없는지 확인 |
| `달 더미가 가득 찼으면` | 여섯 칸을 모두 사용했는지 확인 |
| `잎 더미 맨 위가 별이면` | 상자를 빼지 않고 맨 위 그림 확인 |
| `집게가 비었으면` / `든 상자가 별이면` | 집게 상태 확인 |
| `잎 더미의 상자 수` | 반복 횟수·반환값으로 쓸 수 있는 수 |

**맨 위 확인은 더미를 바꾸지 않습니다.** 빈 더미에서 ‘맨 위가 별인가’를 확인하면 거짓입니다. 실제로 꺼내려 하면 오류가 납니다. 이 차이를 그림으로 보여 줍니다.

새로 배우는 것은 창고 조작이며, 제어 구조는 이미 배운 블록을 사용합니다.

| 기존 블록 | 창고에서의 결합 예 |
|---|---|
| 횟수 반복 | 세 번 `[잎에서 집기 → 달에 놓기]` |
| 조건문 | 든 상자가 별이면 달에, 아니면 해에 놓기 |
| 조건 반복 | 잎 더미에 상자가 있는 동안 하나씩 옮기기 |
| 함수 | ‘하나 옮기기’를 이름 붙인 묶음으로 만들기 |
| 변수 A | 옮길 때마다 A를 1 늘려 처리 개수 세기 |
| 논리 | 잎에 상자가 **있고**, 달이 가득 차지 않았을 때 옮기기 |
| 매개변수 | ‘여러 개 옮기기’에 개수를 전달 |
| 반환값 | 함수가 더미의 상자 수를 돌려주고 그 수만큼 반복 |
| 리스트 | 주문 리스트 `[2, 1, 3]`을 순회하며 현재 값만큼 옮기기 |
| 탐색 | 주문에서 원하는 수를 찾고 순회를 멈추기 |

현재 리스트는 **읽기 전용 숫자 리스트**입니다. 따라서 첫 출시에서도 주문 리스트와 실행 중 바뀌는 상자 더미를 구분합니다. 리스트 추가·삭제를 스택 조작으로 몰래 확장하지 않습니다.

또한 **수치 매개변수와 반환값을 상자 그림 값으로 확장하지 않습니다.** 그림은 조건으로 비교하고, 개수는 숫자로 다룹니다.

**단원별 개방**

저장소의 실제 구성은 1단원 순서·반복, 2단원 조건문부터 12단원 종합입니다. **해당 단원의 정규 퍼즐을 모두 완료하면 그 행의 기능을 추가 개방**합니다.

| 완료한 단원 | 추가로 열리는 프로젝트 기능 |
|---|---|
| 아직 없음 | 시작 상태 만들기·조작 시범 보기. 코드 제작 개방 전 안내 |
| 1. 순서·반복 | 집기·놓기, 숫자 횟수 반복 |
| 2. 조건문 | 조건문·아니면, 빈 더미·가득 참·맨 위 그림·집게 조건 |
| 3. 조건 반복 | 창고 조건을 사용하는 조건 반복. 논리 결합 없이 ‘상자가 있는 동안’도 제공 |
| 4. 함수 | 함수 정의·호출. 기존처럼 최대 두 함수, 함수 간 호출·재귀 제외 |
| 5. 변수 A | A 설정·증감, A만큼 반복 |
| 6. 논리 | 그리고·또는·아니다로 창고 조건 결합 |
| 7. 매개변수 | 수치 매개변수 전달·매개변수만큼 반복 |
| 8. 반환값 | 숫자·A·매개변수·더미 개수 반환, 반환값만큼 반복 |
| 9. 이벤트 | 그림 신호 처리기, 아이가 미리 정한 유한 신호열 |
| 10. 리스트 | 주문 리스트 작성, 앞에서부터 순회, 현재 값·A번 값·길이로 반복 |
| 11. 탐색 | 주문의 목표 수 비교, 뒤에서부터 순회, 순회 멈추기 |
| 12. 종합 | 새 문법 없이 전체 조합 |

더미 개수의 수치 사용은 변수 단원부터, 반환은 반환값 단원부터 제공합니다. 리스트는 0부터 번호를 매기고, 기존 값 범위 0~10·길이 최대 다섯을 유지하되 **빈 리스트도 정상 입력으로 허용하는 확장**을 제안합니다.

프로젝트에는 이동 센서가 없으므로 기존 이동·벽 검사 블록은 넣지 않습니다. 대신 배운 제어 구조를 창고 조건과 결합합니다. 탐색 퍼즐의 ‘전진은 최상위에서만’ 같은 우회 방지 규칙도 가져오지 않습니다.

개방 여부는 팔레트뿐 아니라 **편집·저장본 읽기·실행에서 같은 기준으로 검사**해야 합니다. 진행 기록이 지워져 고급 저장본이 잠기면 원본은 보존하고, 필요한 단원을 안내하며 실행을 막습니다. 코드를 자동 삭제하지 않습니다.

**3. 자유 제작의 목표와 결과**

목표는 시작할 때 선택하거나 나중에 바꿀 수 있으며, 없어도 실행할 수 있습니다.

| 방식 | 아이의 선택 예 |
|---|---|
| 내 목표 카드 | “순서를 뒤집고 싶어요”, “모양끼리 모으고 싶어요”, “별을 꺼내고 싶어요” |
| 선택 미션 | “한 번 옮긴 뒤 순서를 살펴볼까?”, “다른 쌓기에서도 같은 코드가 움직일까?” |
| 직접 정하기 | 그림 기호를 고르거나 짧은 한 줄 입력. 입력은 선택 사항 |

목표 카드에는 정답 코드·필수 배치·통과 조건을 두지 않습니다. 선택 미션도 달성 배지나 완료율로 연결하지 않습니다.

실행 결과는 다음처럼 **관찰 사실**로 보여 줍니다.

- 시작 모습과 현재 모습을 나란히 비교.
- 집거나 놓은 상자와 실행 블록을 함께 강조.
- “잎 더미에서 별 상자를 꺼냈어요”처럼 마지막 동작 설명.
- 집기·놓기·조건 비교 횟수는 펼쳐 보는 관찰 정보로 제공.
- 마지막에 “내가 생각한 모습인가요?”와 ‘다시 고치기’ 제공.

아이가 ‘내 목표를 해냈어요’를 직접 표시할 수는 있지만, 이는 자기 기록입니다. 시스템의 정답 판정이나 개념 숙달 증거로 쓰지 않습니다.

**4. 실행 계약**

프로젝트 실행은 **퍼즐의 성공·도착 판정과 분리**합니다. 별도 프로젝트 실행 진입점과 결과 형식을 두고, 공통 제어 구조의 재사용은 기존 퍼즐 회귀 검증을 전제로 합니다.

| 항목 | 제안 계약 |
|---|---|
| 시작 | 매 실행마다 저장된 시작 더미·빈 집게·A=0에서 시작 |
| 종료 | 본문과 설정된 신호열 처리가 끝나면 “실행이 끝났어요” |
| 집게에 상자가 남음 | 정상 종료. “집게에 별 상자가 남아 있어요” 표시 |
| 재생 | 실행·한 단계·속도·정지·처음으로 제공 |
| 정지 | 마지막으로 재생한 상태를 남기고 “여기서 멈췄어요” |
| 다시 실행 | 항상 시작 상태로 초기화. 중단 상태 이어 실행은 첫 범위에서 제외 |
| 편집 | 실행 중 잠금. 종료 뒤 편집 가능, 다음 실행은 시작 상태부터 |
| 저장 | 실행 결과가 시작 상태를 덮어쓰지 않음 |

안전 상한은 **계산 단계 1,000회·반복 몸체 진입 1,000회**를 제안합니다. 집기·놓기·조건 검사·값 읽기·함수 호출·반환·리스트 방문·신호 처리도 비용을 명시합니다. 빈 반복이나 상태가 바뀌지 않는 조건 반복도 유한하게 멈춰야 합니다.

복합 조건은 기존처럼 양쪽을 평가하되 읽기는 상태를 바꾸지 않습니다. 비교 횟수는 실제 수행한 원자 비교 수로 표시합니다. 신호는 실행 전 최대 20개를 설정하고 순서대로 처리하며, 실행 중 외부 입력·신호 재생산은 제외합니다.

| 상황 | 아이에게 보이는 말 | 상태 처리 |
|---|---|---|
| 빈 더미에서 집기 | “잎 더미가 비어 있어요. 꺼낼 상자가 없어요.” | 해당 동작 전 상태로 멈춤 |
| 든 채 다시 집기 | “집게에 상자가 있어요. 먼저 내려놓아 주세요.” | 기존 상자 유지 |
| 빈 집게로 놓기 | “집게가 비어 있어요. 먼저 상자를 집어 주세요.” | 상태 유지 |
| 가득 찬 더미에 놓기 | “달 더미에는 자리가 없어요. 다른 더미에 놓아 볼까요?” | 집게의 상자 유지 |
| 안전 상한 | “동작이 아주 많이 이어져 잠깐 멈췄어요. 반복 조건을 살펴볼까요?” | 마지막 유효 상태 유지 |
| 없는 리스트 번호 | “번호 3인 칸이 없어요. 이 리스트의 길이는 3이에요.” | 원인 블록과 번호 강조 |

집기·놓기는 **전부 수행되거나 전혀 수행되지 않는 동작**입니다. 오류 때문에 상자가 사라지거나 복제되면 안 됩니다. 오류 프레임에는 원인 블록·함수 호출 문맥·더미 또는 집게를 함께 남깁니다.

**5. 저장 단위와 용량**

**프로젝트 문서 1판**을 진행·이력과 별도 키에 저장하고, 모든 저장 입출력은 기존 규칙대로 진행 저장소를 통합니다.

| 단위 | 저장 내용 |
|---|---|
| 프로젝트 | 앱이 만든 식별자, 아이가 지은 이름, 세계 종류, 생성·저장 시각 |
| 명시적 저장본 | 저장본 식별자·순번, 문서·실행 규칙 버전, 시작 더미, 코드·함수, 주문 리스트·목표 수, 신호열, 목표 카드 |
| 작업본 | 메모리의 현재 편집 내용·변경 순번 |
| 실행 연결 | 작업 순번, 정확히 일치할 경우 저장본 식별자 |

상자 개별 식별자는 시각 추적에만 사용하며 아이가 조건으로 비교하지 못하게 합니다. 실행 프레임과 결과 더미는 저장하지 않습니다.

- 이름은 아이가 정하고 중복을 허용합니다. 기본 이름 ‘내 창고 1’도 제공합니다.
- 이름 최대 20자, 선택 목표 문장 최대 40자. 일반 텍스트로만 표시합니다.
- “진짜 이름이나 학교 이름은 쓰지 않아도 돼요”를 입력 옆에 안내합니다.
- 이름·목표 문장을 학습 이벤트에 복제하지 않습니다.
- 저장 버튼으로 불변 저장본을 만듭니다. 내용이 같으면 새 저장본을 만들지 않습니다.
- 이전 저장본은 작업본으로 복사해 열고, 수정·저장하면 새 저장본이 됩니다.
- 미저장 이탈 시 ‘저장하고 나가기 / 저장하지 않고 나가기 / 계속 만들기’를 제공합니다.

용량 초안은 **20작품·작품당 저장본 5개·프로젝트 전체 512키비바이트**, 기존 전체 앱 예산 2메비바이트 안입니다. 실제 직렬화 용량과 보존 중인 옛 진행 원본까지 합산해 확정해야 하며, 20작품 저장을 보장하는 수치는 아닙니다.

여섯 번째 저장본을 만들 때는 지울 저장본을 아이가 선택하게 합니다. 명시적 저장본을 자동 삭제하지 않습니다. 저장 실패 시 이전 저장본과 작업본을 유지하고, 성공한 경우에만 “저장했어요”를 표시합니다.

프로젝트 삭제는 저장본까지, 기록 전체 삭제는 프로젝트까지 포함합니다. 언어 설정은 유지합니다.

**6. 학습 이력·대시보드**

프로젝트를 단원 퍼즐로 위장하지 않고 **단원 미소속 프로젝트 활동**으로 기록합니다. 이력 2판에 프로젝트 분기를 추가하되, T84-6에서 이미 반영한 구조와 맞춰 중복 이행을 피합니다.

| 기록 | 최소 내용 |
|---|---|
| 생성·열기 | 프로젝트 식별자·세계·선택 저장본 |
| 편집 요약 | 작업 순번, 시작 상태·코드·입력 변경 여부 |
| 실행 시작 | 실행 식별자·작업 순번·일치하는 저장본 |
| 실행 종료 | 끝까지 실행·사용자 정지·조작 오류·안전 상한 |
| 저장 | 실제 저장 성공한 저장본 식별자 |
| 닫기·삭제 | 이탈 사유·미저장 여부 또는 삭제 식별자 |

편집은 실행·저장·이탈 시 요약합니다. 실행 결과를 미리 계산하더라도, 이력은 **아이가 실제로 재생해서 본 종료 지점**을 기준으로 합니다. 화면 이탈과 사용자 정지를 정상 종료로 기록하지 않습니다.

내 배움에는 “창고 프로그램을 만들었어요”, “저장한 작품을 다시 고쳤어요”처럼 사실을 표시합니다. 교사·보호자 화면에는 재방문·저장·실제로 실행한 블록 종류를 보여 줄 수 있습니다. 코드에 들어 있다는 사실과 실제 실행은 구분합니다.

프로젝트 오류는 퍼즐 연속 실패·도움 필요 판정·완료율에 섞지 않습니다. 실행량으로 창의성·실력을 평가하지 않습니다. 작품 저장 성공 후 이력 저장만 실패했다면 작품을 보존하고 이력 누락을 알립니다.
