라운드 3 독립 제안서입니다. **“기본 개념 전부”는 문법을 많이 넣는 목표가 아니라, 순서·선택·반복·추상화·상태·입출력·자료의 조직을 직접 다뤄 보는 교육과정**으로 해석할 것을 제안합니다. 아래 세부안은 모두 **[제안]**이며, 연령별 모드는 만들지 않습니다.

지정 문서와 현재 엔진·저장소·언어 리소스를 읽었습니다. 파일 수정, 커밋, 브랜치 변경은 하지 않았습니다.

## A. 개념 지도

### 1. 권장 순서와 범위

**기존 순서·횟수 반복 → 조건·분기 → 조건 반복 → 함수 → 변수·연산 → 매개변수·반환값 → 이벤트 → 리스트·탐색 → 종합 전이**

함수는 먼저 **인자와 반환값 없는 동작 묶음**으로 도입합니다. 이후 변수와 값의 흐름을 익힌 다음 매개변수·반환값을 연결하면 한 번에 배워야 할 것이 줄어듭니다.

단원 번호와 스테이지 수는 아직 확정하지 않고, 아래 개념별 작은 묶음을 순서대로 검증합니다.

크기는 **S: 기존 구조 안의 작은 작업, M: 한 기능의 여러 계층 변경, L: 엔진·편집·저장에 걸친 변경**입니다. L은 반드시 여러 작업으로 나눕니다.

| 개념·크기 | 개념이 필요해지는 퍼즐 장치 | 글자 암기 없이 상태 보여 주기 | 대표 오해 → 예측·고치기 활동 | 엔진·저장 영향 |
|---|---|---|---|---|
| 순서·횟수 반복·중첩 반복 / 기존 유지 | 기존 1단원과 보너스 | 현재 블록·반복 회차·로봇 방향 | “돌기도 이동한다”, “반복 밖도 함께 반복된다” → 위치·방향 예측, 블록을 틀 안팎으로 옮겨 비교 | 의미·기록 유지. 중첩은 보너스로 계속 지원 |
| 조건·불리언 / M | 앞이 막힌 맵과 열린 맵에 **같은 코드** 사용 | 바라보는 한 칸 강조, 센서의 참·거짓을 기호와 문구로 표시 | “if는 계속 지켜본다” → 조건을 검사한 뒤 위치가 바뀌어도 재검사하지 않는 장면 예측 | 센서 조건 타입, `if`, 참·거짓 검사 프레임. 새 블록 저장부터 버전 변경 |
| 양자택일 `if/else` / M | 막히면 회전, 열렸으면 전진해야 하는 두 변형 맵 | 선택된 가지 강조, 건너뛴 가지는 윤곽으로 표시 | “두 가지를 순서대로 실행한다” → 두 가지가 모두 실행된다고 가정한 결과와 비교 | 두 몸체 경로, 편집·삭제·되돌리기·저장 검증 확장 |
| 조건 반복 `while` / M | 길이가 다른 통로들을 같은 코드로 통과 | **검사 → 몸체 → 다시 검사**를 연결해 표시 | “최소 한 번 실행한다”, “처음 한 번만 검사한다” → 처음부터 거짓인 경우와 종료 조건을 고치는 활동 | 매회 검사 프레임, 빈 몸체·불변 조건도 멈추는 실행 예산 |
| 함수·분해·재사용 / L | 떨어진 두 구간에서 같은 동작 묶음이 필요 | 함수 카드와 호출 연결, 현재 실행 중인 함수 표시 | “정의하면 바로 실행된다”, “한 번만 쓸 수 있다” → 호출 없는 코드 예측, 함수 한 곳을 고쳐 두 호출 결과 확인 | 함수 정의·호출 참조·호출 경로. 저장 프로그램 문서 확장 |
| 변수·대입·기초 자료형·연산 / L | 표시된 배달 수량을 기억하고 하나씩 줄이기 | 고정된 변수 칸에 현재 값, 변경 전후 값·수량 토큰 표시 | “대입은 수학의 등식”, “값은 자동으로 갱신된다” → 대입 전후 값을 고르고 빠진 갱신 고치기 | 실행 환경, 숫자·불리언 리터럴과 참조, 대입·증감·비교. 초기값은 저장, 실행 중 값은 미저장 |
| 논리 결합 `not/and/or` / M | 앞이 열려 있고 물건이 남았을 때만 이동 | 두 조건의 결과와 최종 결과를 나란히 표시 | “and와 or가 같다” → 네 조합 중 결과 예측, 잘못된 연결 하나 수정 | 조건 표현식 트리. 초기에는 부작용 없는 조건만 허용 |
| 매개변수·지역 범위 / L | 같은 함수로 서로 다른 거리 이동 | 호출의 값 토큰이 함수의 입력 칸으로 들어감. 호출마다 지역 칸 분리 | “매개변수를 바꾸면 원래 변수도 바뀐다” → 서로 다른 값으로 두 번 호출해 예측 | 인자·매개변수 연결, 호출별 지역 환경. 초기에는 숫자·불리언 값 전달만 |
| 반환값·입출력 / L | 센 값과 기준값을 비교해 다음 경로 결정 | 함수에서 나온 값 토큰이 비교 블록의 입력 칸으로 이동 | “화면에 보여 주면 반환한 것”, “return 뒤에도 실행한다” → 출력과 반환을 분리해 결과 예측 | 반환 표현식·호출 결과·함수 종료. 처음에는 제한된 값 함수부터 |
| 이벤트·상태 전이 / L | 버튼·신호가 도착해야 문이나 운반 장치 동작 | 이벤트 대기열, 실행 중인 처리기, 장치 상태를 함께 표시 | “이벤트 블록은 위에서부터 자동 실행된다” → 신호 없는 상태 예측, 잘못 연결한 처리기 고치기 | 결정적 이벤트 입력·처리기. 한 처리기씩 실행하고 실제 동시 실행은 제외 |
| 리스트·인덱스·길이·순회 / L | 여러 배송지를 순서대로 방문하고 특정 물건 찾기 | 번호가 붙은 칸, 현재 인덱스 포인터, 길이 표시 | “첫 칸은 1”, “길이 위치에도 원소가 있다” → 0부터 시작하는 포인터 추적, 경계 오류 수정 | 리스트 값·읽기·추가·삭제·길이. 범위 밖 접근은 명시적 실행 오류 |
| 탐색·알고리즘 비교 / M | 같은 목록에서 목표를 찾는 두 절차 비교 | 확인한 칸·비교 횟수·남은 후보 표시 | “답이 같으면 과정도 같다” → 서로 다른 입력에서 검사 횟수 예측 | 기존 리스트·반복 재사용. 비교 횟수는 실행 정보이며 진행 기록에는 불필요 |

**예측·디버깅·다른 입력에 적용하기는 모든 개념에 반복되는 활동**으로 둡니다. 예측 정답이나 실패 횟수로 다음 단원 진입을 막지 않습니다.

### 2. 퍼즐이 개념을 요구하게 만드는 방법

고정 맵 하나에서는 조건 없이 경로를 외워도 풀 수 있습니다. 따라서 새 개념의 핵심 퍼즐은 **수작업으로 만든 2~3개 입력에 같은 프로그램을 실행**하게 합니다.

- 연습에서는 모든 변형과 초기 상태를 먼저 보여 줍니다.
- 성공 판정은 모든 변형 통과로 하되, 실패한 변형을 바로 다시 볼 수 있게 합니다.
- 먼저 블록 제한보다 **입력 변화**로 필요성을 만듭니다.
- 함수는 떨어진 구간에서 재사용하게 하고, 변수는 실행 중 값을 기억해야 하게 합니다.
- 새 단원에서는 코드 길이만으로 별을 주면 의미 있는 함수·변수를 회피할 수 있습니다. **초기에는 통과 중심으로 두고 별 평가는 별도 설계**합니다. 기존 1단원의 별은 유지합니다.

## B. 개념어·언어 방침

### 1. 대안 비교와 추천

| 방침 | 장점 | 한계 |
|---|---|---|
| 기호만 | 읽기 부담이 작음 | 조건·함수·변수의 차이를 기호만으로 설명하기 어려움 |
| 한국어만 | 처음 뜻을 파악하기 쉬움 | 번역어가 길고 다른 도구의 용어와 연결하기 어려움 |
| 영어만 | 키워드가 짧고 일관됨 | 영어를 읽는 능력이 퍼즐의 진입 조건이 될 수 있음 |
| **기호 + 영어 개념어 + 현지어 설명** | 개념어를 유지하며 행동과 연결 가능 | 설명을 타일마다 모두 넣으면 화면이 복잡해짐 |

**추천은 마지막 안입니다.** 다만 영어화할 대상은 프로그래밍 개념어입니다. 시작·실행·삭제 같은 일반 버튼은 UI 언어에 맞춥니다.

- **타일:** 큰 기호, 짧은 키워드, 값·조건 슬롯.
- **팔레트·선택 상세:** 해당 언어로 뜻과 동작 설명.
- **첫 소개:** 실제 작동 장면과 함께 짧은 설명. 영어 철자 입력·시험 없음.
- **접근성 이름:** UI 언어로 전체 동작과 현재 인자를 설명.
- **테마:** 모양과 장식은 바꿔도 새 개념의 키워드·의미는 동일하게 유지.
- 기존 1단원은 기호와 조작을 보존하고, 설명에 키워드를 연결하는 수준부터 적용합니다.

### 2. 표기 예시

대괄호는 사용자가 선택하는 그림·값 슬롯이며, 입력해야 하는 문자가 아닙니다.

| 블록 | 한국어 UI 타일 / 설명 | 영어 UI 타일 / 설명 |
|---|---|---|
| 이동 | `↑` / 앞으로 한 칸 | `↑` / Move forward one cell |
| 회전 | `↺` / 제자리에서 왼쪽으로 돌기 | `↺` / Turn left in place |
| 횟수 반복 | `repeat ×3` / 안의 명령을 3번 반복 | `repeat ×3` / Repeat the blocks inside 3 times |
| 조건 | `if [앞 막힘 그림]` / 앞이 막혔으면 실행 | `if [blocked-ahead icon]` / Run these blocks if the path ahead is blocked |
| 다른 가지 | `else` / 조건이 거짓이면 실행 | `else` / Run these blocks if the condition is false |
| 조건 반복 | `while [앞 열림 그림]` / 앞이 열려 있는 동안 반복 | `while [clear-ahead icon]` / Repeat while the path ahead is clear |
| 함수 정의 | `function [계단 그림]` / 다시 쓸 동작 묶음 만들기 | `function [stair icon]` / Define a reusable group of actions |
| 함수 호출 | `[계단 그림]()` / 이 함수를 실행 | `[stair icon]()` / Run this function |
| 변수 대입 | `set [상자 A] ← 3` / A의 값을 3으로 바꾸기 | `set [box A] ← 3` / Set A to 3 |
| 값 반환 | `return [값]` / 값을 돌려주고 함수 끝내기 | `return [value]` / Return a value and end this function |
| 이벤트 | `on [버튼 그림]` / 버튼 신호가 오면 실행 | `on [button icon]` / Run when the button is pressed |
| 리스트 읽기 | `[목록 그림][0]` / 0번 칸의 값 | `[list icon][0]` / The item at index 0 |

`function`, `set`, `on`은 **이 제품의 블록 표기**이며 특정 텍스트 언어 문법 전체와 같다고 설명하지 않습니다. 변수·함수 이름은 우선 그림 카드와 선택 가능한 이름을 제공해 타이핑을 필수로 만들지 않습니다.

일반 버튼은 `실행 / Run`, `한 단계 / Step`, `고치기 / Fix`, `되돌리기 / Undo`처럼 현지화합니다. `처음으로`는 실행 상태를 초기화하는 동작임을 설명해 코드 삭제와 혼동하지 않게 합니다.

### 3. 영어 품질 기준과 검증

현재 `en.json`은 일부 키만 있어 한국어 fallback이 섞입니다. **영어 공식 지원은 영어 파일을 채운 것과 실제 영어 화면을 검증한 것을 함께 완료 조건으로 삼아야 합니다.**

| 기준 | 완료 조건 |
|---|---|
| 의미 | 원문보다 먼저 실제 엔진 동작을 확인. 회전을 이동처럼, `while`을 고정 횟수 반복처럼 설명하지 않음 |
| 읽기 수준 | 한 문장에 한 행동·질문. 짧고 직접적인 문장, 관용구·불필요한 의인화 최소화 |
| 용어 일관성 | `block`, `cell`, `turn`, `condition`, `parameter`, `argument` 등을 용어집 기준으로 사용 |
| 힌트 | 관찰·질문 수준과 정답 비공개 원칙을 양 언어에서 유지 |
| 배치 | 영어가 길면 문장을 줄이거나 배치를 조정. 글씨·터치 영역을 줄여 맞추지 않음 |
| 접근성 | 화면의 짧은 라벨과 접근성 이름이 같은 동작을 가리킴 |
| 누락 | 공식 지원 `en`은 ko의 모든 leaf key와 치환 인자가 일치. 다른 개발용 locale의 부분집합 정책은 유지 가능 |

**용어집 파일 제안:** `src/i18n/glossary.json`

각 항목에 개념 ID, 공통 키워드, 한·영 이름, 짧은 설명, 피할 표현을 둡니다. 키워드·이름은 화면에서도 재사용하고, 문장 전체는 locale 파일에서 관리합니다.

Claude가 화면 맥락을 보고 직접 번역하고, 검토자는 블록·힌트·실패 안내를 실제 동작과 대조합니다. 실행 중 번역 API는 없습니다.

검증은 다음을 포함합니다.

- 키·치환 인자·용어집 일치 자동 검사.
- `?lang=en`에서 시작→편집→실패→힌트→고치기→성공→재방문.
- 양 언어에서 세 월드 × 세 화면 크기 배치와 스크린샷 육안 확인.
- 앱이 연결하는 정적 안내 페이지도 영어로 제공.
- E2E 통과는 동작·표시의 증거이며, 번역의 자연스러움과 개념 이해는 별도 검토.

### 저장·엔진에서 특히 지켜야 할 것

1. **v1→v2:** 프로그램을 `{ main, functions: [] }` 같은 문서로 감쌉니다. 기존 블록 ID·중첩 순서·스테이지 ID·완료·최고 별은 그대로 옮깁니다. 이후 함수 추가 때 기본 구조를 재사용합니다.
2. 구조 변경마다 순수한 단계별 변환을 둡니다. `v1→v2→…`의 실제 과거 fixture를 계속 검사합니다. 현재처럼 다른 버전을 일괄 초기화하는 정책은 변경해야 합니다.
3. 실행 프레임·현재 변수값·호출 스택·이벤트 대기열은 진행 기록에 저장하지 않습니다. **코드와 초기 설정만 복원하고 실행은 처음부터** 시작합니다.
4. 기존 키는 이행 성공 전 덮어쓰지 않습니다. v1 원본을 보존한 새 버전용 키로 시작하면 v1.0.0 되돌리기도 가능하지만, 새 버전에서 쌓은 진행이 구버전으로 역변환되지는 않음을 명시해야 합니다. 기록 삭제는 앱이 소유한 구·신 키를 모두 처리합니다.
5. 한 스테이지의 손상이 다른 정상 기록까지 지우지 않게 합니다. 검증에는 블록 종류뿐 아니라 깊이·총 노드 수·참조·값 범위의 상한도 둡니다.
6. 현재 `program.ts`와 편집 경로는 `repeat.body`만 압니다. 조건·함수에 맞춰 **컨테이너의 자식 목록을 다루는 공통 규칙**을 만들되, 사용하지 않을 범용 플러그인 구조까지 만들지 않습니다.
7. 현재 interpreter의 마지막 분기는 이동·반복 이외를 회전으로 처리합니다. 블록 확장 때 명시적 분기와 누락 검사로 바꿔야 합니다.
8. 기존 1단원의 “목표 진입 즉시 성공”은 보존합니다. 후속 수량·이벤트 퍼즐은 **목표 위치와 과제 조건이 함께 충족되는 시점**을 별도로 정의합니다.
9. 현재는 전체 실행을 먼저 계산하고 재생합니다. 조건·함수·변수까지는 유지하고, 이벤트 단계에서만 **상태 + 입력 → 다음 상태 + 프레임**인 순수 전이 함수를 검토합니다.

## D. 하지 말 것

- “기본 개념 전부”를 한 번의 대형 엔진 개편이나 여러 단원 동시 구현으로 처리하지 않기.
- 영어 철자 입력·정의 암기·용어 퀴즈를 진행 조건으로 만들지 않기.
- 모든 블록에 영어·한국어·긴 설명을 함께 넣거나 글씨를 줄여 화면에 맞추지 않기.
- 기존 1단원 코드·별·완주·보너스 선택 원칙을 새 과정에 맞춰 소급 변경하지 않기.
- 함수·변수 단원에 기존 10블록 상한과 코드 길이 별 평가를 그대로 강제하지 않기.
- 조건을 썼는지만 검사해 통과시키지 않기. 다른 입력에서도 올바르게 동작하는지 확인하기.
- 실패 횟수에 따른 숨은 난이도 조절, 강제 예측, 정답 자동 삽입, 학습자 감시 기록 만들지 않기.
- 서버·회원가입·외부 전송·유료 API·실행 중 AI 번역 추가하지 않기.
- 새 의존성·테마·드래그 편집·PWA·배포를 이번 개념 확장에 묶지 않기.
- E2E 통과를 학습 효과 입증으로 보고하지 않기.

이번 결과는 **읽기 전용 기획 제안**입니다. 코드·화면 변경이 없어 테스트는 실행하지 않았으며, 제안한 기능과 학습 효과는 미검증입니다. Claude 종합 시 우선 확정할 항목은 **개념 범위, 기호·영어 키워드 표기 원칙, T33~T38의 완료 조건과 저장 이행 정책**입니다.
