Lealnspire Guide for Teachers and Parents

A one-page guide for teachers and parents who use Lealnspire with children. It describes how the app actually behaves.

What children learn

Children give a robot instructions with blocks to guide it to a star. Unit 1 teaches three ideas.

  1. Order (sequence): A computer runs instructions one at a time, in the order they are placed. Change the order and the result changes.
  2. Repeat (loops): Spot actions that happen again and again, and shorten them with a repeat block.
  3. Fixing (debugging): Run a program that doesn't work, find where it goes wrong, and fix it.

Blocks and buttons use symbols, so children who can't read yet can still play (↑ move forward, ↶ turn left, ↷ turn right, ↻ repeat). Programming terms such as repeat, if, else, and while are kept as they are in real programming instead of being replaced with everyday words.

Unit 9: EventsOpens after Unit 8. Children learn that an on handler runs when its signal comes, one at a time in the order signals arrive, not in the order the cards are placed. A signal opens a closed door, and they fix handlers whose signals were swapped.
Unit 10: ListsOpens after Unit 9. Children use the values of a list one at a time from the front (for each), and learn by fixing code that indexes start at 0 and that the length (number of cells) is not the last index.
Unit 11: SearchOpens after Unit 10. Children find the cell in a list that equals a target value, see that stopping as soon as it is found means fewer comparisons, and learn from the comparison count that whether searching from the front or the back is faster depends on the input.
Unit 12: Choose Your ToolsOpens after Unit 11. Without being told which idea to use, children look at what changes between two maps and choose the tools they need (loops and conditions, functions and parameters, lists). Finishing all 45 regular puzzles shows a course-complete screen.

How to help without giving the answer

The game never shows the answer on purpose. When a child is stuck, try these steps in order.

  1. Let them run it first. There's no penalty for failing. When a run fails, a "!" marks the cell where the robot stopped and the block where it went wrong. Pressing "Fix" keeps the code and selects that block.
  2. Use the "Step" button to follow one action at a time. Besides moves and turns, it also stops at each condition check, value change and signal arrival. A repeat block shows which round it is on, like "2/3".
  3. Press the hint (light bulb). The first hint asks what to observe; the second asks a question about the idea. Each step outlines where to look (map, block palette, workspace, list, comparisons, signals, or box A) with a dashed border and says "Look at: …". Hints never give the answer numbers or block order.
  4. If they don't know how to use a block, press the hand + ▶ button ("See how it works"). It appears on stages that introduce a new idea and stays after blocks are placed, so children can watch it again when stuck. It shows the controls in 4 frames on an example map that differs from the puzzle. It never shows the answer and never pops up by itself.
  5. If they're still stuck, ask questions like these:
    • "Which way is the robot facing right now?" (Turns are from the robot's point of view, not the screen's.)
    • "How many cells to the star? Where does it need to turn?"
    • "Do you see a part that happens again and again? How many times?"
    • "Where did the robot stop? Which block ran just before that?"

Children learn more when they run and fix the program themselves than when an adult places the blocks for them.

What the stars mean

In Unit 1, a successful run earns 1 to 3 stars. Stars are feedback on code length ("there's a shorter way"), not a grade. The next stage opens even with fewer stars. (The rule is provisional: 3 stars at or under the stage's block target, 2 stars for up to 2 blocks over, otherwise 1.) From Unit 2 on, stars don't depend on code length: every success earns 3 stars, because the goal is to use the new idea, not to write the shortest code.

Progress and privacy

  • Progress (finished stages, best stars per stage, the last blocks made in each stage) is saved only in this browser on this device. Nothing is sent to a server, and there are no accounts.
  • Clearing this site's data (cookies and site data) in the browser settings deletes the progress. Clearing only the browsing history does not. It doesn't move to other devices or browsers.
  • On the home screen, "ⓘ About my progress" (top left) shows what is saved and lets you delete it (after a confirmation).
  • If saving fails (for example, when storage is full), the game shows "Your progress couldn't be saved…" once, and the success window says "This progress was not saved on this device." Children can keep playing, but that progress may be lost when the page is closed.
  • If the site operator rolls the site back to an older version, progress in units that the older version doesn't have will not appear, and it may be erased if the older version saves. If you host the game yourself, back up progress before rolling back.
  • Progress and learning records (runs per puzzle, kinds of mistakes, hints and demos used, estimated active time) are stored only on this device and never sent to a server. No names or photos are collected. "My Learning" on the home screen shows solved puzzles and the next puzzle; the child's screen never shows mistake counts, hint counts, or time.
  • Shared computers (such as a school computer lab): if several children use one browser, their progress mixes. After class, delete it with "About my progress → Delete progress", or give each child a separate browser profile.

Where it has been tested

  • Tested: desktop Chrome-based browsers (Chromium) at 1280×720, phone-size screens 375×667 and 360×560 (browser emulation), touch input, and keyboard-only use.
  • Not yet tested: real phones and tablets, Safari, Firefox.
  • Languages: Korean and English. Add ?lang=en to the address, or use the language button in the app, for English.
  • Accessibility: keyboard use, screen reader names, and reduced motion have been checked (not certified).
